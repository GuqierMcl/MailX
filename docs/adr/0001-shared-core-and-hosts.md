# ADR 0001：共享 Rust 核心与分阶段宿主

状态：**Proposed** · 2026-10-14 · 初始建议，允许后续替换。

## 背景

启动愿景同时包含 Tauri 桌面客户端和 Docker Web。若一开始分别编写两套收发、搜索与权限逻辑，后续很难保证同样的离线、幂等和 AI 行为；同时交付两种形态又会让单人早期开发范围过大。

## 当前建议

业务服务、领域模型与端口放在宿主无关的 Rust core；SQLite、邮件协议和模型 HTTP 实现在 infra。桌面 / Web 只装配生命周期、通信、平台凭证和文件交互。先完成桌面首版，再用 Axum 承载相同服务。

每个数据目录只有一个核心写入实例，MCP 是该实例的受限入口。桌面与 Web 独立部署时分别保存数据，不直接共享 SQLite，也不把 Web 偷换成多租户服务。

## 代价与重评条件

需要较早定义 UI adapter 和 RequestContext，测试宿主差异；初期目录比单一 Tauri 模板略多。暂不采用微服务或消息中间件。

若远程桌面控制、团队协作、长驻 headless 同步或平台分发带来真实需求，可重新设计进程所有权与部署方式。更改时同步更新[总览](../architecture/overview.md)和[宿主边界](../architecture/desktop-web.md)，无需拘泥本记录。
