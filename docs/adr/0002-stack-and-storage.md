# ADR 0002：前端与持久化的初始选择

状态：**Proposed** · 2026-10-14 · 具体依赖版本待 M0 验证。

## 背景

蓝图保留了 Svelte / React 两种可能；参考项目 NexusPilot 已使用 React、TypeScript、Bun 和 Tauri。MailX 同时需要可恢复邮件缓存、草稿、队列与离线查询，早期不宜引入外部数据库服务。

## 当前建议

前端采用 React + TypeScript + Vite，Bun 管理依赖，Cargo 管理 Rust。选择依据是维护者熟悉程度和跨宿主 UI 复用，不是声称某框架天然达到蓝图的内存目标。初版只覆盖 IMAP / SMTP；POP3、JMAP 与服务商 API 保留扩展空间。

SQLite 使用 `rusqlite`，通过专用执行器隔离阻塞访问，启用 WAL、外键和 FTS5。草稿与队列是需保护的本地源数据；可重新获取的邮件缓存和可重建索引在恢复策略上区别处理。附件与原始大对象使用不可变 blob 文件。

候选协议库 `async-imap` / `lettre` 必须通过统一路由验证，尤其 SMTP 自定义连接、TLS 和 OAuth。M0 失败时可换库或调整适配，不用绕过代理来保住选型名称。

## 代价与重评条件

数据库执行器需要明确任务边界；WAL 仍不能消除单写入限制；全文中文短词需要专门体验评估。使用 React 仍需虚拟列表与懒加载，不能把性能交给框架名称。

若实际查询并发、异步存储维护成本、全文搜索质量或前端开发体验不合适，可评估 SQLx、其他本地检索方案或 Svelte。已积累用户数据后更换存储须设计迁移；本轮草案本身没有兼容包袱。详见[存储设计](../architecture/storage-search.md)。
