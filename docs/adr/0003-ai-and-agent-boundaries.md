# ADR 0003：内置 AI 与外部 Agent 的初始边界

状态：**Proposed** · 2026-10-14 · 工作流和实现方式可演化。

## 背景

蓝图希望同时提供端内 AI 与外部 MCP 访问。邮件既含不可信指令，也含敏感内容和验证码；发送更涉及难以撤销的动作。NexusPilot 的独立 AI sidecar 有其复杂 Agent 场景背景，不能只因参考其文档结构就照搬。

## 当前建议

v0.1 在 Rust 中实现有限模型适配和固定工作流，降低多进程生命周期成本。模型调用选定内容，输出摘要、待办或草稿建议；发送仍由用户在应用中检查确认。

对外 MCP 默认关闭，首批工具为列表、搜索、阅读与创建草稿。不提供语义含混的“起草或代发”工具，不把邮件内容当成新的授权。首版 stdio bridge 复用正在运行的核心；远程传输与第三方 MCP Client 以后再设计。

## 代价与重评条件

Rust 需要维护各模型的流式协议适配，固定工作流限制通用 Agent 能力。初版不承诺兼容所有模型，也不支持全自主邮箱代理。

若工具编排、多模态、SDK 生态或插件扩展成为主要需求，可以评估独立 Runtime、现成 Agent SDK 和双向 MCP。新方案需重新说明凭证、内容披露与发信授权边界，而不是受限于本轮的进程结构。详见 [AI Runtime](../ai-runtime/README.md)与 [MCP 草案](../contracts/mcp.md)。
