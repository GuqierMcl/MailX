# 初始实施路线图

状态：**部分已实现 / 后续 Planned，可调整** · 2026-10-20。阶段、版本号、功能组合与验收指标用于指导启动，不是发布日期承诺。后续需求与验证结果可以改变路线。

当前已建立仓库与工程基础、Rust 账号配置、SQLite/SecretStore、Tauri IPC、shadcn 工作台和设置弹窗。后台经账号路由（直连 / SOCKS5 / HTTP CONNECT）登录 IMAP，同步目录及全部可选文件夹的邮件头；桌面端读取真实本地缓存，提供统一收件箱、主题 / 发件人搜索、未读筛选、详情、按需正文阅读和“加载更多”，普通浏览器开发仍使用 mock 数据。

每个可选文件夹的 UIDVALIDITY 代际首次以 UTC 当日减 30 天为固定起点，每轮选窗口内 UID 最新的 1,000 封补齐，单批 200 封；先前头部保留，总缓存可超过 1,000。账号之间并发且不设全局并发上限；账号内头部同步单连接串行，整轮结束后等待 60 秒，目录每 10 分钟到期刷新；窗口外不对账，按需完整 MIME 下载与正文缓存已有实现，附件独立保存、标记写回、发信和服务器宿主尚未实现。实现边界见[同步设计](../architecture/mail-sync.md)，当轮检查见[验证策略](../development/validation.md)。

上述实现不表示 M0 或 M1 全部验收完成。三平台 CI 与合成正文 WebView 检查已有通过记录；macOS 真实邮件头、正文与增量对账已有部分冒烟证据，明确标注 GBK 的 HTML 实样及断网重开仍待验。已确认本次 2925 网页星标未体现为 IMAP Flagged，完整服务商矩阵未完成，详见[验证策略](../development/validation.md)。原蓝图的八周计划不作为交付承诺；协议 / OAuth / 代理的剩余组合应有证据后再估算。

优先顺序为**第一阶段桌面 MVP，第二阶段服务器 MVP**。下文 M0–M4 是桌面阶段的细分候选里程碑，M5 是后续服务器阶段；AI / MCP 的具体交付范围可根据邮件收发闭环进展再调整。

仓库为 [GuqierMcl/MailX](https://github.com/GuqierMcl/MailX)，按开源项目形式维护，项目处于早期开发阶段，尚未达到 MVP。

## M0：工程骨架与关键可行性

- [x] 合并 core / infra，采用 `desktop → core`；最初的只读版本 IPC 已演进为账号与邮件读取服务。
- [x] 选择 React + TypeScript + Vite + shadcn，初始化 `frontend/` 与根 Bun 工作区，接通 Tauri 开发 / 构建入口。
- [x] 账号配置的结构化错误、应用服务、Rust → TypeScript DTO 生成、user-data-dir 与实例锁。
- [x] 账号创建 / 列表 / 详情 / 修改的 Tauri IPC 与 shadcn 设置页；保存明确标记连接尚未验证。
- [ ] IMAP 的 Direct / SOCKS5 / HTTP CONNECT + TLS 最小探针。
- [x] SMTP 的 Direct / SOCKS5 / HTTP CONNECT + STARTTLS / 隐式 TLS 路由探针：`lettre` 在受控本地服务上跑通，代理失败不回退直连（仅测试代码，见[写信与发送设计](../architecture/sending.md#4-smtp-会话)）。真实服务商的 SMTP 经代理发信仍未验证。
- [ ] OAuth 应用注册与回调方案验证，记录发布所需外部依赖。
- [x] 账号配置采用 rusqlite、WAL、外键、v1 初始化与校验、凭证更新恢复。
- [x] [版本化迁移与启动准入](../architecture/database-migrations.md)：兼容 v1，启动完成数据库准备后再开放业务；备份恢复与完整升级保障后续实施。
- [ ] FTS5 搜索探针。
- [x] 三平台合成 HTML iframe 隔离与外链处理验证；平台链接差异见验证策略。
- [ ] MCP SDK + stdio bridge / 本地 IPC 最小连通性验证。
- [x] `.github/workflows/ci.yml` 已配置前端格式相关检查、类型、测试和构建，以及 Linux / macOS / Windows 的 Rust Clippy 与测试；本次执行结果单独记录，不由工作流存在推定通过。

完成条件：空应用可运行；协议探针在受控服务完成收发并证明代理不回退；有一条生成 DTO 的 IPC 调用；关键风险有结论或替代方案。没有证明 SMTP 代理前，不宣称分账号收发路由已实现。

## M1：可恢复的邮件核心

依赖 M0。

- [x] 账号、独立收发端点、密码类认证、路由配置及 SecretStore 持久化；OAuth 仅预留模型。
- [ ] 真实连接 / 认证 / 代理行为、OAuth 提供商适配及首批审核预设。
- [x] v3 邮件头迁移、全部可选目录头部分批入库、UID 身份和代际、固定窗口游标、重连 / 退避、flags 与删除对账的实现；真实服务商冒烟已有部分证据，完整兼容性验证未完成。
- [x] 当前来源与代际隔离的头部列表 / 详情、稳定游标分页、LIKE 主题 / 发件人搜索和 coverage 声明；正文单独按需获取，全文索引尚未实现。
- [x] 有界 MIME 解析、按需正文缓存与隔离阅读；单封 bodyState 与截断状态已提供，bodiesComplete 保守为 false。
- [x] 附件保存（桌面）：核心从本地原始邮件取字节并清洗文件名，桌面经系统另存为对话框写入；服务器宿主的 HTTP 下载与缓存配额 / 淘汰仍未实现。
- [ ] 本地全文检索、中文短词限制评审、过滤与权限范围。
- [ ] QQ / 163 及 Gmail / Microsoft 的受控接入测试按可用资格推进。

完成条件：至少两个不同路由账号互不干扰；重启后缓存可读；重复同步、UID 世代变化、对账中断和磁盘失败行为可复现。服务商支持按实际组合记录，OAuth 外部资格未完成的组合保留未验证状态。

## M2：桌面收发闭环

依赖 M1。

- [x] 三栏头部工作台、统一收件箱、文件夹 / 未读筛选、搜索、分页加载和同步后保留有效选中。
- [x] 自动选择 HTML / 纯文本正文、按需下载与手动失败重试。
- [ ] 虚拟列表与其余账号交互扩展。
- [x] 空 sandbox 正文、附件元数据、远程图片询问 / 自动加载 / 永不加载策略与阅读期内存缓存，正文原位置外链交由系统打开；历史三平台及本轮 macOS 合成 WebView 证据的范围见验证策略。
- [x] 桌面附件保存已实现；本地 OTP 识别仅作为可选体验实验，尚未实现。
- [ ] 草稿版本、回复 / 转发、附件、发送确认、outbox 与已发送副本。v0.1 的范围、写信窗口与实施步骤见[写信与发送设计](../architecture/sending.md)；附件、富文本与向服务器追加已发送不在首个可发送版本内。
- [x] 已读 / 星标：本地先行、后台写回队列（独立写连接、退避重试、UIDVALIDITY 核对）、服务器不支持星标时仅本机保存并 Toast 提示；仅当前打开的邮件，批量操作与离线重启后的重放验证仍待做。
- [x] 新邮件通知：核心判定新到达的未读收件箱邮件（首次同步、重建与补齐的旧邮件不算）并经统一事件出口发给宿主；桌面使用系统通知，点击打开邮件，支持按账号静音、隐藏预览、前台是否通知与提示音（系统默认 + 八个自带音效）。服务器宿主的 webhook 出口、IMAP IDLE 即时推送尚未实现，目前最长有约 1 分钟延迟。
- [ ] 键盘操作、主题、缓存不完整与发送 unknown 的界面。

完成条件：用户可离线读缓存、编辑草稿、恢复后发送；DATA 后断线不自动重发；恶意正文无法执行脚本或调用 IPC。可以在受控用户群体验，尚不等于正式全平台发布。

## 下一次开发的建议起点

邮件头同步已扩展到全部可选文件夹，并补充目录级失败隔离与界面状态；既有收件箱版本已有三平台证据，扩展版本的实际检查结果单独记录。继续核查真实服务商证据中的缺口：两个不同路由账号、来源与 UID 世代切换和失败恢复；持续观察网页星标与 IMAP flags 的服务商差异。已有真实 GBK、新增时延、统一分页、重启读取、已读 / 删除增量和保持未读的冒烟结果见验证策略；保持首轮固定 30 天窗口、每轮最新 1,000 封与历史缓存保留的范围说明。

按需正文与安全阅读已有实现；QQ 的 GB2312 HTML、CID 图片、2925 未读保持和旧外链确认流程已有现场证据，明确标注 GBK 的 HTML 实样与断网重开仍待验。远程图片策略及正文内链接已实现，macOS 已确认真实邮件的远程 SVG Logo 和 JPEG 图片显示，完整平台与路由兼容矩阵仍待补充。SMTP 路由探针已在受控服务完成，发信按[写信与发送设计](../architecture/sending.md)分步实施；OAuth 注册与分发资格仍待推进；不要把头部同步或保存配置视为完整收发证明。任务完成时提供验证结果与未解决限制，文档按代码和证据更新。
