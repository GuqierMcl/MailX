# 初始实施路线图

状态：**Planned / 可调整** · 2026-10-14。阶段、版本号、功能组合与验收指标用于指导启动，不是发布日期承诺。后续需求与验证结果可以改变路线。

当前已完成：文档与仓库基础初始化。当前未开始：下列应用实现阶段。原蓝图的八周计划不直接作为交付承诺，先解决协议 / OAuth / 代理等不确定性再估算工期。

仓库为 [GuqierMcl/MailX](https://github.com/GuqierMcl/MailX)，目前私有，按开源项目形式维护。首个 MVP 版本发布后再公开并开源；公开时机跟随实际 MVP 交付，不固定绑定本文的阶段编号。

## M0：工程骨架与关键可行性

前置：本轮初始设计可供讨论。

- [ ] Cargo workspace、React / Vite / Bun、Tauri 空壳，固定版本和锁文件。
- [ ] core / infra 边界、结构化错误、DTO 生成、平台数据目录与实例锁。
- [ ] IMAP 与 SMTP 的 Direct / SOCKS5 / HTTP CONNECT + TLS 最小探针。
- [ ] OAuth 应用注册与回调方案验证，记录发布所需外部依赖。
- [ ] SQLite WAL / FTS5 探针、HTML iframe 无 IPC / 外链处理验证。
- [ ] MCP SDK + stdio bridge / 本地 IPC 最小连通性验证。
- [ ] 已存在代码的格式、类型、测试和构建 CI。

完成条件：空应用可运行；协议探针在受控服务完成收发并证明代理不回退；有一条生成 DTO 的 IPC 调用；关键风险有结论或替代方案。没有证明 SMTP 代理前，不宣称分账号收发路由已实现。

## M1：可恢复的邮件核心

依赖 M0。

- [ ] 账号、端点、路由、认证与 SecretStore；通用配置及首批审核预设。
- [ ] 迁移、头部分页入库、UID 身份、游标、重连 / 退避与范围对账。
- [ ] 有界 MIME 解析、按需正文 / 附件、缓存覆盖状态。
- [ ] 本地全文检索、中文短词限制评审、过滤与权限范围。
- [ ] QQ / 163 及 Gmail / Microsoft 的受控接入测试按可用资格推进。

完成条件：至少两个不同路由账号互不干扰；重启后缓存可读；重复同步、UID 世代变化、对账中断和磁盘失败行为可复现。服务商支持按实际组合记录，OAuth 外部资格未完成的组合保留未验证状态。

## M2：桌面收发闭环

依赖 M1。

- [ ] 三栏工作台、统一收件箱、虚拟列表、账号 / 文件夹筛选。
- [ ] 安全正文、附件与外链交互；本地 OTP 识别仅作为可选体验实验。
- [ ] 草稿版本、回复 / 转发、附件、发送确认、outbox 与 Sent 归档。
- [ ] 已读 / 星标离线队列、权限校验与显式失败提示。
- [ ] 键盘操作、主题、缓存不完整与发送 unknown 的界面。

完成条件：用户可离线读缓存、编辑草稿、恢复后发送；DATA 后断线不自动重发；恶意正文无法执行脚本或调用 IPC。可以在受控用户群体验，尚不等于正式全平台发布。

## M3：AI 与本地 MCP

依赖 M2 的阅读、草稿和权限服务。

- [ ] 云端兼容接口与 Ollama、提供商配置、内容披露与取消。
- [ ] 摘要、待办建议、拟信与改写；Run 快照和输入 revision 检查。
- [ ] MCP 配对、账号 / 工具范围、撤销和本地 bridge 生命周期。
- [ ] list / search / read / create-draft 工具，至少两个目标 MCP 客户端联调。
- [ ] 注入样本、跨账号访问、失败流、进程中断验证。

完成条件：AI 只使用选定上下文，异常不影响收发；外部 Agent 可在授权范围检索和创建草稿；不能绕过 UI 发送，正文与日志不泄漏凭证。

## M4：v0.1 桌面预发布

依赖 M0–M3。是否合并或缩小版本范围可根据实际进展再定。

- [ ] Windows / macOS / Linux 构建与宿主安全冒烟测试。
- [ ] 真实邮箱兼容矩阵、OAuth 分发资格、性能与恢复基准。
- [ ] 用户安装 / 使用指南、可验证下载地址与已知限制。
- [ ] 备份恢复演练、依赖许可检查、签名 / 公证方案与校验和。
- [x] 确定使用 Apache-2.0，并添加根目录 [LICENSE](../../LICENSE)。
- [ ] 维护者确定发布渠道和安全报告方式。
- [ ] 首个 MVP 版本发布后，检查提交历史与敏感信息，确认许可证与归属声明完整并将仓库设为公开。

完成条件：每项公开支持声明都有证据；许可证与渠道已落实；无已知的重复发送、数据破坏或权限绕过阻断问题。某平台未通过时明确标记未支持，不以统一品牌掩盖状态。

## M5：v0.2 单用户 Web / Docker

建议在桌面核心稳定后开展，不阻塞首版邮件核心开发。

- [ ] Axum API 与同源 SPA，复用 core / infra 和 DTO。
- [ ] 引导、防抢占、Session、TOTP、CSRF、限速、恢复与主密钥管理。
- [ ] 非 root 单镜像、本地数据卷、secret 挂载、健康检查和升级 / 恢复指南。
- [ ] 两种宿主的功能契约对照与发布测试。
- [ ] 远程 MCP 作为独立扩展评审，不因 Web 存在就自动开放。

完成条件：能从空目录安全部署、登录、收发并恢复备份；实际镜像和命令可运行；数据、认证和远程入口边界有完整验证。

## 暂缓方向

POP3 / JMAP、更多预设、向量索引、自然语言搜索、自动分流、Anthropic 原生适配、第三方 MCP Client、远程 OTP / 发信授权、跨设备设置同步、富文本编辑和移动端。它们是候选方向，不是固定追加队列。

## 下一次开发的建议起点

先做 M0 的协议路由探针和最小 workspace，再进入“收取最近 5 封 → 入库 → 重启读取”的 M1 纵向链路。任务完成时提供改动、验证命令 / 场景、结果和未解决限制；文档仅在功能真正落地后标记 Implemented。
