# 产品目标与能力边界

本页说明桌面产品的能力边界与后续方向。平台与服务商验证集中记录在[验证记录](../development/validation.md)中，具体发布变化见 [CHANGELOG](../../CHANGELOG.md)；后续范围可随项目演化调整。

MailX 面向需要管理多个邮箱的开发者与个人用户，将可靠收发、本地搜索、分账号网络路由和可选 AI 工作流集中在一个工作台。MailX 不提供邮箱托管服务，不运营邮件中继，不要求注册 MailX 云账号。

## 交付边界

| 能力 | 当前桌面实现 | 后续 |
| --- | --- | --- |
| 收发协议 | IMAP 收取、SMTP 发送队列，TLS 必需；收件箱 IDLE、失败退回轮询 | POP3、JMAP、提供商专属 API、生产 OAuth 服务商接入 |
| 账号 | 多账号、统一收件箱、手动配置、QQ / Foxmail、163 / 126 / yeah.net、139 预设与收发登录测试 | 更多预设和自动发现 |
| 阅读 | 三栏布局、虚拟列表与分页、按需正文缓存、附件保存、隔离 HTML、远程图片策略 | 全量离线下载与缓存配额 |
| 整理 | 已读 / 未读、星标、按账号与文件夹过滤、可撤销删除、本机归档 | 移动到服务器文件夹、服务端归档、UI 多选批量操作 |
| 撰写 | 富文本新邮件、回复 / 全部回复、转发、附件、内嵌图片、本地草稿、发件队列、已发送本机副本 | 远程草稿同步、定时发送、向服务器追加已发送 |
| 搜索 | 本地邮件头、预览、已缓存正文、附件名与已发送本机副本 | 后台补齐正文索引、向量语义搜索、附件内容索引 |
| 网络 | 账号级直连 / 继承默认直连 / 独立 SOCKS5 或 HTTP CONNECT；IMAP 与 SMTP 共用路由 | 可配置全局默认代理、系统 PAC 自动解析 |
| AI | 可通过本地 MCP 接入外部 AI 客户端；内置模型与聊天界面尚未实现 | OpenAI 兼容接口与 Ollama、内置摘要 / 待办 / 拟信 |
| MCP | 默认关闭的本地 stdio bridge；统一授权读取、整理、草稿、附件与直接发送 | 逐客户端 / 逐账号授权、远程 Streamable HTTP |
| 桌面体验 | 中英文、主题、通知、关闭窗口后后台运行、可选开机自启动 / 静默启动、应用内更新 | 继续补齐平台与打包体验验证 |
| 形态 | Windows / macOS / Linux 构建与 CI；各能力实机证据不同 | 单用户 Docker Web |

当前 AI 接入方式是外部客户端通过 MCP 调用 MailX；内置 AI 与 Web 仍为规划，不属于已交付的桌面能力。MCP 和 AI 均不是启动与收发的前置条件，也未实现第三方 MCP Server 接入。未来桌面实例与 Web 实例各自保存数据，通过邮箱服务端同步邮件，不同步应用设置和本地草稿。

发布时按[发版清单](../development/release.md)核对安装包、升级路径与支持范围；功能实现与实际平台、客户端、服务商验收分别记录。

## 邮箱兼容矩阵

以下是兼容性测试目标，**当前没有完成完整收发矩阵的服务商**。QQ 已有部分历史收信与阅读证据，QQ / Foxmail 预设、官方图标、授权码引导和收发登录诊断已有实现；新实现仍需真实账号专项验收。每个提供商必须分别记录接收、发送、刷新认证、代理、重连和文件夹行为；预设或登录验证通过不等于实际投递通过。

| 提供商类别 | 认证设计 | 验收重点 |
| --- | --- | --- |
| 通用 IMAP / SMTP 测试服务 | TLS + 测试凭证 | 可重复故障注入与基本收发 |
| QQ / Foxmail | IMAP / SMTP + 16 位授权码；已有预设 | 数字/英文 QQ 地址与 Foxmail 身份分别验证，真实发信、标记写回、收取范围变化、已发送副本及路由；见[接入方案](../reference/qq-foxmail-integration.md) |
| 网易 163 / 126 / yeah.net | IMAP / SMTP + 客户端授权码；已有三个独立预设 | 官方参数与 IMAP ID 要求已核查，已有用户真实邮箱手测反馈；完整域名、平台与收发兼容矩阵待补充，见[接入方案](../reference/netease-163-126-integration.md) |
| 139 邮箱 | IMAP / SMTP + 客户端授权码；已有预设 | 账号资格、授权码有效期、真实收发与路由；已有用户手测反馈，见[接入方案](../reference/139-mail-integration.md) |
| Gmail（后续） | OAuth 2.0 + XOAUTH2 通用基础已有实现，Gmail 接入尚未开放 | 同意范围、刷新、标签文件夹语义、走代理 |
| Outlook.com / Microsoft 365（后续） | OAuth 2.0 + XOAUTH2 通用基础已有实现，Microsoft 接入尚未开放 | 租户策略、SMTP 可用性、刷新失败提示 |
| 企业邮箱 | 手动端点 + 届时已实现的认证方式 | 协议与 TLS 证书可用性；私有 CA 的显式配置尚未提供 |

Google 文档描述 Gmail 的 XOAUTH2 接入与公开应用验证要求；Microsoft 文档描述 Outlook.com / Microsoft 365 的 OAuth 邮件接入。由此将应用注册、授权与发送权限验证列为实施依赖，而不假设普通密码普遍可用。[Google 官方说明](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol)、[Microsoft 官方说明](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth)。

## 数据与隐私表述

- 当前桌面数据在本机；未来 Web 数据在用户部署的服务器。邮件收发与用户授权的外部访问会传输内容，本地优先不表示“数据永不离开设备”。
- 邮箱协议连接所配置服务商；使用代理时经用户指定代理。MCP 总开关确认后，连接客户端可读取所有账号并直接发送邮件，无需逐封确认；客户端可能向其 AI 提供商发送所读内容。关闭开关撤销后续访问，已入队的发送需另行取消。内置云端 AI 尚未实现。
- 未来的本地模型能力只有在端点确实本地、模型已就绪且未使用外部工具时，才可在断网环境运行。模型运行仍占用硬件资源。
- 密钥与邮件缓存分开管理；首版不承诺数据库与附件整体加密。详见[安全边界](../architecture/network-security.md)。

## 非目标与发布表述

不做多租户 SaaS、企业日历 / LDAP / 工单系统、移动端、反垃圾服务器、自动执行邮件里的指令。外部客户端在 MCP 总开关授权下可直接发信；MailX 不自带无人值守的 AI 发信工作流。

产品愿景可以描述“兼容市面所有邮箱”等目标，实际能力与性能声明以验证结果为准，性能作为[验证预算](../development/validation.md)管理。

产品名为 `MailX`，仓库为 [GuqierMcl/MailX](https://github.com/GuqierMcl/MailX)。桌面安装包按 `MailX_<版本>_<平台>` 命名，随包 MCP bridge 名为 `mailx-mcp`，具体产物见[发版流程](../development/release.md)。初始蓝图中的 `mailx-app`、`mx` 不是当前分发名称；服务器可执行程序和镜像名尚未确定。
