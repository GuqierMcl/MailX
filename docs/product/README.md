# 产品目标与首版范围

状态：**Initial draft** · 全部产品能力待实现；v0.1 / v0.2 仅为初始规划，可随项目演化调整。

MailX 面向需要管理多个邮箱的开发者与个人用户，将可靠收发、本地搜索、分账号网络路由和可选 AI 工作流集中在一个工作台。MailX 不提供邮箱托管服务，不运营邮件中继，不要求注册 MailX 云账号。

## 交付边界

| 能力 | v0.1 桌面目标 | 后续 |
| --- | --- | --- |
| 收发协议 | IMAP 收取、SMTP 提交，TLS 必需 | POP3、JMAP、提供商专属 API |
| 账号 | 多账号、统一收件箱、手动配置与小规模审核预设 | 30+ 预设和自动发现 |
| 阅读 | 三栏布局、分页虚拟列表、缓存正文、附件下载、受限 HTML | 高级邮件卡片、全文离线归档策略 |
| 整理 | 已读 / 未读、星标、按账号与文件夹过滤 | 移动 / 删除 / 清空、复杂标签与服务端规则 |
| 撰写 | 纯文本新邮件、回复 / 全部回复、转发、附件、本地草稿、发件队列 | 富文本编辑、远程草稿同步、定时发送 |
| 搜索 | 本地缓存的主题、发件人、正文及结构化过滤 | 向量语义搜索、附件内容索引 |
| 网络 | 账号级直连 / 应用默认 / 独立代理 | 系统 PAC 自动解析 |
| AI | 用户触发的摘要、待办提取、拟信；OpenAI 兼容接口与 Ollama | Anthropic 原生适配、自动分流、自然语言查询规划 |
| MCP | 桌面 stdio：授权检索、纯文本阅读、创建草稿 | 远程 Streamable HTTP、OTP 专项授权、发送审批工具 |
| 形态 | Windows 首先完成验证，macOS / Linux 纳入桌面发布门槛 | v0.2 单用户 Docker Web |

v0.1 不实现第三方 MCP Server 接入，因此“内置 AI + 对外 MCP Server”不称为双向 MCP。AI 非启动与收发的前置条件。桌面实例与 Web 实例各自保存数据，通过邮箱服务端同步邮件，不同步应用设置和本地草稿。

## 邮箱兼容矩阵

以下是测试目标，**当前没有任何已验证邮箱**。每个提供商必须分别记录接收、发送、刷新认证、代理、重连和文件夹行为；预设存在不等于兼容通过。

| 提供商类别 | 认证设计 | 验收重点 |
| --- | --- | --- |
| 通用 IMAP / SMTP 测试服务 | TLS + 测试凭证 | 可重复故障注入与基本收发 |
| QQ / 163 | 服务商允许的授权码或应用专用凭证 | 开通指引、ID 扩展需求、直连；具体规则实施时核验 |
| Gmail | OAuth 2.0 + XOAUTH2 为正式路径 | 同意范围、刷新、标签文件夹语义、走代理 |
| Outlook.com / Microsoft 365 | OAuth 2.0 + XOAUTH2 | 租户策略、SMTP 可用性、刷新失败提示 |
| 企业邮箱 | 手动端点 + 届时已实现的认证方式 | 私有 CA 的明确配置、协议可用性 |

Google 文档描述 Gmail 的 XOAUTH2 接入与公开应用验证要求；Microsoft 文档描述 Outlook.com / Microsoft 365 的 OAuth 邮件接入。由此将应用注册、授权与发送权限验证列为实施依赖，而不假设普通密码普遍可用。[Google 官方说明](https://developers.google.com/workspace/gmail/imap/xoauth2-protocol)、[Microsoft 官方说明](https://learn.microsoft.com/en-us/exchange/client-developer/legacy-protocols/how-to-authenticate-an-imap-pop-smtp-application-by-using-oauth)。

## 数据与隐私表述

- 桌面数据在本机；Web 数据在用户部署的服务器。两者都不是“数据永不离开设备”的绝对保证。
- 邮箱协议连接所配置服务商；使用代理时经用户指定代理。启用云端 AI 会发送所选邮件内容，启用 MCP 会向获授权客户端披露数据。
- 本地模型只有在端点确实本地、模型已就绪且未使用外部工具时，才可在断网环境运行。模型运行仍占用硬件资源。
- 密钥与邮件缓存分开管理；首版不承诺数据库与附件整体加密。详见[安全边界](../architecture/network-security.md)。

## 非目标与发布表述

不做多租户 SaaS、企业日历 / LDAP / 工单系统、移动端、反垃圾服务器、自动执行邮件里的指令，也不以无人值守自动发信作为首版目标。

产品愿景可以描述“兼容市面所有邮箱”等目标，实际能力与性能声明以验证结果为准，性能作为[验证预算](../development/validation.md)管理。

产品名为 `MailX`，仓库为 [GuqierMcl/MailX](https://github.com/GuqierMcl/MailX)。可执行程序、命令行别名、安装包和镜像名称尚未确定；初始蓝图中的 `mailx-app`、`mx` 仅为候选，不构成命名决定，也不假设不存在冲突。具体名称在后续分发设计中再确定。
