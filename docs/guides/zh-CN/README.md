# MailX 使用入门

[English](../README.md) | 简体中文

本页说明桌面版的基本操作。已发布安装包以 [Releases](https://github.com/GuqierMcl/MailX/releases) 为准；功能验证范围见[验证记录](../../development/validation.md)，后续功能见[路线图](../../roadmap/README.md)。

## 安装与添加账号

1. 在 Releases 选择对应平台的安装包，按该版本安装说明打开。macOS 区分 Apple 芯片与 Intel；Windows 提供 x64 安装程序；Linux 提供 x64 AppImage、deb 和 rpm。安装包尚未做代码签名，可用同一版本的 `SHA256SUMS.txt` 核对下载文件。
2. 在邮箱服务商网站准备客户端访问，按服务商要求启用 IMAP / SMTP，并取得客户端密码、授权码或应用专用密码。MailX 内置 QQ / Foxmail、163、126、yeah.net、139 和 iCloud 入口，其他账号可手动填写服务器与端口。当前不支持 OAuth 登录。
3. 在 MailX 添加账号，填写地址与客户端凭证；需要代理时，为该账号设置 SOCKS5 或 HTTP CONNECT。可在保存前测试收发登录并分别查看结果。登录测试成功只表示可以认证，实际投递仍需用自己的测试收件人确认。
4. 保存后等待同步。侧栏顶部汇总所有账号的收件箱、星标、草稿和已发送，归档、垃圾邮件和已删除收在“更多”里；有多个账号时，悬停某一行并点它的箭头可按账号分别列出。下方的各账号默认折叠，展开后可以看到该账号的全部文件夹，包括收件箱和已发送。想给邮件更多空间时，用标题栏按钮或 Cmd/Ctrl+B 收起侧栏：它会变成一列图标，入口不变，悬停显示名称和未读数，“更多”和账号改为弹出菜单；选择会被记住。服务商拒绝连接时，检查客户端协议是否开启、授权码是否有效以及网络路由。

### iCloud 邮箱

如果尚未开通邮箱，先[创建 iCloud Mail 地址](https://support.apple.com/guide/icloud/create-a-primary-icloudcom-email-address-mmdd8d1c5c/icloud)。为 Apple 账号启用双重认证，再到 `account.apple.com` 的“登录与安全 → 应用专用密码”生成[应用专用密码](https://support.apple.com/en-us/102654)。将该密码填入 MailX；邮箱地址应填写 iCloud Mail 地址，而非仅用于登录 Apple 账号的其他邮箱。

`@icloud.com`、`@me.com` 和 `@mac.com` 地址可选择 iCloud 入口。MailX 预填 `imap.mail.me.com:993` 隐式 TLS 与 `smtp.mail.me.com:587` STARTTLS，收发共享应用专用密码。两端用户名默认使用完整邮箱地址；收信登录失败时，可按 [Apple 服务器指南](https://support.apple.com/en-us/102525)，在高级设置中仅将 IMAP 用户名改为 `@` 前的部分，SMTP 保持完整地址。

修改或重置 Apple 账号主密码会撤销全部应用专用密码，需重新生成并在 MailX 的账号连接设置中更新。MailX 尚未提供 Apple 账号授权登录。iCloud+ 自定义域请使用手动 IMAP / SMTP 入口；别名没有独立的发件人选择器，指向同一邮箱的多个地址也不会自动合并。Mail Drop 尚不可用，附件与内嵌图片仍受 Apple 普通邮件大小限制。

## 收信、搜索与整理

每个文件夹首次同步以最近 30 天为起点，每轮补齐窗口内最新的最多 1,000 封邮件头，已缓存历史会保留；这不是邮箱全量下载。支持 IMAP IDLE 的账号会监听收件箱变化，其他文件夹及不支持 IDLE 的账号继续轮询。

自动同步安静运行：账号行保留未读数，不显示加载动画。手动刷新时，只有你使用的刷新按钮显示进度。新添加的账号首次获取可浏览内容时会显示弱化的文字提示；已有缓存的账号正常启动时不重复提示。同步问题仍会显示静态警示，方便检查账号。

打开邮件时下载并缓存正文，之后可离线阅读已缓存内容。搜索在本机查找邮件头、预览、已缓存正文和附件名；没有下载的正文不会被完整搜索，附件内容也不参与搜索。搜索结果不代表服务器上的全部邮件。

已读与星标会写回服务器。归档只在本机将邮件移出收件箱，可在“更多 → 归档”或账号下的“已归档”找回，不影响其他客户端。服务器上本身名为“归档”的文件夹仍以服务器上的名称显示在对应账号下。删除会先给出短暂的撤销机会，随后移入服务器“已删除”；在“已删除”中或没有对应文件夹时，确认后永久删除。尚不支持移动到任意服务器文件夹。

远程图片默认先询问，附件可另存为本机文件。邮件缓存与附件没有由 MailX 整体加密；使用共享电脑时应依靠操作系统账号和磁盘保护。

## 写信与发送

新邮件、回复、全部回复和转发使用独立写信窗口，草稿自动保存在本机。可添加文件附件、插入图片或粘贴截图；普通附件和内嵌图片合计默认上限为 20 MiB，服务商可能另有更低限制。草稿不会同步到其他客户端。

检查收件人、发件账号、正文与附件后，按界面提示再次点击发送确认。想留出撤销时间，可在“设置 → 发信”中选择 5、10、20 或 30 秒，默认不等待；撤销只适用于仍在等待的队列项，不能撤回服务器已接受的邮件。

发件箱显示排队、发送失败或结果未知等状态。结果未知意味着服务器可能已接受邮件，MailX 不会自动重发；先检查收件端或服务商的已发送记录，再决定是否手动重试。服务器接受 SMTP 提交也不等于收件人最终收到邮件。

已发送文件夹先显示本机副本，MailX 匹配到服务商保存的副本后只显示服务器那封。QQ 邮箱可能重新分配邮件标识，MailX 也会核对 QQ 保留的原始标识，避免两份同时显示。已有重复项会随邮件头同步重新对账，无需再次发送；无法确认匹配时继续保留本机副本。服务商是否自动保存已发送邮件取决于其行为；MailX 暂不将本机副本上传到服务器。

## 连接外部 AI 客户端（MCP）

MailX 已提供本地 MCP 服务器，内置 AI 聊天或模型设置尚未提供。MCP 默认关闭。

1. 打开“设置 → MCP”，开启并阅读授权确认。总开关向连接的本机客户端开放所有账号的读取、邮件整理、草稿与本机文件附件管理，以及直接发信，**无需逐封发送确认**。
2. 点击“复制客户端配置”，将配置加入兼容的 MCP 客户端。配置使用随应用安装的 bridge；更换安装位置后应重新复制。不同客户端导入配置的方法以其文档为准。
3. 保持 MailX 运行，可在设置页查看状态与已连接客户端。关闭主窗口并驻留后台时仍可使用；完全退出应用或关闭 MCP 开关后，客户端连接不可用。关闭 MCP 不会取消已入队的发送任务，需在发件箱另行处理。

客户端可能将读取的邮件内容发给其使用的 AI 服务，应按自己的隐私需求选择客户端和模型。当前没有逐客户端或逐账号授权界面，MCP 不支持删除邮件。客户端、平台与工具组合的兼容性见[验证记录](../../development/validation.md)。

## 后台运行、开机启动与更新

关闭主窗口时可选择后台运行或退出，默认每次询问，可在通用设置中修改。开机自启动与静默启动默认关闭；静默启动只在系统登录时自动启动生效。系统或桌面环境没有可用后台入口时会显示主窗口，避免应用运行却无法找回。

应用会检查 GitHub 上的新版本，可关闭自动检查，也可在关于页手动检查。macOS、Windows 与 AppImage 支持应用内更新；deb / rpm 按发布页安装新包。系统代码签名与更新包签名是两回事，当前安装包仍可能触发系统首次运行提示。

## 升级与数据保留

应用启动时会执行需要的数据库迁移，具体升级变化见对应版本的发布说明。较旧版本通常无法打开迁移后的数据库；不要把重新安装旧程序当成回退数据的方法。

升级前如需保留回退材料，先从应用中**完全退出**，再复制完整的 MailX 数据目录，包含数据库、可能存在的 SQLite 旁文件、设置和 blob 文件，不能只复制 `mailx.sqlite3`：

| 平台 | 默认数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/MailX` |
| Windows | `%APPDATA%\MailX` |
| Linux | `~/.local/share/MailX`（设置了 `XDG_DATA_HOME` 时使用对应目录） |

密码和授权码保存在系统凭据库，复制数据目录不会复制凭据，也不是已经验证的跨机器迁移或完整恢复方案。自动备份与一键恢复尚未提供；历史队列恢复也可能涉及已经发送的邮件，不要直接用旧备份覆盖正在使用的数据。

遇到问题请在 [Issues](https://github.com/GuqierMcl/MailX/issues) 描述版本、系统、服务商和操作步骤，使用虚构地址及测试邮件；不要附上密码、授权码、真实邮件或完整私人日志。安全漏洞通过[私密报告入口](../../../SECURITY.md)提交。
