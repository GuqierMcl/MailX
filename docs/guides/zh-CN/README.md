# MailX 使用入门

[English](../README.md) | 简体中文

本页说明桌面版的基本操作。已发布安装包以 [Releases](https://github.com/GuqierMcl/MailX/releases) 为准；功能验证范围见[验证记录](../../development/validation.md)，后续功能见[路线图](../../roadmap/README.md)。

## 安装与添加账号

1. 在 Releases 选择对应平台的安装包，按该版本安装说明打开。macOS 区分 Apple 芯片与 Intel；Windows 提供 x64 安装程序；Linux 提供 x64 AppImage、deb 和 rpm。安装包尚未做代码签名，可用同一版本的 `SHA256SUMS.txt` 核对下载文件。
2. 在邮箱服务商网站准备客户端访问，按服务商要求启用 IMAP / SMTP，并取得客户端密码、授权码或应用专用密码。MailX 内置 Gmail、iCloud、Outlook、Microsoft 365 / Exchange、QQ / Foxmail、163、126、yeah.net 和 139 入口，其他账号可手动填写服务器与端口。Outlook 和 Microsoft 365 在浏览器中登录，不需要密码或授权码（见下文）；其他服务商暂不支持浏览器登录。
3. 在 MailX 添加账号，填写地址与客户端凭证；需要代理时，为该账号设置 SOCKS5 或 HTTP CONNECT。可在保存前测试收发登录并分别查看结果。登录测试成功只表示可以认证，实际投递仍需用自己的测试收件人确认。
4. 保存后等待同步。侧栏顶部汇总所有账号的收件箱、星标、草稿和已发送，归档、垃圾邮件和已删除收在“更多”里；有多个账号时，悬停某一行并点它的箭头可按账号分别列出。下方的各账号默认折叠，展开后可以看到该账号的全部文件夹，包括收件箱和已发送。选择某个账号的文件夹后，邮件列表标题旁会显示该邮箱的名称。想给邮件更多空间时，用标题栏按钮或 Cmd/Ctrl+B 收起侧栏：它会变成一列图标，入口不变，悬停显示名称和未读数，“更多”和账号改为弹出菜单；选择会被记住。服务商拒绝连接时，检查客户端协议是否开启、授权码是否有效以及网络路由。

### Gmail

先为 Google 账号开启[两步验证](https://support.google.com/accounts/answer/185839)，再到 Google 账号的“应用专用密码”页面生成[应用专用密码](https://support.google.com/accounts/answer/185833)。Google 显示的是分组的 16 位密码，粘贴到 MailX 时去掉中间的空格。Gmail 的 IMAP 始终开启，不需要在 Gmail 设置里另外打开。

`@gmail.com` 和 `@googlemail.com` 地址可选择 Gmail 入口。MailX 预填 `imap.gmail.com:993` 与 `smtp.gmail.com:465`，均为隐式 TLS，收发共享应用专用密码，用户名都是完整邮箱地址。

修改 Google 账号密码后，所有应用专用密码都会失效，需要重新生成并在 MailX 的账号连接设置中更新。两步验证只用了安全密钥、开启了高级保护，或使用公司 / 学校账号时，Google 不提供应用专用密码；MailX 目前还没有在浏览器中登录 Google 的方式，这类账号暂时无法添加。Gmail 用标签管理邮件，同一封邮件可能出现在多个文件夹中，它在 MailX 中的表现尚未用真实账号完整验证。

### iCloud 邮箱

如果尚未开通邮箱，先[创建 iCloud Mail 地址](https://support.apple.com/guide/icloud/create-a-primary-icloudcom-email-address-mmdd8d1c5c/icloud)。为 Apple 账号启用双重认证，再到 `account.apple.com` 的“登录与安全 → 应用专用密码”生成[应用专用密码](https://support.apple.com/en-us/102654)。将该密码填入 MailX；邮箱地址应填写 iCloud Mail 地址，而非仅用于登录 Apple 账号的其他邮箱。

`@icloud.com`、`@me.com` 和 `@mac.com` 地址可选择 iCloud 入口。MailX 预填 `imap.mail.me.com:993` 隐式 TLS 与 `smtp.mail.me.com:587` STARTTLS，收发共享应用专用密码。两端用户名默认使用完整邮箱地址；收信登录失败时，可按 [Apple 服务器指南](https://support.apple.com/en-us/102525)，在高级设置中仅将 IMAP 用户名改为 `@` 前的部分，SMTP 保持完整地址。

修改或重置 Apple 账号主密码会撤销全部应用专用密码，需重新生成并在 MailX 的账号连接设置中更新。MailX 尚未提供 Apple 账号授权登录。iCloud+ 自定义域请使用手动 IMAP / SMTP 入口；别名没有独立的发件人选择器，指向同一邮箱的多个地址也不会自动合并。Mail Drop 尚不可用，附件与内嵌图片仍受 Apple 普通邮件大小限制。

### Microsoft（Outlook / Microsoft 365）

这两个入口通过浏览器登录，MailX 不会接触你的密码。个人 Outlook.com、Hotmail 或 Live 地址选择 **Outlook**；工作或学校地址选择 **Microsoft 365 / Exchange**。不需要先填写邮箱地址：需要时先改网络设置，再点击**在浏览器中登录**。MailX 会打开微软的登录页面，在那里完成登录后回到 MailX。MailX 等待期间可以随时取消。

MailX 会从登录结果得到你的邮箱地址，并确认邮件服务器确实能打开这个邮箱。如果不能（例如你用的是别名或不同的登录名），它会请你填写账号的邮箱地址，并用已有的登录再确认一次，不会再次打开浏览器，最多可以试五次。然后给邮箱起个名字，点击**完成**。返回上一步或关闭窗口会放弃这次登录，15 分钟后它也会自动失效。

选错入口时，MailX 会告诉你该用哪一个。如果提示无法打开邮箱，先检查邮箱地址。Outlook.com 请确认已在 Outlook 设置中开启 IMAP。工作或学校邮箱可能需要管理员批准 MailX，或为你的邮箱允许 IMAP 和 SMTP。组织关闭了其中任何一项时，MailX 无法绕过，也不会反复要求你重新登录。

登录过期或被撤销后，在 MailX 中打开该账号，点击**重新登录**即可，已有的邮件和设置不会变。公司自己搭建的 Exchange 服务器不在 Microsoft 365 入口支持范围内，请使用手动 IMAP / SMTP 配置，服务器信息向管理员获取。

Outlook 入口已用个人 Outlook.com 账号测试；Microsoft 365 入口尚未用真实的工作或学校账号测试。共享邮箱和世纪互联运营的 Microsoft 365 暂不支持。

## 管理账号

点侧栏的**账号**管理邮箱。顶部显示账号名称、邮箱地址和最近同步时间。有问题的邮箱在列表中带一个小感叹号，和侧栏“账号”入口上的一样：红色表示同步已停止，琥珀色表示 MailX 会自动重试；从侧栏打开账号时，会直接选中第一个有问题的账号。同步已停止、凭证需要确认或需要重新登录，都会在顶部提示，处理按钮在页面底部。

名称、发件人名称、服务商图标和标识颜色修改后自动保存。标识颜色可选预设色、不标识，或点最后的彩虹色块用系统取色器选任意颜色。红色的**移除账号**在左下角；**验证收发连接**和**修改连接**（浏览器登录的账号为**重新登录**）在右下角，滚动时始终可见。验证只检查已保存的登录，不发送邮件：连接方式一行会说明收发是否通过，有一侧未通过时，连接详情会自动展开，并在对应服务器下写明原因。通过只表示登录可用，不代表已测试投递。其余时候服务器、凭证和网络路由等详情默认折叠。

## 此刻

侧栏“写邮件”下方的**此刻**会向你问好，并汇总邮箱的情况：需要处理的事（同步已停止的账号、发送失败或可能没有发出的邮件、本机草稿）、自上次查看“此刻”以来收到的邮件、收件箱未读和星标未读数量、最近 15 分钟内的验证码（可一键复制），以及最近收到的附件。点任意一项即可打开。页面上的内容都在这台电脑上计算，不会发送到任何地方。验证码只从这台电脑上已有的预览和正文中识别，可能有遗漏。想让 MailX 打开时先显示“此刻”而不是收件箱，可在“设置 → 通用 → 启动时打开”中选择。

## 收信、搜索与整理

每个文件夹首次同步以最近 30 天为起点，每轮补齐窗口内最新的最多 1,000 封邮件头，已缓存历史会保留；这不是邮箱全量下载。支持 IMAP IDLE 的账号会监听收件箱变化，其他文件夹及不支持 IDLE 的账号继续轮询。

自动同步安静运行：账号行保留未读数，不显示加载动画。点击标题栏侧栏折叠按钮右侧的刷新按钮，可刷新全部邮箱；账号行上的刷新按钮则只刷新对应账号。手动刷新时，只有你使用的刷新按钮显示进度。新添加的账号首次获取可浏览内容时会显示弱化的文字提示；已有缓存的账号正常启动时不重复提示。同步问题仍会显示静态警示，方便检查账号。

打开邮件时下载并缓存正文，之后可离线阅读已缓存内容。在“未读”视图中打开的邮件标为已读后仍留在列表里，直到切换邮箱、筛选或搜索。搜索在本机查找邮件头、预览、已缓存正文和附件名；没有下载的正文不会被完整搜索，附件内容也不参与搜索。搜索结果不代表服务器上的全部邮件。

当邮件属于一段多次往来的对话时，阅读区会显示整段对话：当前邮件完整显示，对话中的其他邮件（包括“已发送”里你自己的回复）以单行形式排在它的上方和下方。点击某一行即可阅读该邮件，并停留在同一段对话中。对话较长时，其余邮件会收进“更早”或“更新”的一行。可在阅读区顶部的“单封”和“对话”之间切换，回到逐封阅读。MailX 按邮件中的回复信息串联对话，因此部分发件方或较早的邮件仍可能单独显示；如果本机尚未下载整段对话，阅读区会给出提示。

鼠标悬停或键盘聚焦邮件时，右上角会取代时间显示快捷操作：星标、标为已读 / 未读、归档 / 移回收件箱，隔开一段距离后最右侧是删除；无论是否开启正文预览都一样。鼠标刚进入某一行就点击时，点击会打开邮件，不会误点到还在淡入的按钮。鼠标点击操作后，移开鼠标即可再次隐藏按钮。已加星的邮件会在主题旁持续显示一颗黄色小星标。每行最左侧的窄条里，未读邮件显示蓝点，已读邮件留空。阅读区工具栏使用同样的状态环：空环表示已读，环中带蓝点表示未读；本机已发送副本则提供需要确认的“从本机移除”操作。在跨多个账号的视图里，每行会在发件人后写出所属邮箱名称；在“设置 → 外观 → 邮件列表”中把“所属邮箱显示为”改成“图标”，则改为在发件人头像上显示一个小的账号图标。

在列表中右键点击邮件，可在一个菜单里使用同样的操作：打开、回复、全部回复、转发、标为已读或未读、加星标或取消星标、可归档时的归档或移回收件箱，以及删除。本机已发送副本只提供打开、回复、全部回复、转发和从本机移除。右键不会打开邮件，菜单打开期间该行保持高亮。多选期间右键不弹出菜单，请使用顶部的操作按钮。使用键盘时，按 Shift+F10 或菜单键可为当前聚焦的邮件打开菜单，按 Esc 关闭。

同一菜单还可以查看发件人的全部邮件：选择“查看此联系人的邮件”，邮件列表会切换为该联系人在各文件夹中的邮件（不含垃圾邮件和已删除邮件）。点击列表顶部的返回按钮、按 Esc 或鼠标后退键，即可回到原来的位置。选择“聚合此联系人的邮件”后，该联系人的所有邮件在收件箱中收成一行，显示邮件数和未读数，点击即可查看全部。搜索时邮件始终逐封显示；多选时不能选中聚合行。要取消聚合，可在聚合行或该联系人的邮件上右键，也可以在“设置 → 联系人”中查看和管理所有已聚合的联系人。聚合按发件人的邮箱地址匹配，对所有账号生效，只保存在本机。

当前打开的邮件、草稿或发件箱项目会持续显示蓝色选中底色，浅色和深色主题分别适配。自定义强调色也会用于选中底色；近灰、极亮或极暗的颜色会回退为默认蓝色高亮，以保持清晰可辨，主强调色设置不变。鼠标移开或悬停其他行时，当前打开的项目仍保持高亮。

已读与星标会写回服务器。归档只在本机将邮件移出收件箱，可在“更多 → 归档”或账号下的“已归档”找回，不影响其他客户端。服务器上本身名为“归档”的文件夹仍以服务器上的名称显示在对应账号下。删除会先给出短暂的撤销机会，随后移入服务器“已删除”；在“已删除”中或没有对应文件夹时，确认后永久删除。尚不支持移动到任意服务器文件夹。

要一次处理多封邮件，点击邮件列表上方的“选择”，或按住 Cmd/Ctrl、Shift 点击某封邮件。选中的邮件显示蓝色描边，角上带勾。单击可选中或取消，按住 Shift 点击可连续选中，“全选”会选中当前列表中的全部邮件，一次最多 500 封。随后可用顶部按钮标为已读或未读、加星标、归档或删除。删除和归档可以撤销；没能处理的邮件会保持选中，方便查看是哪几封。点“完成”或按 Esc 结束。

回复邮件的末尾如果带有被引用的原邮件，MailX 会把这部分收进“显示引用内容”按钮，让新写的内容更醒目，点击即可展开。MailX 能识别常见邮件客户端的引用格式；无法识别的引用、在引用中穿插作答的回复以及转发的邮件，仍按原样完整显示。折叠只影响显示，回复和转发时仍会带上完整原文。

不在输入框里时，主窗口可用键盘快捷键：J 或 ↓ 打开下一封，K 或 ↑ 打开上一封；Enter 或 O 打开第一封；/ 打开搜索，? 列出全部快捷键。对当前打开的邮件，E 归档（或移回收件箱），# 或 Delete 删除，S 加星标，U 标为已读或未读，R、A、F 分别回复、全部回复和转发；归档或删除后会打开下一封。多选时，E、#、S、U 作用于选中的邮件。使用语音输入或辅助工具时，可在“设置 → 快捷键”中关闭单键快捷键；带 Cmd/Ctrl 的快捷键和 Esc 仍可用。

远程图片默认先询问，附件可另存为本机文件。邮件缓存与附件没有由 MailX 整体加密；使用共享电脑时应依靠操作系统账号和磁盘保护。

## 翻译邮件

MailX 可以翻译你正在阅读的邮件，并保留原有版式：段落、列表、表格、粗体、链接和内嵌图片都留在原来的位置，主题也会一起翻译。翻译开箱即用，默认使用 Microsoft 翻译，无需注册，也不需要密钥。它使用在线翻译服务，不是 AI 助手，也不是 MailX 内置的功能；如果你连接了 AI 模型（见下文“AI”），也可以选它来翻译。需要更稳定时，可以换成使用你自己密钥的服务。这项功能是新加的，目前只通过自动测试、几句测试文字和一次用示例数据的预览检查，还没有在各系统上手动验证。

### 选择翻译服务

Microsoft 翻译和 Google 翻译无需设置，使用与 Edge、Chrome 浏览器内置翻译相同的通道。这个通道不是微软或谷歌正式开放给其他应用的服务，可能随时失效或变慢，两家公司也没有任何承诺。出问题时，邮件上方的提示行会给出“重试”和“换一种翻译服务”。Google 翻译在中国大陆通常需要代理。需要更稳定时，请选择使用自己密钥的服务。

改用 AI 模型：先在“设置 → 集成 → AI”里连接服务商，再把“翻译服务”选为“AI 模型”。它默认使用默认模型，也可以在“模型”里另选一个（“跟随默认模型”即用默认模型）。没有可用模型时，按钮会提供“打开 AI 设置”。模型可能比其他服务慢，也可能出错，目前还没有用真实模型做过实际测试。

使用自己的密钥：

1. 打开“设置 → 翻译”，在“翻译服务”的“使用自己的密钥”组里选择 DeepL、Microsoft Translator 或 Google Cloud Translation。你需要一个所选服务的密钥，请到该服务自己的网站获取。使用 Microsoft Translator 时还有一项可选的“区域”，填创建资源时选择的区域；全球资源请留空。
2. 粘贴密钥并点“保存”。MailX 把它安全保存在本机，保存后不再显示，这一行会显示“已保存”，之后可以“更换”或“移除”。点“测试”会翻译一句示例文字，用来检查密钥和网络是否可用（免设置的服务没有密钥，也可以测试），不会发送你的任何邮件。
3. 在“翻译”里选择要翻译成的语言：“跟随界面语言”（默认），或 26 种语言之一。

### 翻译与切换回原文

打开一封邮件，点击阅读区工具栏里的翻译按钮，它在已读和星标按钮之后。旁边的小箭头会打开一个菜单：“翻译成”（换一种语言）、“重新翻译”和“翻译设置…”。也可以在命令面板选择“翻译这封邮件”。翻译进行时原文仍可阅读，也可以取消。再次点击按钮回到原文，再点一次回到译文。两个版本都保持加载，因此切换是即时的，并各自记住滚动位置。翻译失败时，原因和“重试”按钮会显示在邮件上方的提示行里。

如果你关闭了翻译（“不使用翻译”），或选了使用自己密钥的服务却还没保存密钥，按钮会告诉你“还没有设置翻译服务”，并提供“去设置”。只有已经下载、带有格式化（HTML）正文的邮件才能翻译。

第一次使用某项服务时，在发送任何内容之前，MailX 会先问“把邮件内容发送给……？”，你可以“取消”；对 Microsoft 翻译和 Google 翻译，这个问题还会说明：这是浏览器使用的通道，不是正式开放给其他应用的服务，可能随时失效，你的文字会发送给微软或谷歌。换用另一项服务时会再问一次。选用 AI 模型时，第一次把邮件发给该服务商前会先问，换成另一个服务商时会再问。只要 MailX 还开着，它会按邮件记住你当时是在看译文还是原文，以及是否关闭了提示；退出后不保留。

### 语言提示

服务可用后（免设置的服务始终可用），如果打开的邮件看起来不是你使用的语言，邮件上方会出现一行提示，例如“这封邮件是法语”，旁边有“翻译成……”按钮。提示里的“更多”菜单可以为该语言选择“总是翻译……”或“不再提示……”，关闭按钮只对这一封邮件隐藏提示；工具栏菜单里有同样两项。语言在你的电脑上检测，你点击翻译之前不会发送任何内容。很短的邮件和多种语言混合的邮件可能识别不出来，简体与繁体中文也不区分。你可以在“设置 → 翻译 → 外语邮件”里关闭提示（“提示翻译”）。

### 按语言自动翻译

为某种语言选择“总是翻译……”后，这种语言的邮件在打开时会自动翻译，也就是自动把文字发送给你已同意的翻译服务。“设置 → 翻译 → 外语邮件”列出了“总是翻译的语言”和“不提示的语言”，可以在那里添加或移除；同一种语言只能在两个列表之一里。

### 会发送什么，不会发送什么

MailX 只在你同意之后，把邮件的主题和文字发送给你选择的服务（微软、谷歌、你保存了密钥的那一项，或你的 AI 模型所在的服务商）。不会发送附件、图片、链接地址和邮箱密码。回复末尾引用的早先邮件默认不翻译，除非你打开“翻译引用的历史邮件”（默认关闭）。代码以及单独的网址、邮箱地址保持原样。服务如何处理你的文字由该服务自己的条款决定，用于私密邮件之前请先了解。免设置的服务对这种用法没有条款，也没有数据处理说明，私密或敏感的邮件请优先使用你自己的密钥并读过其条款的服务。

### 翻译时使用代理

翻译默认直接连接。多数人不需要改它，所以它放在“设置 → 翻译”页面最下方的“高级”组里，默认折叠，展开后才能修改；折叠时，标题旁会显示当前连接（“直接连接”或“通过代理 地址:端口”）。展开后在“连接方式”里选择“通过代理”（SOCKS5 或 HTTP），代理只用于翻译。如果你的代理需要登录，再填写“用户名”和“密码”；它们是可选的，多数本机代理不需要。密码保存在这台设备上，保存后不再显示，并且只有填了用户名才会使用。邮箱账号上设置的代理不会用于翻译。代理连不上或不接受登录时，翻译会报错，不会悄悄改为直连。

### 已保存的译文

翻译完成的结果保存在这台电脑上，重新打开邮件不会再次发送；删除邮件或账号时一并删除。“设置 → 翻译 → 已保存的译文”显示已保存的邮件数量和占用空间，“清除”会全部删除。没有单独删除某封邮件译文的按钮；工具栏菜单里的“重新翻译”会用新的翻译替换这封邮件已保存的译文。已保存的译文没有加密，请和邮件缓存一样看待。

### 限制

- 很长的邮件只会翻译一部分：每封邮件最多发送 50,000 个字符，其余保持原文，邮件上方的提示行会写“邮件较长，只翻译了前面的部分”。正文超过 2 MiB 的邮件不会翻译。
- 邮件需要先下载才能翻译。纯文本邮件同样可以翻译；正文为空的邮件没有可翻译的内容。
- 只存在于这台电脑上的已发送副本无法翻译，写信时的草稿也不能翻译。
- 如果服务在某一段里丢掉了链接或图片，MailX 会让这一段保持原文。
- MCP 客户端不能使用翻译，也没有左右对照的显示方式。

## AI

“设置 → 集成 → AI”用来把 MailX 连接到 AI 模型服务商。翻译可以使用模型（在“翻译”里选“AI 模型”）；MailX 里其他功能暂时都不使用，除非你选择这样做，你读写的任何内容都不会发送给模型。

### 添加服务商

1. 打开“设置 → 集成 → AI”，在“服务商”下选择“添加服务商”。
2. 从列表中选一个服务商，或选择“自定义”并自己填写地址和接口类型（兼容 OpenAI 或兼容 Anthropic）。
3. 填写 API 密钥并选择“连接”。MailX 会向服务商获取模型列表；失败时会显示原因，选择“仍然保存”可以不检查就保存。然后选一个模型。

密钥保存在这台设备上，保存后不再显示。MailX 会显示密钥发往哪个主机。Ollama、LM Studio 等本机服务运行在这台电脑上，不需要密钥。

### 默认模型与测试

在“默认模型”下，从你添加的服务商的模型中选一个。“测试”会发送一句固定的短句（不含任何邮件内容），并显示回复用了多久，或失败的原因。翻译默认跟随这个模型，也可以在“设置 → 翻译 → 模型”里另选。

### AI 使用代理

AI 默认直接连接。在“高级”中可以设置只用于 AI 的代理（SOCKS5 或 HTTP，用户名和密码可选），再为每个服务商选择是否经过它。邮箱账号上设置的代理不会用于 AI。代理连不上时请求会失败，不会改为直连。

## 写信与发送

新邮件、回复、全部回复和转发使用独立写信窗口，草稿自动保存在本机。可添加文件附件、插入图片或粘贴截图；普通附件和内嵌图片合计默认上限为 20 MiB，服务商可能另有更低限制。草稿不会同步到其他客户端。

从侧栏打开“草稿”并选择一封，可在阅读区预览已保存的富文本排版和内嵌图片。预览跟随正文主题设置，在草稿保存后更新；普通文件附件单独列出。点击“继续编辑”重新打开写信窗口，或用“删除”丢弃草稿。

检查收件人、发件账号、正文与附件后，按界面提示再次点击发送确认。想留出撤销时间，可在“设置 → 发信”中选择 5、10、20 或 30 秒，默认不等待；撤销只适用于仍在等待的队列项，不能撤回服务器已接受的邮件。

发件箱显示排队、发送失败或结果未知等状态。结果未知意味着服务器可能已接受邮件，MailX 不会自动重发；先检查收件端或服务商的已发送记录，再决定是否手动重试。服务器接受 SMTP 提交也不等于收件人最终收到邮件。

已发送文件夹先显示本机副本，MailX 匹配到服务商保存的副本后只显示服务器那封。QQ 邮箱可能重新分配邮件标识，MailX 也会核对 QQ 保留的原始标识，避免两份同时显示。已有重复项会随邮件头同步重新对账，无需再次发送；无法确认匹配时继续保留本机副本。服务商是否自动保存已发送邮件取决于其行为；MailX 暂不将本机副本上传到服务器。

## 连接外部 AI 客户端（MCP）

MailX 已提供本地 MCP 服务器，内置 AI 聊天尚未提供。MCP 默认关闭。

1. 打开“设置 → MCP”，开启并阅读授权确认。总开关向连接的本机客户端开放所有账号的读取、邮件整理、草稿与本机文件附件管理，以及直接发信，**无需逐封发送确认**。
2. 点击“复制客户端配置”，将配置加入兼容的 MCP 客户端。配置使用随应用安装的 bridge；更换安装位置后应重新复制。不同客户端导入配置的方法以其文档为准。
3. 保持 MailX 运行，可在设置页查看状态与已连接客户端。关闭主窗口并驻留后台时仍可使用；完全退出应用或关闭 MCP 开关后，客户端连接不可用。关闭 MCP 不会取消已入队的发送任务，需在发件箱另行处理。

客户端可能将读取的邮件内容发给其使用的 AI 服务，应按自己的隐私需求选择客户端和模型。当前没有逐客户端或逐账号授权界面，MCP 不支持删除邮件。客户端、平台与工具组合的兼容性见[验证记录](../../development/validation.md)。

## 验证码快捷复制

### 在 MailX 中复制

MailX 识别出邮件中的唯一验证码后，邮件行快捷操作会用“复制验证码”替换星标、已读和归档，保留删除按钮。右键菜单、键盘操作和已有星标标记仍可使用。从邮件行复制不会打开邮件或标为已读。联系人聚合行和多选模式不提供这项单封邮件操作。

阅读区会在正文上方显示轻量的验证码提示条，列出码值与“复制验证码”按钮；复制成功后短暂显示“已复制”。已读、历史或归档邮件中识别出的码同样可以复制，关闭系统通知也不影响此入口。MailX 无法判断发件人是否还接受旧码。不支持的格式或多个候选码不会提供单一快捷复制答案。

### 从通知复制

开启通知内容预览后，MailX 可以识别近期新邮件中的验证码，并为匹配邮件单独显示通知。在 Windows 和 macOS 的系统通知中选择“复制验证码”，即可复制而不打开 MailX 窗口；点击通知正文则打开邮件。Linux 会在通知文字中突出验证码，复制请使用 MailX 窗口。

MailX 需要保持运行，也可以驻留后台。通知中的快捷复制最多可用五分钟，使用后、应用重启、移除账号或关闭相关通知后会失效；不可用时请打开邮件。按钮位置由操作系统决定，可能需要展开通知或把指针移到通知上。

“设置 → 通知 → 显示通知内容”控制系统通知里的发件人、主题和验证码；关闭时也不提供通知复制按钮，按账号静音和前台通知设置同样适用。此开关不影响 MailX 界面内的复制。识别在本机进行，可能会临时从邮箱服务商读取候选邮件，但不会因此标为已读。复制后的码使用系统剪贴板，可能被剪贴板历史或系统同步保留。

### 复制后移到已删除

“设置 → 邮件 → 增强”中的“复制验证码后移到已删除”默认关闭。开启后，邮件列表、阅读区和系统通知的复制按钮采用同一清理行为；普通选中文字复制不会触发此设置。

只有复制成功，才会把该邮件移到账号的“已删除”，并提供短暂的“撤销”。应用内复制在结果提示中提供撤销；后台通知复制则提供系统撤销通知。撤销窗口为五秒，不会因提示显示较晚而重新计时。复制失败时保留邮件；已复制但清理失败时，会分别说明两项结果。

此选项不会永久删除邮件。邮件已在“已删除”中，或账号没有已删除文件夹时，只复制并保留邮件。若后台撤销通知无法准备，MailX 会尝试取消清理；清理已经开始或取消失败时，会提示你在 MailX 查看邮件状态。

## 后台运行、开机启动与更新

关闭主窗口时可选择后台运行或退出，默认每次询问，可在通用设置中修改。macOS 默认在菜单栏显示 MailX，也可以手动关闭；主窗口隐藏后 Dock 仍是恢复入口。开机自启动与静默启动默认关闭；静默启动只在系统登录时自动启动生效。系统或桌面环境没有可用后台入口时会显示主窗口，避免应用运行却无法找回。

MailX 会在启动后不久及运行期间每六小时检查 GitHub 上的新版本，检查固定开启。“设置 → 关于”的“自动更新”默认开启：新版本在后台下载，完成后提醒你重启安装。也可继续工作，在完全退出应用时安装。MailX 不会自动重启，关闭窗口并驻留后台也不会触发安装。

关闭“自动更新”后仍会检查版本，也可手动下载。关闭时会停止自动下载，并取消自动下载包的退出安装安排；你主动点击下载的更新仍会在退出时安装。“取消下载”会暂停该版本的自动下载，直到下次启动、手动下载，或将“自动更新”关闭后重新开启。临时下载失败会有限次重试，需要处理时可从更新入口点击“重试”。如果安装未完成，下次启动会显示失败状态，可重试或从 GitHub 下载安装包。

macOS、Windows 与 AppImage 支持应用内更新。deb / rpm 不提供自动更新，请从发布页安装新包，或使用安装 MailX 时的包管理器更新。系统代码签名与更新包签名是两回事，当前安装包仍可能触发系统首次运行提示。

## 升级与数据保留

应用启动时会执行需要的数据库迁移，具体升级变化见对应版本的发布说明。较旧版本通常无法打开迁移后的数据库；不要把重新安装旧程序当成回退数据的方法。

升级前如需保留回退材料，先从应用中**完全退出**，再复制完整的 MailX 数据目录，包含数据库、可能存在的 SQLite 旁文件、设置和 blob 文件，不能只复制 `mailx.sqlite3`：

| 平台 | 默认数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/MailX` |
| Windows | `%APPDATA%\MailX` |
| Linux | `~/.local/share/MailX`（设置了 `XDG_DATA_HOME` 时使用对应目录） |

密码和授权码保存在系统凭据库，复制数据目录不会复制凭据，也不是已经验证的跨机器迁移或完整恢复方案。自动备份与一键恢复尚未提供；历史队列恢复也可能涉及已经发送的邮件，不要直接用旧备份覆盖正在使用的数据。

遇到问题请在 [Issues](https://github.com/GuqierMcl/MailX/issues) 描述版本、系统、服务商和操作步骤，使用虚构地址及测试邮件；不要附上密码、授权码、真实邮件或完整私人日志。安全漏洞通过[私密报告入口](../../../SECURITY.md)提交。
