# 邮件翻译

状态：**core、桌面 IPC 与界面均已有实现，仅有自动测试；三项翻译服务均未用真实密钥调用，三平台桌面未手测** · 2026-11-12。本文记录把已打开的邮件翻译成用户阅读语言的设计：范围、数据披露、处理链、安全不变量、服务与限额、网络路由、存储与错误。具体验证范围见[验证记录](../development/validation.md#translation-validation)；接口见[应用 API](../contracts/app-api.md#邮件翻译主窗口)；界面见[界面设计语言](ui-design.md#邮件翻译已实现实机未验证仅自动测试)。设计可随实测与后续需求调整。

## 1. 范围与非目标

首版能力：

- 在阅读区翻译已打开的邮件，保留版式：段落、列表、表格、粗体 / 链接和内嵌图片留在原位置；主题一并翻译。阅读区工具栏有翻译按钮和旁边的选项菜单，再次点击按钮回到原文，两个版本同时加载，切换即时，各自保留滚动位置。只有已下载、有正文文档且不是本机已发送副本的邮件才出现翻译控件；纯文本邮件由核心转成 HTML 文档，同样可以翻译，正文为空的邮件没有控件。
- 打开邮件时，如果本机检测到语言与用户阅读语言不同，在正文上方显示一行提示，可翻译、可设为“总是翻译该语言”或“不再提示该语言”，也可只对本封关闭。提示行仅在已选翻译服务并保存密钥后出现；本次应用运行期间，应用按邮件记住用户是在看译文还是原文、提示是否已关闭（不持久化）。离开仍在翻译的邮件会取消该次翻译。
- 翻译过程中原文保持可读，可取消；失败时在同一行显示原因与重试。
- 按语言自动翻译：命中“总是翻译”列表的邮件在打开时自动提交给翻译服务。
- 翻译结果缓存在本机，可在设置中整体清除；阅读区没有单独清除某封邮件译文的控件，工具栏选项菜单里的“重新翻译”会先清除该邮件的缓存译文再重新翻译。

翻译是**非 AI 功能**：服务是 DeepL、Microsoft Translator、Google Cloud Translation 三选一，由用户自带密钥。内置 AI 作为翻译来源见第 10 节，尚未实现。

首版不包含：

- 只存在于本机的“已发送本机副本”（没有可挂缓存的邮件行）；
- 写信时翻译草稿；
- 经 MCP 提供翻译工具；
- 双语对照视图；
- 国内服务（百度、有道、腾讯）。

## 2. 数据披露与同意

翻译会把邮件内容发给第三方。披露范围固定为：**邮件主题和正文文本**。不发送附件、图片、链接地址、HTML 属性，也不发送邮箱密码或任何账号凭证。语言检测完全在本机进行，用户点击翻译（或命中“总是翻译”）之前不发送任何邮件内容。

- 首次使用某个翻译服务前，界面请用户确认一次“将本封邮件的主题和正文文本发送给该服务”；更换服务后需重新确认。同意保存为 `translation.consentedProvider`，只在它等于当前所选服务时有效。
- 同意由 core 强制：`translate_email` 在检查服务与密钥之后、做任何处理之前，若 `consentedProvider` 不等于所选服务，返回 `translationConsentRequired`。不依赖界面是否弹出确认，其他宿主也不能绕过。
- “总是翻译”自动提交同样要求已同意当前服务；未同意时状态里的 `autoTranslate` 为 false。
- “测试”按钮只翻译一句固定的英文，不含邮件内容，因此无需同意。
- 翻译结果是由邮件派生的敏感数据，见第 8 节。

## 3. 处理链

翻译作用于缓存的、已经净化的正文 HTML，与引用折叠处于同一位置：

```text
缓存的净化 HTML → 折叠引用 → 应用翻译 → 绑定图片与链接 → 隔离 iframe
```

- 翻译的输入是 `sanitized_html`，`bodies` 缓存中的原始 MIME 与净化版本不被改写。
- 译文由同一个正文协议提供，使用自己的文档令牌；准备正文时的 `translation` 参数给出译文的目标语言，宿主据此读取缓存的译文，并在提供文档时应用（`include_quotes` 取自已保存的设置）。译文变体没有当前有效的缓存译文时，不签发令牌（准备返回 `notFound`），协议请求也返回 404，**绝不退回提供原文**；原文与译文是两个独立文档，由界面各自加载。“应用翻译”之后的资源绑定、令牌、sandbox、CSP 与链接拦截都沿用[网络与安全](network-security.md)第 5 节，隔离模型不变，正文仍不获得 Tauri IPC 权限。
- 翻译只读取已缓存的正文：正文未缓存时，状态查询不报告语言，翻译返回 `bodyNotCached`，不会为翻译去下载正文。
- 缓存的净化版本与当前 `SANITIZER_VERSION` 不一致时同样视为未缓存。

## 4. 分段与回写

### 4.1 分段（`core/src/translate/walk.rs`）

对净化 HTML 做一次文档遍历，`extract` 与 `apply` 共用同一遍历，因此两者的分段列表由构造保证一致。

- 块级文字块成为一个“段”。段内的行内元素（链接、粗体、强调、`span` 等）、换行和图片成为编号占位符，按段内文档顺序从 1 起计数；属性、URL 和图片本身不发送。
- 不翻译：`code`、`kbd`、`samp`；整段只是一个网址或邮箱地址；不含任何字母的文字；`style`、`script`、`title`、`head`、`svg`、`math`、`select`、`textarea`、`template` 内的内容。
- 回复末尾已折叠的引用历史（`details.mailx-quote`）默认跳过，设置“翻译引用内容”开启后才翻译。
- 一个段最多 64 个占位符，超过的块不作为一段发送。预排版文字保留换行；发件方在约 60 个字符处硬折行的文本按折行规则处理。
- 单封邮件净化 HTML 超过 2 MiB 不翻译；分段数量上限 5000，超出的内容不再切段、保持原文；core 用 `extract_checked` 判断是否在上限处被截断（`truncated`），截断的邮件同样记为部分翻译（`partial`）。
- 遍历为迭代式，恶意的深层嵌套不会耗尽栈。

### 4.2 线格式（`wire.rs`）

发给服务的是极简 HTML 片段：文字做转义，占位符只有 `<span id="n">…</span>`（行内元素）、`<br id="n">` 和 `<img id="n">`。解码很宽松，只产出片段，不信任内容。

### 4.3 回写与安全不变量（`rewrite.rs`）

**服务的答案不可信。** 不变量：译文只能成为文本节点，或复用该段内**已经存在**的元素（按占位符编号匹配）；它不能引入任何新元素或新属性。

- 每个占位符必须在原段中存在且种类一致、至多使用一次；符合时按原结构回写，复用的是原元素的浅拷贝或原节点本身。
- 答案丢了链接或图片（原段中“必须保留”的占位符）时，该段保持原文；其他不匹配的情况退回为整段纯文本译文。
- 答案没有任何非空白文字时，该段保持原文。
- 首尾空白按原文恢复为一个空格。
- 答案条数与请求不一致、单条长度超过源文长度的 10 倍加 1000 字节，视为无效响应（`translationInvalidResponse`）。
- 缓存的段数与当前 HTML 重新切段的结果不一致（过期缓存）时，`apply` 返回 `None`，协议对该译文文档返回 404，不会拼出一份不对应的译文。

分段规则的任何改动，只要可能使同一 HTML 产生不同的段，都必须提升 `SEGMENTER_VERSION`（当前为 1），让旧缓存失效。

## 5. 语言检测

检测在本机完成（`core/src/translate/detect.rs`），不联网，使用折叠引用后、跳过引用的前 4000 个字符作样本。

- 先剔除网址、邮箱地址和数字；字母字符少于 10 个时不给结论。
- CJK 文字按字符类别判定，因为三元组模型在同一文字系统承载多种语言时最弱：CJK 字符占 20% 以上时按文字判定：谚文多于汉字加假名为韩语，假名占 CJK 字符 5% 以上为日语，其余为中文；**简体与繁体不区分**。
- 其余语言交给 `whatlang`，输出小写 ISO 639-1 代码，没有时用 ISO 639-3 代码。
- “可靠”要求加权长度（CJK 字符计 3）不少于 60 且（对非 CJK）检测库自己也认为可靠。只有可靠的检测才会触发提示或自动翻译。
- 语言比较只看主语言子标签，忽略文字与地区：`zh-Hans`、`zh-Hant` 与检测到的 `zh` 相同；`nb` 与 `no` 视为同一语言。

状态判断（`translation_status`，纯本地）：

- `suggested`：已选服务且已保存密钥、邮件不是本机已发送副本、设置“显示提示”开启、检测可靠且与目标语言不同、该语言不在“不再提示”列表中。
- `autoTranslate`：同样要求已选服务且已保存密钥与可靠的外语检测，另外要求已同意当前服务，并且该语言在“总是翻译”列表中。
- 同一语言不能同时在两个列表里：保存设置时拒绝，读取旧文件时从“不再提示”里去掉冲突项。

## 6. 服务与限额

| 服务 | 主机（固定） | 说明 |
| --- | --- | --- |
| DeepL | `api.deepl.com`；密钥以 `:fx` 结尾的免费版使用 `api-free.deepl.com` | 英语、葡萄牙语目标分别映射为 `EN-US`、`PT-BR` |
| Microsoft Translator | `api.cognitive.microsofttranslator.com` | 全局入口，资源区域放在请求头；区域可留空 |
| Google Cloud Translation | `translation.googleapis.com` | Basic v2，密钥放在请求头；`zh-Hant` 映射为 `zh-TW`，`nb` 映射为 `no` |

目标语言共 26 种（`core/src/translate/languages.rs`）：简体中文、繁体中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、意大利语、俄语、荷兰语、波兰语、土耳其语、阿拉伯语、印尼语、乌克兰语、瑞典语、丹麦语、芬兰语、捷克语、希腊语、匈牙利语、罗马尼亚语、保加利亚语、书面挪威语。设置为“跟随应用语言”时，中文界面使用简体中文，其他情况使用英语。所选服务不支持该语言时返回 `translationLanguageUnsupported`。

每次请求携带的内容上限（预算低于各服务文档给出的上限，留出引号与转义的余量）：

| 服务 | 每次请求条数 | 每次请求文字字节 |
| --- | --- | --- |
| DeepL | 50 | 100,000 |
| Microsoft Translator | 1000 | 40,000 |
| Google Cloud Translation | 128 | 80,000 |

邮件级限额：

- 净化 HTML 超过 2 MiB：`translationTooLarge`。
- 一封邮件最多发送 50,000 个字符的段落文字，超出的独立段落保持原文；单段超过一次请求上限的、以及在 5000 段上限处被截断的内容同样保持原文。这几种情况都把结果标记为“部分翻译”（`partial`，截断标志与预算标志取“或”），界面会注明只翻译了前面的部分。相同的段落只发送一次，重复出现不占预算；单段本身超过一次请求上限的同样保持原文。主题单独作为一项发送，不占这 50,000 字符预算。
- 每个请求总时限 30 秒；超时为 `translationTimeout`。
- 一次翻译把条目按上表限制分批，顺序发出。

## 7. 网络路由与密钥

- 翻译使用**专用路由**，来自翻译设置：`direct`（直连）或 SOCKS5 / HTTP 代理（`route.kind = "proxy"`，含类型、主机、端口和可选的 `username`）。邮箱账号自己的代理不用于翻译。设置页把这些放在页面末尾默认折叠的“高级”组里。
- 代理登录是可选的：`username` 非空时才登录，空表示不登录，即使本机存有代理密码也不使用。用户名不是秘密，存在设置里，校验与账号代理用户名相同（非空白、不超过 255 字节、无控制字符，不去首尾空白），字段为 `translation.route.username`；设置文件里非法的用户名只丢弃该用户名，代理本身保留，不会因此变成直连。
- 代理密码是秘密，存放在 `SecretStore`，名称为 `mailx/translation/proxy-password`（不会与按服务命名的密钥冲突）。写入时不去首尾空白（密码可以以空格开头或结尾），拒绝空值、控制字符与超过 16384 字节的值，字段为 `translation.route.password`；没有任何接口返回密码，只返回“是否已设置”。请求前才读取：有用户名而没存密码时使用空密码；有用户名而系统凭据库被锁定或不可用时，请求以该凭据库错误失败，绝不在缺少登录的情况下发出，也不回退直连。
- 代理不可用、连接失败或拒绝登录返回 `translationProxy`，**绝不回退直连**；不为代理登录失败另设错误码。
- 主机固定，没有任何用户可填的服务地址；请求走 `net::connect` 与 `net::upgrade_tls`，按主机名验证证书，不提供忽略证书的开关。
- 密钥存放在 `SecretStore`，名称为 `mailx/translation/<provider>`（`deepl` / `microsoft` / `google`）。写入前去掉首尾空白，拒绝空值、控制字符与超过 512 个字符的值；没有任何接口返回密钥，只返回“是否已设置”。密钥与区域在请求头中标记为敏感值，不出现在调试输出里；代理密码同样不出现在调试输出里。
- 服务的错误只按状态码或错误原因代码分类为上文的固定错误，不向界面传递服务返回的原文。

详见[网络、凭证与不可信内容边界](network-security.md#9-邮件翻译)。

## 8. 存储与失效

表 `message_translations`（迁移 `0029`，详见[数据库迁移](database-migrations.md)）按（邮件、目标语言、是否含引用）为主键保存：

- 邮件正文的原始内容哈希、净化版本、分段版本；三者任一变化，旧行即视为过期，无需清理任务；
- 所用服务、服务报告的源语言、译文主题；
- 每段一项的译文（线格式字符串，或 `null` 表示保持原文）及是否部分翻译。

译文只保存线格式字符串，只有经 `translate::apply` 才会在隔离的正文协议中变成 HTML。写入前核对邮件仍是翻译时的那份正文（`BodyNotCached` 表示期间已变化）。

- 邮件删除或账号移除时，缓存随之删除（外键级联）；设置里可清除全部；API 提供按邮件清除（`clearTranslation`），界面只在“重新翻译”里使用，阅读区没有单独清除的按钮。
- 译文是邮件派生的敏感数据：与邮件缓存一样不整体加密，设置页显示数量与大小并提供“清除”。
- 本机已发送副本没有对应的邮件行，无法缓存，也不提供翻译。

## 9. 并发、取消与错误

- 全应用同时最多 2 个翻译在运行，其余排队；对同一封邮件再次发起翻译会取消上一次。
- `translation_cancel` 取消正在进行的翻译，调用方得到 `translationCancelled`；已经取消的结果不会写入缓存。取消立即停止等待：进行中的请求被丢弃，写入缓存前还会再检查一次取消标志。
- 翻译前的检查顺序：设置校验 → 已选服务 → 已保存密钥 → 同意 → 目标语言 → 正文读取与大小。

错误代码与面向用户的含义（固定脱敏文本；界面以代码生成中英文文案，不解析中文消息）：

| code | 用户看到的含义 |
| --- | --- |
| `translationNotConfigured` | 还没有选择翻译服务，或没有保存密钥 |
| `translationConsentRequired` | 需要先同意把邮件文字发给所选服务 |
| `translationKeyRejected` | 服务没有接受这个密钥，请检查后重新填写 |
| `translationQuotaExceeded` | 翻译额度已用完 |
| `translationRateLimited` | 请求太频繁，稍后再试 |
| `translationNetwork` | 暂时连不上翻译服务 |
| `translationProxy` | 无法通过设置的代理连接翻译服务 |
| `translationTimeout` | 翻译服务响应太慢 |
| `translationUnavailable` | 翻译服务暂时不可用 |
| `translationInvalidResponse` | 翻译服务返回的内容无法使用 |
| `translationLanguageUnsupported` | 所选服务不支持这种目标语言 |
| `translationTooLarge` | 这封邮件太大，无法翻译 |
| `translationCancelled` | 翻译已取消 |

另有 `bodyNotCached`（正文尚未下载或已变化）与参数校验的 `validation`（例如 `translation.key`、`translation.route.port`、`target`）。

## 10. 后续：内置 AI 作为翻译来源（Planned）

翻译来源的设计允许在三项服务之外增加“模型”类来源，等 [AI Runtime](../ai-runtime/README.md) 落地后接入：模型来源应沿用本文的分段、线格式、不可信回写与缓存规则，并复用 AI 运行时的内容披露与 Run 规则。**这些均未实现**：当前没有任何模型被用于翻译，设置里也没有模型选项。

## 11. 状态与验证

**Implemented（仅自动测试）**：分段与回写（含恶意答案）、语言检测、三个服务客户端（对本机模拟监听器）、代理路由（含对本机模拟 HTTP CONNECT 监听器的代理登录头）、翻译服务与缓存有 Rust 单元测试；前端界面测试与之配套。**尚未验证**：没有用真实密钥调用过任何一项服务；DeepL 的 `ZH-HANT`、`NB` 目标代码及每次请求条数上限，以及 Google 对无效密钥的响应形态，无法从公开文档确认；语言检测准确率未在真实邮件上测量；版式保真未用真实营销邮件语料检查；没有 macOS、Windows、Linux 的桌面手测。具体记录见[验证记录](../development/validation.md#translation-validation)。
