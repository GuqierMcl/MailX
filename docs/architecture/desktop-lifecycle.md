# 桌面关闭、后台运行与退出

状态：**Implemented；三平台真实桌面行为仍按验证策略分别验收** · 2026-10-29。

## 用户选择

所有平台默认“每次询问”。主窗口关闭按钮（含对应窗口关闭快捷键）弹出“关闭 MailX 后如何处理？”；取消不改变偏好，勾选“记住我的选择，不再询问”并选择后台/退出才持久化。设置 → 通用 → 关闭主窗口时可随时改为每次询问、后台或退出，只影响下一次关闭。

| 平台 | 后台选项 | 恢复入口 | 最小化按钮 |
| --- | --- | --- | --- |
| macOS | 关闭窗口并继续运行 | Dock/Finder；可选菜单栏图标 | 原生 Dock 最小化 |
| Windows | 最小化到系统托盘 | 托盘左键或“打开 MailX”，应用快捷方式 | 原生任务栏最小化 |
| Linux | 最小化到系统托盘，限有可用宿主的会话 | 托盘菜单“打开 MailX”，应用启动器 | 遵循窗口管理器 |

macOS 保留 Regular 应用身份及 Dock，不因关闭窗口切换为 Accessory。Cmd+H 隐藏整个应用；Cmd+Q、应用/Dock/托盘退出，以及设置中的“退出 MailX”，直接进入退出流程，不再询问后台偏好。关闭写信窗口只处理自己的草稿。

主窗口选择后台时隐藏但不销毁 WebView，维持当前页面和事件监听；仍占用窗口内存。写信窗口不受影响。第二次启动只唤回同一个实例；Dock 重开同时处理主窗口隐藏/最小化状态。通知继续按既有设置运行，未改变后台 3–10 分钟目标轮询间隔，托盘不等于即时推送。

## 托盘与降级

Windows/Linux 创建通知区域入口；macOS 的“在菜单栏显示 MailX”默认关闭，关闭此图标不影响后台运行。原生菜单提供打开 MailX、写邮件、立即同步、设置、退出 MailX，跟随应用语言。写邮件/设置仅在工作台已订阅动作时可用，避免启动期间丢动作；不提供直接发信操作。

Linux 的 AppIndicator 对象创建成功不证明有可用宿主。后台操作需要会话 D-Bus 的 `org.kde.StatusNotifierWatcher.IsStatusNotifierHostRegistered` 为真；探测放在 worker，单轮含连接在内最多 750ms，每约 5 秒复查。托盘单击事件在当前 Linux 后端不可用，所有恢复操作通过菜单提供。宿主消失后恢复可发现窗口但不抢焦点；已知锁屏时延后到解锁，无法确认锁屏状态时保守等待健康探测。用户主动打开不受此限制。

缺少宿主、创建失败或不可确定时，不允许隐藏最后一个恢复入口；已记住后台偏好则本次重新询问，不静默退出或覆盖偏好。宿主探测不证明图标没有被用户藏入溢出区，应用快捷方式始终是另一恢复入口。Windows 的托盘溢出区、Explorer 重启、Linux 的 GNOME 扩展变化与 Wayland 激活规则需真机验证。

## 安全退出

关窗策略属于 desktop；同步、写回和发送任务仍属于同一个 Rust 核心。隐藏不暂停撤销发送倒计时或已经确认的发送。核心不依赖 Tauri。

明确退出时建立退出代际，暂停领取新的发件队列项，请求所有写信窗口保存，并等待主窗口刷新防抖布局设置及进行中的界面变更。主窗口在这一轮退出中暂停编辑，按同一代际确认写入完成。已经领取的发送事务继续至结果落盘；所有写信窗口确认关闭且发送空闲后才退出。保存失败或用户取消立即取消退出；30 秒未完成同样取消退出并显示主窗口说明，绝不把超时当作放弃草稿。取消后恢复队列领取，迟到的关闭确认不得影响下一轮。

整应用退出期间不删除空草稿，避免另一窗口取消退出时迟到的删除仍破坏数据；普通写信窗口关闭保留空草稿清理，且没有强制销毁期限。账户移除导致草稿不再存在的强制关闭保留独立路径。更新重启沿用明确退出协调器；取消退出也取消更新重启标记，隐藏不会触发退出时安装。

系统关机、注销、强制终止不能保证运行完整异步退出流程。草稿持续自动保存、发送结果持续落盘，重启按已有协议状态恢复：未开始投递可回队列，可能已送达且无法确认时保留 unknown，不自动重发。后台驻留不提供睡眠中收信、退出后常驻、登录自动启动或独立服务；登录启动与 IMAP IDLE 另行实施。

实现入口：`desktop/src/lifecycle.rs`、`tray.rs`、`tray_support.rs`、`compose.rs`；前端 `features/lifecycle/`、通用设置和写信窗口关闭协议。接口见[应用 API](../contracts/app-api.md#桌面主窗口关闭与后台运行)。
