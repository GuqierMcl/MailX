# 验证码识别

状态：**core 本地识别、列表与阅读区快捷复制、桌面验证码通知和可选复制后清理已有实现**。这是规则识别实验，尚无真实邮件语料上的准确率或覆盖率结论。自动验证与有限的 macOS 开发模式手测证据见[验证记录](../development/validation.md#verification-code-notification-validation)。

## 1. 能力与宿主边界

纯识别模块提供宿主无关的函数、合成样本测试与本地命令行探测。函数不访问账号、数据库或网络，不获取正文、不写日志，不发通知或操作剪贴板。

应用层提供共享的识别状态与结果缓存；桌面列表、阅读区和系统通知通过同一复制服务复核识别结果并写剪贴板。Windows / macOS 的原生通知提供复制按钮，Linux 的原生通知只在文字中突出验证码；三平台应用内界面均有复制入口。所有复制均由用户点击触发。

“设置 → 邮件 → 邮件增强”的“复制验证码后移到已删除”默认关闭。开启后，专用复制动作成功才安排可撤销的移到 Trash，不能永久删除。没有新增 MCP 验证码或剪贴板工具。

## 2. core 接口

模块：`mailx_core::mail::verification_code`。

| 接口 | 输入与结果 |
| --- | --- |
| `detect(subject, body)` | 已解码的主题和纯文本正文，返回 `Result<Detection, DetectionError>` |
| `detect_eml(raw)` | 完整的 RFC 5322 / MIME 字节，解析主题和正文后执行同一检测器；不适用于部分 IMAP 预览 |
| `Detection::Found` | 唯一 `Candidate { code, evidence }` |
| `Detection::Ambiguous` | 多个不同候选，不选择其中一个作为答案 |
| `Detection::NotFound` | 没有满足规则的候选，不代表邮件一定不含验证码 |
| `DetectionError` | `InputTooLarge` 表示超过处理预算；`InvalidMessage` 表示 MIME 不受支持或结构 / 编码无效 |

`code` 保留原有前导零与字母大小写。同码的多处出现合并，大小写不同按不同候选处理。`evidence` 仅携带来源（主题 / 正文）、规则和固定关键词，不携带周围原文；规则区分关键词在码前、在码后，以及主题关键词与正文开头的独立数字行。

纯识别结果提供显式 JSON 序列化供本地探测使用，输出状态为 `found`、`ambiguous`、`notFound`。候选的 `Debug` 对码值脱敏。应用服务使用第 7 节的状态 DTO 和识别凭据；它们仅开放给可信主窗口，不能因纯类型可序列化而向其他入口暴露。

## 3. 首批规则

- 接受连续的 4–8 位 ASCII 数字，或同长度且同时含 ASCII 字母和数字的码；全字母、全角、空格分组与带连字符的码暂不支持。
- 要求局部明确语境，例如“验证码 / 驗證碼 / 校验码 / 动态密码”、`verification code`、`security code`、`login code`、`one-time password`、`OTP`，或码后紧邻 `to sign in`、`to verify your email` 等明确用法。
- 关键词与码之间只接受短连接语和标点，例如 `is`、`your`、“为”“是”，不以距离近为唯一依据。因此 `verification code expires in 2026`、`verification code: order number 123456` 不匹配。
- 主题有明确验证码语境时，可接受正文开头独立一行的数字，或正文中的 `code: …`；不把任意段落中的独立数字提升为验证码。
- 同一语境列举多个不同码（如 `123456 or 654321`）、主题与正文码冲突时返回歧义。重复出现的同一码仍是唯一候选。
- 排除链接 / 邮箱地址 token 内的数字，拒绝从长字符串、分组数字、电话、日期、小数和带不可见连接符的数字中截取片段；金额符号、百分比和明确旧码语境也会排除。
- 回复 / 转发前缀的主题不参与检测。纯文本正文跳过 `>` 引用行，在常见的 `On … wrote:`、原始邮件或转发分隔行处停止。新写正文仍可被识别。

这是保守的有限规则，不是自然语言理解：未列出的语言、换行方式、引用分隔符、带品牌名的连接语可能漏识别；识别结果不证明发件人身份、验证码有效期，也不代表用户正在进行相应登录。

## 4. MIME 与预算

MIME 路径复用现有 `mail-parser` 解码、渲染模块的结构 / 编码检查、HTML 净化与文本转换。附件与内嵌的其他邮件不作为识别正文。非空 `text/plain` 优先；没有可用纯文本时才从 HTML 提取文本。因此相互不一致的纯文本 / HTML alternative 以纯文本为准，不声称两种表示一致。

HTML 提取前移除 `blockquote`、常见引用容器、脚本 / 样式 / 模板及明确隐藏内容（`hidden`、`aria-hidden`、内联 `display:none` / `visibility:hidden` / `mso-hide:all`）。移除时保留边界，避免把两段数字拼接成新码。HTML 实体、编码和正常行内文本拼接由现有解析流程处理。它不运行浏览器布局、不求值任意 CSS，也不加载远程图片或样式表，不能保证识别所有视觉隐藏内容。

| 预算 | 上限与处理 |
| --- | --- |
| 原始 MIME | 1 MiB，在解析前检查 |
| 主题 | 4 KiB，解码后检查 |
| 纯文本 / HTML 源表示 | 各 64 KiB，选用前均检查；HTML 转文本后再次检查文本上限 |
| 不同候选 | 最多 16 个，超过时失败 |

超过预算时拒绝本次检测，不扫描截断前缀后声称找到唯一答案。字节限制约束输入规模，不是解析器的精确内存峰值保证。检测器按有界上下文扫描，网络地址范围只预处理一次。

## 5. 本地模拟探测

在仓库根目录运行，使用提交的合成样本：

```sh
bun run otp:probe --eml tests/fixtures/verification-code/sample.eml
```

该样本包括当前验证码、HTML 编码与引用中的旧码。预期结果为 `found`，码为 `482913`，旧引用码不进入候选。

也可仅提供主题，或提供主题与 UTF-8 文本文件；文件路径 `-` 表示从 stdin 读取：

```sh
bun run otp:probe --subject 'Your verification code: 001234'
bun run otp:probe --subject 'Your verification code' --body-file /path/to/synthetic-body.txt
bun run otp:probe --eml -
bun run otp:probe --help
```

无需 Bun 时使用 `cargo run -p mailx-core --locked --example verification_code_probe --` 加相同参数。JSON 输出到 stdout，包含码值；只对明确提供的文件或 stdin 进行读取，错误输出不附带路径或邮件原文。`found`、`ambiguous`、`notFound` 均是成功运行，参数、输入或输出失败返回非零退出码。分享输出和提交样本时只使用合成或脱敏数据，不提交真实邮件。

批量回归覆盖见 `core/src/mail/verification_code/tests.rs` 和 `core/tests/verification_code_mime.rs`，执行方式：

```sh
cargo test -p mailx-core --lib mail::verification_code --locked
cargo test -p mailx-core --test verification_code_mime --locked
```

模拟测试通过只能证明这些样本上的规则行为。仍需扩充脱敏模板，分别检查误识别、漏识别、歧义和 MIME 提取结果。

## 6. 桌面通知接入

入口为 `CoreEvent::NewMail`，沿用真正新到达未读收件箱邮件的判定；首次同步、历史补齐和 UIDVALIDITY 重建不会触发。事件保留本轮完整的 `messages`（受同步范围约束），普通账号摘要仍只列前 3 封的发件人。桌面最多同时准备 2 个批次；每批最多探测 5 封主题疑似验证 / 登录的邮件，整个批次最多等待 5 秒。没有空闲准备名额或候选不足时直接发普通通知，失败后不补发第二条提醒。

宿主先应用通知总开关、账号静音、前台是否通知与 `showPreview`。隐藏预览时不抓取验证码正文，也不显示码值或按钮。每次读取候选和最终展示前重新检查设置；宿主的设置修订号阻止旧查询撤销新隐私偏好，最终展示、复制与设置撤销共享互斥边界。设置界面把预览开关说明为发件人、主题及识别到的验证码。

### 获取与识别

`MailxCore::notification_verification_code(email_id)` 仅供可信宿主从新邮件事件调用，通知专用方法不直接作为 IPC 或 MCP 入口；它复用第 7 节的共享识别服务。核心独立检查当前可见 INBOX、未读、候选主题，以及 `received_at` 距当前不超过 10 分钟且不在未来。候选主题是轻量中英文规则，不保证所有验证码模板都被探测。

读取使用独立于用户阅读通道的并发闸门，整个 core 请求限时 4 秒、全局最多 2 个；优先读取不超过 1 MiB 的本地原始缓存，否则按账号路由建立临时 IMAP 连接，`EXAMINE` 核对 UIDVALIDITY 后执行有界 `BODY.PEEK[]`。接收器在分配 literal 前强制 1 MiB 限额，未知或错误的服务器 size 不能绕过上限。取消会丢弃网络 future；解析等已开始的本机阻塞任务可能继续完成，但不会发布迟到结果。下载不标已读、不写正文缓存或失败状态，不影响用户后续正常阅读的重试。

完成后再次核对账号 revision、邮箱来源、UIDVALIDITY 和邮件可见性；超时、网络失败、超限、无候选或有歧义均回到普通通知。网络只访问邮件账号现有路由，不调用模型，也不获取 HTML 远程资源。

### 展示与复制

识别成功的每封邮件单独通知，标题带发件人与账号名，正文首行显示验证码，随后显示主题；这些邮件从普通账号摘要中剔除。同批多条通知只播放一次提示音。原生按钮准备失败时回退为带验证码文字的普通通知。

Windows / macOS 的按钮参数只携带随机 UUID，不带验证码、账号或正文；当前进程的原生动作表（最多 128 项）将其绑定到邮件与共享识别凭据，码值由共享识别缓存持有。动作有效期最多 5 分钟，成功复制后消费，过期项在下一次注册或查询时移除；它是快捷动作的有效期，不是邮件验证码的真实有效期。用户点击时重新核对 token、通知预览/静音设置与邮件当前身份和时效；允许用户已经读过该邮件。账号移除、隐私设置撤销、应用重启或动作过期都会使复制失效。原生剪贴板写入由宿主完成，窗口隐藏时仍可执行；复制后按第 8 节的设置决定是否清理邮件，不读取旧剪贴板，不自动复制、粘贴、恢复或定时清空。系统历史记录与跨设备同步由操作系统控制。

点击通知正文打开对应邮件；复制成功不唤起主窗口。快捷动作不可用或剪贴板写入失败时提示打开邮件。关闭通知/预览或账号已移除时不再投递复制结果。旧通知的显示记录不一定能撤回，不能把撤销动作等同于清除系统通知历史。

### 平台实现与待验边界

- **macOS**：复用现有 `tauri-plugin-notification` 的原生 action，只有一个“复制验证码”按钮；普通通知的 `tap` 监听器忽略专用 token，由独立回调区分复制与打开。当前依赖仍使用旧 `NSUserNotification` 后端，按钮位置和展开方式由系统控制；开发模式身份与通知中心回调必须以安装包实测确认。
- **Windows**：验证码通知单独使用 WinRT Toast XML，主题与正文以文本节点转义。复制按钮和正文使用协议激活；在当前用户的 `Software\Classes` 下注册与应用 identifier 对应的 `<identifier>.notification` 协议及当前可执行文件路径，通过现有单实例入口转交给运行中的应用。复制入口在普通聚焦前拦截，冷启动收到旧动作时直接退出，因为旧 token 不可恢复。通知带独立组和 5 分钟原生过期时间，启动或关闭内容预览时清理该组；普通邮件通知仍使用原插件。注册使用现有安装包 AUMID，安装包内的通知中心留存、系统协议分发、升级与安装路径变化需要实机验收。
- **Linux**：使用普通系统通知，只改变验证码邮件的文字内容，不注册复制 action；声音、通知紧急级别和正文点击能力沿用现有通知服务器行为。应用内复制使用宿主持有的原生剪贴板对象，避免写入后立即释放剪贴板所有权。

普通通知 API 的成功返回只说明请求准备成功，操作系统仍可能因权限、专注模式或通知设置而不显示。三平台实际呈现、Windows 通知中心中的复制及 macOS 后台复制尚不能由单元测试替代。

## 7. 共享识别状态与界面

`MailxCore::verification_code_status(email_id, allow_fetch)` 面向当前可见的服务器邮件，与通知总开关、已读状态、文件夹角色和邮件年龄无关。已读、历史和本机归档中的邮件仍可手动复制识别出的文字；不会把通知动作的 5 分钟有效期或 10 分钟候选窗口当作邮件验证码的真实有效期。草稿、本机已发送副本和不可见邮件不提供复制结果。

结果 `VerificationCodeStatus` 包含 `emailId`、`state`、`code`、`recognitionId`。状态为 `unchecked`（尚未得到可检查的正文）、`ready`（唯一候选）、`notFound`（已检查但未命中规则）、`ambiguous`（多个候选）或 `unavailable`（当前身份、输入预算或读取条件不允许提供结果）。只有 `ready` 携带码值和随机的识别凭据；“未命中”不证明邮件不含验证码。

通知、列表和阅读区共用最多 512 项的进程内结果缓存，不新增持久化码值副本。缓存绑定账号、邮箱来源、连接 revision、文件夹、UIDVALIDITY、UID、本地邮件 ID 和原始 MIME 哈希；来源或已缓存正文变化后旧结果不再有效。同封邮件并发请求复用一次读取，已存在的结果不排在慢网络读取之后；账号移除会释放其缓存项。

列表只请求实际可见的单封邮件行，前端最多同时发起 2 项请求，行离开视口后尚未开始的请求放弃。后端只为疑似验证码主题进行受限网络读取；已缓存完整正文可在普通主题下识别。阅读区在正文缓存状态变化时重新查询，因此正常打开邮件后也能补充识别。复制入口可用性独立于系统通知设置，不扫描整个邮箱。

- **列表卡片**：唯一候选将星标、已读与归档三个快捷操作替换为固定文案“复制验证码 / Copy code”，保留删除按钮；码值不写进按钮名称。已加星标记、右键菜单和键盘操作继续可用。复制不打开邮件或标为已读，多选模式、发件人聚合行不显示这项单封操作。悬停 / 键盘聚焦期间固定按钮所使用的识别快照，避免异步结果到达时替换指针下的动作；最终复制仍由后端校验识别凭据。
- **阅读区**：可信应用界面中的轻量提示条位于正文、翻译与图片提示之前，不注入邮件 HTML。标签和等宽码值按基线对齐，间距 8px，按钮固定为“复制验证码”。提示绑定当前展开邮件；HTML、纯文本及已有识别结果但正文仍在加载的情况均可显示。
- **反馈**：请求中禁用重复操作，成功短暂显示“已复制 / Copied”；复制失败提示重试并刷新结果。多个不同候选不显示可直接复制的唯一答案。

## 8. 复制后移到已删除与撤销

设置为 `mail.trashVerificationMailAfterCopy`，默认 `false`，旧设置文件缺少该节时补默认值。界面位于“邮件”分组的独立“邮件增强 / Mail enhancements”页，不属于通用设置。此设置统一作用于列表、阅读区和系统通知的专用复制按钮，普通选中文字复制不会触发。

桌面共享入口调用 `copy_verification_code_with_policy`。核心在服务锁内复核识别凭据、邮件当前身份与正文版本，宿主在实际写入时读取最新设置并通过修订号闸门，再调用原生剪贴板。剪贴板写入成功后才能在同一核心服务锁内安排清理；复制失败或凭据失效不删除。识别凭据只用于定位已识别结果，调用方不能传入任意码值或指定永久删除。

`VerificationCodeCopyOutcome` 总是表示复制已经成功，另含 `cleanup` 与可空的 `deletion`：

| `cleanup` | 行为与反馈 |
| --- | --- |
| `disabled` | 设置关闭，只复制 |
| `queued` | 复用现有删除队列，本地立即隐藏，返回 `EmailDeletion` 与 5 秒撤销窗口；仅移到 Trash |
| `unavailable` | 已在 Trash 或账号无可选 Trash，只复制并保留邮件 |
| `failed` | 已复制，但安排清理失败，或原生撤销提示失败后成功取消清理；提示邮件已保留 |

清理始终使用 `confirmedPermanent=false`。在 Trash 内或没有 Trash 时不弹永久删除确认，也不把设置开启视作永久删除授权。已隐藏的邮件不能被重复排队；撤销后恢复原有可见状态，不恢复剪贴板旧内容。

应用内复制由响应更新当前列表、阅读区和未读数，并显示带“撤销”的 Toast。通知复制另外向主窗口发送不含码值的结果事件；后台清理提供单按钮原生撤销通知，UUID 只绑定清理批次，期限使用原删除队列的剩余窗口，不重新延长 5 秒。撤销可在关闭通知内容预览后继续使用，Windows 的撤销通知使用独立组，清理验证码通知不会同时移除它。

若原生撤销通知连准备都失败，宿主尝试取消已排队的清理；取消成功则保留邮件并提示复制成功、清理失败。若服务器写回已经领取或取消失败，则保留真实的 `queued` 结果并提示暂时无法撤销，不能声称邮件已经恢复。通知准备成功也不保证操作系统实际展示；原生交互仍按[验证记录](../development/validation.md#verification-code-workbench-validation)分别验收。
