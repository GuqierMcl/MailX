# 界面设计语言：画布与浮动岛屿

状态：**Accepted；第一阶段（无毛玻璃）已有实现，桌面三平台的实际观感尚未逐一验证** · 2026-10-21。此文是前端界面的风格约定，用于指导后续开发；与实际代码冲突时以代码和测试为准，新的明确设计优先于本文，更新时同步修订。

## 界面文本与语言

首版已支持简体中文与英文，可在“设置 → 通用 → 语言”选择跟随系统或显式语言。下文的中文名称、按钮和提示为示例；实际界面、Tooltip 和读屏标签使用当前语言，包括 Windows / Linux 自绘窗口按钮。业务组件在渲染时订阅语言变化，模块级配置保存语义 key；切换不重新挂载编辑器或清空选中项。邮件原文、主题、用户命名与附件名按原数据展示，日期 / 时间、数字、文件大小和排序沿用现状。新功能应同时提供中英文资源及无障碍文本，范围和验证规则见[中英文文本适配](internationalization.md)。

从导航或命令面板打开设置窗口时，默认选中第一项“通用”；需要定位到特定设置页的入口仍通过 `SettingsTarget.section` 指定目标。

## 总体结构

整个窗口是一块**画布**，邮件内容是浮在画布上的**岛屿**：

- **画布**：标题栏与左侧导航（`NavRail`）连成同一平面，底色由根容器 `.app-canvas` 提供，两者之间没有边框，也没有各自独立的背景。
- **岛**：邮件列表与邮件阅读区合成**一个**岛（`Island`），而不是每栏一个。两者关系紧密，拆开会过碎；导航将来扩展为综合菜单入口，留在画布上更合适。
- **间距**：岛与窗口右、下边缘及与导航之间保持 8px，让画布露出；导航收成图标栏后仍保留这 8px。

岛的表面：圆角 `rounded-2xl`、`bg-background` 实色、`shadow-sm` 和半透明描边 `ring-1 ring-foreground/10`，保证正文可读性。画布与岛的色阶通过 token 取得，不写死色值：

| 用途 | 来源 |
| --- | --- |
| 画布底色与导航色 | `--sidebar`、`--sidebar-accent`、`--sidebar-border`，在 `.app-canvas` 内按明暗覆盖，设置对话框等区域不受影响 |
| 岛 | `--background`、`--foreground` |
| 强调色 | 外观设置写入的 `--primary` 等，不在组件里改 |

主岛外层不设置滚动裁切，让上沿阴影与描边自然延伸到标题栏画布；圆角内容裁切保留在 `Island` 内，列表、阅读区和启动状态页分别管理自己的滚动。

## 不用分割线

岛内和画布上**不画分割线**，区域靠留白、色调和阴影区分：

- 不使用贯穿式 1px 线：不要在岛内用 `Separator`，不要给栏与栏之间、头部与内容之间加边框。
- 列表与阅读区之间：列表区用很淡的底色（`bg-muted/40`），阅读区保持岛的原色；拖拽条平时不可见，悬停和拖动时才显示淡色高亮，点击范围仍保持约 8px。
- 工具栏里的按钮分组用间距分开，不用竖线。
- 列表中的每条邮件**不加卡片边框**：平时透明，悬停轻微变深（`hover:bg-foreground/5`）；当前打开的邮件使用独立的选中底色，默认石墨外观下为浅蓝底，深色模式为较深的蓝底，设置自定义强调色时使用对应的淡色底。近灰、极亮或极暗的自定义色会使选中底色回退为默认蓝色，以保持可辨对比，主强调色设置不变。选中状态由当前打开的邮件决定，鼠标移开、进入阅读区、再次悬停或聚焦时均保留，文字继续使用正常前景色。草稿与发件箱列表复用同一选中底色。
- **列表标题的邮箱名称**：查看某个账号的具体文件夹或该账号的本机“已归档”时，在文件夹标题右侧以小号、常规字重的 `text-muted-foreground` 文字显示账号的 `displayName`，便于辨认当前邮箱；长名称以省略号截断。跨账号统一视图不显示此名称。
- 邮件列表使用虚拟滚动（`@tanstack/react-virtual`），只渲染可视窗口及上下少量缓冲行；选中行和当前获得焦点的行始终保留在 DOM 中，每行带 `aria-setsize` / `aria-posinset`。每行高度固定：发件人与主题均单行截断，预览区按 `previewLines` 预留 1 / 2 / 3rem（`none` 不预留），高度随根字号缩放。预览区有三种显示：等待预览（`previewState` 为 missing 且未放弃）时第一行以弱化色显示“（加载中）”，其余留空；预览就绪（或正文已下载）时显示预览文本，文本为空则留空；预览失败，或本次尝试没有结果而暂时放弃（60 秒内不再请求）时留空。三种状态占用同一预留高度，行高不变。只有渲染出的行（可视窗口加缓冲）才请求预览，防抖约 250 ms，`none` 时不发请求。滚动到距末尾约 10 行时自动加载下一页；加载失败不自动重试，仍由“加载更多”按钮重试。
- 头像在整行**垂直居中**；未读标记放在每行最左侧的**固定窄列**（头像左边），宽约 12px、所有行相同，只放 8px 的未读蓝点并垂直居中，所以无论发件人名字多长，所有行的点都在同一条竖线上；已读行此处留空，头像距行边缘约 20px。点用**固定蓝色**（浅色 `blue-500`、深色 `blue-400`），不跟随强调色：红、橙类强调色会被读成错误或紧急，黄色会和星标撞色。未读与已读的视觉差异只由这个蓝点表达，邮件文字保持同一字重；这个点只是指示，不可点击（保留“未读”无障碍标签），已读 / 未读切换放在右上角的快捷操作里。
- **快捷操作是行右上角的一条横排工具栏，所有 `previewLines` 取值（含 `none`）都相同。** 鼠标悬停或键盘聚焦邮件行时，它在时间位置淡入、时间淡出；从左到右依次为星标、已读 / 未读、归档 / 移回收件箱（仅可归档时），隔开一段明显间距后，最右侧是删除（本机副本为带确认的“从本机移除”，且没有服务器读写操作）。可用性规则不变：多选模式与发件人分组行没有快捷操作，当前不能修改标记或归档时对应按钮不出现。图标字形 14px，每个按钮点击区 24×24px，使用真正的 `IconButton`、Tooltip 和无障碍标签；已加星时星标按钮保持按下样式。鼠标点击保留的 DOM 焦点不会锁住工具栏，移开鼠标后仍淡出；键盘操作时继续保持可见。已加星的邮件在所有模式下都在主题旁常显一颗小的琥珀色星标（“已加星标”标签）。删除使用 destructive 色，并沿用已有撤销或确认流程。
- 工具栏**不加面板边框、阴影或圆角**，但不能让下面的文字透出来：它带有与行当前背景完全相同的不透明底色（行背景是半透明的悬停 / 聚焦 / 右键菜单 / 已打开状态，由每行的 `--row-backing` 变量按状态换算成不透明等价色：岛背景、列表面板的 `bg-muted/40` 底色（`--mail-list-tint`，改面板底色时同步）、再叠行自身的半透明底；已打开和多选选中的行本身不透明，直接使用其底色。浅色和深色主题一致），左侧再加约 16px 由透明渐变到该底色的过渡，让第一行文字的尾部自然淡出，没有可见接缝。动作只用约 150ms 的透明度过渡，不发生位移，并遵循减少动态效果偏好，不改变虚拟列表行高。
- **防误触：** 工具栏开始出现后约 200ms 内，按钮忽略鼠标点击（点击落到邮件行，照常打开邮件），避免鼠标刚进入行就点击时误中正在淡入的按钮；键盘操作不受影响。按钮之间的空隙不是按钮，点击同样打开邮件。
- 允许使用边框的只有表单控件（输入框、选择器、按钮的 outline 变体）、焦点环，以及附件等独立小元素的轮廓。判断标准：它是控件或独立对象的外形，而不是在分隔区域。多选时选中邮件的蓝色描边是状态标记，不是分隔，属于例外（见下文“多选”）。

邮件行只有发件人首行为右上角的时间预留宽度（约 4rem），所有预览设置相同；主题和正文预览使用全部可用宽度。工具栏覆盖在时间位置，垂直对齐首行中心，底部不侵入主题行；显示与隐藏时不改变文字布局。

在跨多个账号的视图里，发件人后默认以弱化的小字显示所属邮箱名称（`发件人 | 邮箱名`）。外观设置“所属邮箱显示为”（`appearance.mailboxLabel`，`name` 默认 / `icon`）选择“图标”时，不再显示这段文字，而是在发件人头像右下角叠一个约 14px 的账号徽标（复用侧栏的 `AccountAvatar`，带账号颜色与服务商图标），外圈用行背景色的细环与头像分开；徽标有悬停提示（账号名称与邮箱地址）和无障碍标签，只在邮件行带有账号时（即上述多账号视图）出现，不占用文字宽度，因此不会被工具栏遮住。

状态点点击区与头像之间保持 4px 间距，头像与文字之间保持 12px。列表和阅读区工具栏复用 `ReadStatusButton`：已读显示空环，未读显示环加蓝点；阅读区常显环，列表只在悬停或聚焦时显环，两处保留同样的 Tooltip、状态标签和点击尺寸。

## 多选（已实现，实机未验证）

- **入口。** 邮件列表标题行在“全部 / 未读”左侧有文字按钮“选择”（草稿与发件箱列表没有）。未进入多选时，`Cmd/Ctrl` 或 `Shift` 点击某行也会进入多选，但只选中被点的那一行，正在阅读的邮件不会自动算进去。
- **标题行。** 多选时标题行原地变为操作栏，高度不变：左侧“全选 / 取消全选”和“点选邮件 / 已选 N 封”，右侧已读、星标、归档（已归档视图为“移回收件箱”）、删除图标按钮和“完成”。筛选切换在多选期间不可用；未选任何邮件时按钮置灰而不隐藏。“全选”选中当前列表条件下的全部邮件（含尚未滚动到的），一次最多 500 封，超出时标题下方显示淡色小字“一次最多处理 500 封”。
- **点击。** 多选中单击或 `Cmd/Ctrl` 点击切换该行，`Shift` 点击从上一次点击的行连选，`Cmd/Ctrl+A` 全选，空格切换焦点行，`Esc` 或“完成”退出。切换邮箱、文件夹、搜索或筛选时退出并清空；被同步或删除移走的邮件自动从选择中去掉。
- **样式。** 选中行为 1.5px 内描边加约 8% 的淡底，颜色都取 `--mail-selection-accent`；右上角一个约 22px 的直角三角（随行圆角裁切），内含背景色的勾，不压住时间。未选中行悬停时显示约 40% 透明度的描边，无三角。多选期间不显示“当前打开”的选中底色，隐藏行内快捷操作。过渡约 150ms，遵循减少动态效果。读屏按复选框朗读，选中不只靠颜色表达。
- **阅读区。** 多选时阅读区显示“已选择 N 封邮件”和按账号的淡色计数，不放操作按钮；退出后若原先打开的邮件仍在则恢复显示。
- **操作。** 已读 / 星标按钮：所选中有未读（未加星）时为“标为已读”（“加星标”），否则为反向操作，不提供撤销。归档、删除跳过不适用的邮件（非收件箱、本机已发送副本等）；删除中有需要永久删除的邮件时确认一次并写明数量。每次操作只出一条提示，删除与归档带“撤销”；部分失败时写明成功与失败的数量，失败的邮件保持选中，成功的移出选择；操作后保持多选状态。接口见[批量处理](../contracts/app-api.md#批量处理主窗口)。

## 打开的邮件独立于列表

阅读区里的邮件是**独立的状态**，不是“列表里恰好能找到的那一封”。它只记邮件 id、所属账号和打开时该账号的服务器来源，其余内容（包括已读、星标、待同步标记）都从邮件自身读取，不依赖列表里有没有它：

- 切换邮箱 / 文件夹、切换“全部 / 未读”、搜索、列表刷新、同步，以及它被标为已读而从“未读”列表里消失，都**不会**关闭它；列表只在恰好列出它时高亮。
- 只有三件事会改变它：用户点另一封邮件；用户主动关闭（工具栏最右侧的关闭按钮，或 `Esc`）；它必须消失——邮件已被删除或对用户不可见（读取返回 `notFound`），或其账号的服务器来源已被替换（这时继续显示会把旧服务器的邮件放在新账号旁边）。
- 没有打开邮件时，阅读区不显示工具栏，只显示“未选择邮件”的空状态。
- `Esc` 让位于正在使用它的控件：输入框、命令面板、菜单和对话框先于邮件处理，不会顺手关掉邮件。
- 不跨重启记住打开的邮件；以后可作为设置项提供。

## 自有外壳组件，不直接用 shadcn Sidebar

`frontend/src/features/shell/` 是应用外壳，shadcn 的 `components/ui/` 只作为底层原语（按钮、输入框、对话框等），便于同步上游。外壳级组件由我们自己维护，后续往里加内容不需要覆盖 shadcn 的定位逻辑：

| 组件 | 职责 |
| --- | --- |
| `ShellLayout` | 画布下的布局：导航展开或收成图标栏、`Cmd/Ctrl+B`、折叠按钮、导航宽度、窄窗口处理和岛；通过 `ShellContext` 暴露 `navOpen` 与 `toggleNav` 供命令使用 |
| `NavRail` | 导航容器：在完整侧栏与图标栏（`NAV_RAIL`，48px）之间切换、宽度过渡，右侧 8px 间隙兼作拖拽条 |
| `Island` | 岛的表面 |

## 邮件侧栏的结构

状态：**第一阶段已实现，未经手测** · 2026-11-05。面向所有用户，不只是技术人员：侧栏不出现“统一”“本机”“角色”之类的词，空的条目不显示。顶部按类型跨账号查看，账号树按账号查看，两种入口并存，由用户选择；账号树默认折叠，平时只占每个账号一行。

`MailSidebar` 从上到下：

- **写邮件**。
- **顶部（无分组标题）**：每一行都是跨所有账号的视图——收件箱（未读数，计数未知时显示“—”）、星标（不显示数字）、草稿（本机草稿，显示数量）、已发送、发件箱（只在有未完成的发送时出现），以及默认收起的“更多”。“更多”里是归档（本机归档，`{ kind: 'archived', accountId: null }`，显示已归档未读数）、垃圾邮件（只显示圆点，从不计数）和已删除。“更多”的展开状态记在 `localStorage` 的 `mailx.sidebar.expanded`。
- **按账号展开**：收件箱、已发送、归档、垃圾邮件、已删除在有两个及以上账号具备对应文件夹时，行尾有箭头按钮（悬停、聚焦或已展开时显示，数字随之左移而不被遮住），展开后按账号显示顺序列出每个账号的那个文件夹，带账号头像；收件箱子行显示该文件夹未读数，垃圾邮件子行只显示圆点。默认收起，状态同样记在 `mailx.sidebar.expanded`。只有一个账号时不显示箭头，该账号的文件夹在账号树里。
- **“邮箱”分组**：每个账号一行，保留头像、同步状态与手动刷新、同步失败图标。账号默认折叠，用户展开的账号记在 `mailx.sidebar.expanded`；展开后是该账号的完整文件夹树，收件箱之后是该账号的本机“已归档”，有子文件夹的文件夹默认展开，用户收起的记在 `mailx.sidebar.collapsed`。收件箱、已发送、垃圾邮件、已删除用统一名称和图标；服务器上的草稿和归档文件夹用服务器上的原名和普通文件夹图标，不加“（服务器）”等后缀，所以不会与顶部的本机“草稿”“归档”重名。账号行的未读数是该账号全部文件夹之和（垃圾邮件不计入）。尚未取得文件夹列表的账号直接显示“正在同步文件夹…”或“暂无文件夹”，不是折叠按钮。
- **选中项保持可见**：选中项来自命令面板、通知或账号移除后的回退时，侧栏只为它展开必需的部分（视图在“更多”里就展开“更多”；文件夹没在已展开的顶部行下列出时展开它的账号）。这种展开只在本次会话有效，不写入 `mailx.sidebar.expanded`；用户收起后不再自动展开，直到选中项变化。

“星标”视图查询 `{ starred: true, archive: 'include', excludeFolderRoles: ['junk', 'trash'] }`，可用“全部 / 未读”筛选和搜索。命令面板“跳转”分组按相同顺序列出这些顶部视图，再列出各账号文件夹。

下一阶段（未实现）：收藏与隐藏文件夹，入口为右键菜单（使用 shadcn `context-menu`，需保证 Shift+F10 / 菜单键可用），收藏可拖动排序，隐藏的文件夹统一收在账号区末尾以便恢复；星标计数需核心提供计数后再加。

## 列表与阅读区的分隔

列表与阅读区之间的拖拽条可以拖动，列表宽度保存在核心 `settings.json` 的 `layout.listWidth`（300–2000px，默认 420px），下次启动恢复。只保存用户亲手拖动的结果：窗口缩放引起的比例变化不写盘；阅读区折叠期间列表占满岛，也不会把那个宽度存下来。

**拖动类的布局变化都抖动写入**（侧栏宽度、列表宽度、阅读区折叠）：统一经 `useDebouncedLayoutSave`（基于 TanStack Pacer 的 `useDebouncedCallback`），停止变化 500ms 后才写一次，所以一次拖动、连按方向键或连续几次拖动都只写一次磁盘，拖动过程中不会有任何写入。等待期间的多项变化合并成一次提交，侧栏和列表各自的值不会互相丢失。窗口关闭（`pagehide`）或组件卸载时立刻写出尚未写入的内容。以后新增的这类高频布局值也应走这个入口，不要直接调用 `updateSettings`。窗口比保存的宽度所需更窄时，列表和阅读区按比例一起缩小，各自不低于最小宽度（列表 300px、阅读区 360px）；保存的宽度只在启动时用一次，所以设置读到之前先不渲染面板组，避免先按默认宽度排版再跳变。

标题栏右上角的折叠按钮把阅读区收起，列表占满整个岛；再点一次展开，图标显示点击后会发生的事。折叠时阅读区是 `inert`（Tab 和读屏都不可达），Esc 不会去关一封看不见的邮件，拖拽条隐藏。**打开任何一封邮件都会自动展开**：点列表里的邮件、命令面板里选一封、点系统通知，都走同一个 `openEmail`。折叠状态会持久化（`layout.readerCollapsed`），下次启动恢复；打开邮件使它展开，这个变化同样会保存。拖动拖拽条把阅读区压到最小宽度以下也会折叠它，状态由 `onResize` 同步回按钮。

导航宽度可拖动，范围 220–420px，默认 256px；双击拖拽条恢复默认，聚焦后可用方向键、Home、End 调整。宽度保存在核心 `settings.json` 的 `layout.navWidth`，拖动或按键结束后才保存，约定见[应用 API](../contracts/app-api.md)。拖动期间岛临时 `pointer-events-none`，避免鼠标进入正文 iframe 后丢失事件。

**导航只有两种状态：完整侧栏和图标栏，不存在完全隐藏。** 标题栏按钮、`Cmd/Ctrl+B` 和命令面板在同一位置切换，选择保存在 `layout.navCollapsed`，重启后保持。收起后的图标栏宽 48px，只显示图标，悬停和聚焦时用 Tooltip 显示名称（含未读数，如“收件箱 · 24 封未读”）：写邮件、收件箱（未读数角标，超过 99 显示 99+）、星标、草稿（数量）、已发送、发件箱（仅在有待发邮件时）、更多，然后是每个账号的头像，最后是账号和设置。

- **更多与账号改用菜单**：图标栏只有一列，所以“更多”和账号头像点击后弹出菜单（shadcn `dropdown-menu`），其中列出与完整侧栏相同的条目：归档 / 垃圾邮件 / 已删除，以及该账号的完整文件夹树（按层级缩进，含该账号的本机“已归档”，显示未读数；垃圾邮件只显示圆点）。菜单项的选中态与完整侧栏一致，打开菜单不会切换邮箱。
- **账号角的圆点与当前账号指示**：有未读邮件时为强调色圆点，同步失败时为红色圆点；当前打开的文件夹属于某个账号时，仅以该账号按钮的淡底色表示选中，移除头像选中圆环。未读 / 异常圆点与键盘焦点环保留。账号头像区独立滚动，写邮件和底部的账号 / 设置固定不动。
- **拖到很窄就收起**：把侧栏拖到宽度小于 `NAV_SNAP`（图标栏与最小宽度之间）时切换成图标栏，拖动图标栏的右边缘向右则恢复完整侧栏；图标栏状态下键盘 `→` / Home / End 展开，完整侧栏在最小宽度再按 `←` 收起。收起时保留原来的宽度，下次展开回到那个宽度。
- **窄窗口自动收成图标栏**：窗口宽度小于“侧栏最小宽度 + 列表最小宽度 + 阅读区最小宽度 + 16px”（当前 912px）时显示图标栏，即使保存的选择是完整侧栏。此时点折叠按钮可以临时展开，窗口变宽后回到保存的选择；这次临时展开不写入 `layout.navCollapsed`。

`MailSidebar` 只负责邮件相关内容，放进 `NavRail`；它里面的菜单项暂时仍用 shadcn 的 `SidebarMenu*` 原语，设置对话框也仍使用 shadcn `Sidebar`，等有定制需求再替换。新增业务板块应往导航里放内容，而不是改容器。

### 同步状态反馈

日常自动同步保持安静：侧栏账号行不显示旋转或呼吸动画，未读数持续显示，不被同步状态替换。标题栏侧栏折叠按钮右侧提供全部邮箱刷新按钮，账号行保留单账号刷新入口；用户主动刷新时，只在使用的刷新按钮上显示进行中反馈，其他账号行保持稳定。

账号行右端只有一个插槽，未读数、刷新按钮和手动刷新的旋转图标轮流占用：平时显示未读数，悬停或聚焦该行时换成刷新按钮，手动刷新进行中保持旋转的按钮直到结束。账号名称只为这一个插槽让出空间，不为隐藏的按钮额外预留。

新接入账号首次获取可浏览内容时，使用弱化的静态文字提示；已有缓存的账号正常启动时不重复显示首次获取提示。同步异常继续保留静态提示和处理入口，避免静默运行掩盖需要用户处理的问题。

### 账号与设置入口

导航底部有两个相邻入口：**账号**（`@` 图标）和**设置**（齿轮），各开一个独立弹窗。账号决定数据来源、网络路由和凭证，是核心资产，不放进应用偏好；同步失败时账号入口显示警示标记；打开时若有账号出问题，直接选中第一个（按显示顺序，停止的优先于重试中的），显式指定的账号（如刚添加的账号、从提示进入）优先。

账号按修改频率拆成两部分：**资料**（名称、标识颜色、发件人名称、是否使用服务商图标，常改、无风险）和**连接**（地址、服务器、凭证、网络路由，配好后很少改，改了会重新连接）。两部分各有一个可复用组件：`ProfileFields` 和 `ConnectionForm`。添加和修改连接中的 IMAP / SMTP 登录用户名都可留空，说明文字提示默认使用邮箱地址，占位符跟随本次邮箱输入；两个字段独立在提交时解析默认值，保存实际用户名，重新编辑时显示已保存值。

- **账号管理弹窗**（`AccountsDialog`）：左侧账号列表，列表标题右侧为使用强调色的“加号 + 添加账号”文字按钮，不附加重复的 tooltip，避免弹窗默认聚焦时自动出现提示；窄窗口列表转为顶部横排时仍保留此入口。列表每项在名称下用弱化文字显示邮箱地址；有问题的账号右侧带一个与侧栏“账号”入口相同的小感叹号“!”并有无障碍名称：同步已停止、凭证需要确认或需要重新登录为红色，会自动重试为琥珀色。列表需要同步状态，所以 `AccountsDialog` 接收 `syncStates`。右侧为所选账号：顶部是概览（头像随正在编辑的颜色与图标即时变化、名称、弱化的邮箱地址、服务商标签）和一行同步状态——正常时是弱化的“最近同步”，会自动重试时是琥珀色提示加原因，同步已停止、凭证需要重新确认或必须重新登录时是红点和一句话（处理按钮只在底部操作栏，不在概览里重复；服务商认证或策略类停止时在下方附帮助），它们取代了原先的大块警示。资料直接编辑并自动保存（名称在失焦或回车时、颜色在点选或取色器关闭时、图标偏好在切换时），所以这里没有“保存”按钮和未保存确认。连接分组只有一行“连接方式”（如“IMAP/SMTP”或“Outlook · 浏览器登录”），服务器、凭证和网络路由收进默认折叠的“连接详情”（紧凑行：弱化标签在左、值在右，不记忆展开状态）；凭证需要确认或缺少密码时，在连接方式一行用红色短语标出，不藏在折叠里。操作固定在页面底部的操作栏：左侧是高风险的浅红色“移除账号”，右侧是“验证收发连接”（检查中旁边有“取消验证”）和“修改连接”（浏览器登录账号为“重新登录”）。状态用页面呈现，事件用 toast：资料保存失败、账号顺序保存失败和重新登录的等待、成功、失败都是 toast；加载失败且没有内容可显示时才在页面里保留带“重试”的提示；字段级错误仍显示在字段上。内容宽度有上限，所以用固定尺寸的弹窗而不是铺满主岛，避免大窗口下留白。
- **修改连接弹窗**（`ConnectionDialog`）：叠在管理弹窗之上，内容是 `ConnectionForm`；保存后立即重新连接，离开前确认未保存的修改。
- **添加账号弹窗**（`AddAccountDialog`）：独立的三步引导，高度固定：选择服务商 → 连接（`ConnectionForm`）→ 命名（`ProfileFields`，名称默认取邮箱地址，手动 IMAP/SMTP 默认选一个其他账号没用的颜色，其他服务商入口默认“不标识”）。每步底部有“上一步”和“下一步 / 完成”；点服务商行只是选中，点“下一步”才前进（双击行可直接前进）。步骤切换按方向左右滑入，系统要求减少动态效果时不播放。返回时保留搜索词和已选服务商，重新打开向导则重置；从第 3 步返回第 2 步会保留已填内容和密码；服务器拒绝连接参数时退回第 2 步并标出字段。服务商使用无边框的单列列表，每行从左到右显示 Logo、名称、短描述与选中标记，以淡底色区分悬停和选择。搜索框固定在上方，底部操作固定，中间列表独立滚动；搜索本地匹配名称、域名、描述与别名，忽略大小写和首尾空白，多词需全部匹配。过滤隐藏当前选项时清除选择，“下一步”恢复禁用；无结果显示提示。使用原生单选框支持 Tab、方向键与空格选择。当前列表前两项为带官方本地图标的“Gmail”和“iCloud 邮箱”，随后是“QQ 邮箱”（覆盖 QQ / Foxmail）、“网易 163 邮箱”、“网易 126 邮箱”、“网易 yeah.net 邮箱”和“139 邮箱”；末项为“IMAP/SMTP”（手动配置其他邮箱）。Gmail 使用应用专用密码；Outlook 与 Microsoft 365 / Exchange 通过浏览器登录，见下一段。完成后回到管理弹窗并选中新账号。

  浏览器登录的服务商（`MailProvider.signIn` 有值）在 `providers.ts` 里排在 Gmail、iCloud 之后：“Outlook”（个人）与“Microsoft 365 / Exchange”（工作或学校），分别使用 Microsoft Outlook 产品图标与 Microsoft 标识（来源、许可与选用理由见服务商图标维护规范）。名称列允许折成两行，避免“Microsoft 365 / Exchange”被截断。列表下方显示一段简短帮助：Outlook.com 需先开启 IMAP；工作或学校账号可能需要管理员批准或允许 IMAP / SMTP；公司自建 Exchange 服务器请用手动 IMAP/SMTP。这类服务商**先登录，再得到邮箱地址**：第 2 步（`SignInStep`）没有地址、服务器、密码和“测试登录”，只有一段说明、“高级设置”里的网络路由（登录使用同一路由，代理失败不回退直连）和主按钮“在浏览器中登录”。点击后显示“请在浏览器中完成登录”和“取消”；取消不报错，关闭弹窗同样放弃等待中的登录。浏览器返回后有两种结果：邮件服务器已打开登录名对应的邮箱，直接进入第 3 步，账号名称默认取该地址；或者服务器没能打开它（例如登录名只是别名），第 2 步改为显示“MailX 没能用这个微软账号的登录名打开邮箱。请填写这个账号的邮箱地址。”和预填了被拒地址（若有）的地址输入框，“下一步”只用已有的登录再求证一次，不再打开浏览器，被拒时在输入框下用通俗文字提示，最多五次，用完或会话超时后回到“在浏览器中登录”并说明原因。入错入口、没有允许访问或代理问题的错误显示在第 2 步，方便再点一次。第 3 步命名不变，“上一步”或关闭弹窗会丢弃已登录的会话；已登录的会话最多保留十五分钟，超时时点“完成”会回到第 2 步并说明。账号详情里 OAuth 账号没有密码字段，也没有“修改连接”。“重新登录”始终在底部操作栏右侧：平时是普通按钮，必须重新登录才能继续同步时变为主按钮，并在顶部概览的状态行说明原因（与密码账号“同步已停止”的位置一致）；等待、成功和失败提示是 toast，等待时按钮换成“取消”。

账号管理列表的每个账号左侧提供独立拖动手柄，使用 `@dnd-kit/react` 的 sortable 与指针、键盘传感器；手柄和账号选择按钮并列，点击账号仍只切换详情。宽窗口上下排序，窄窗口的顶部横排左右排序，支持滚动。聚焦手柄后按空格或回车拿起，方向键移动，再按空格或回车放下，Esc 仅取消本次拖动；说明和位置播报均随界面语言切换。拖动不会切换当前编辑账号。放下且顺序改变时保存一次，取消或原位放下不保存；保存失败回退到已提交顺序并显示错误。此离散操作直接使用布局字段更新，不走宽度变化的 500ms 抖动写入。

显示顺序保存在本机 `settings.json` 的 `layout.accountOrder`，由账号管理、邮件侧栏、命令面板、写信发件账号下拉框和相关设置中的账号列表共用，其他窗口经设置事件跟随。未记录的新账号接在末尾，不存在或已删除的 id 在显示时忽略，空偏好沿用原始账号顺序。该偏好只调整显示顺序，不改变草稿已有发件账号、显式默认发件账号或核心在缺省时选择账号的顺序。

添加时，用户未手选颜色的默认值随添加方式变化；手选颜色或“不标识”（包括再次点击当前选项）后，返回步骤、更换添加方式和保存失败重试均保留选择，重新打开向导则重置。关闭服务商图标不会自动补色；已有账号的颜色保持原值。

添加向导的连接步骤提供“测试登录”，QQ、网易和手动配置均可使用。它验证当前填写的收发连接并分别显示结果，不保存账号、不发送邮件；可以跳过测试或在部分协议失败后继续。测试时可取消，修改任意连接字段、下一步、返回、关闭及卸载都取消旧尝试并移除过期结果；测试完成保留输入，方便修正和继续保存。按钮、说明和结果位于可滚动表单内，底部“上一步 / 下一步”保持可达。

“验证收发连接”按钮在底部操作栏，分别检查已保存版本的 IMAP / SMTP 登录，可取消；状态由 `useConnectionVerification` 持有，按钮和结果共用，配置变化、切换账号或关闭弹窗使旧结果和在途请求失效。“验证已保存的连接和登录，不发送邮件。”是连接方式一行的弱化说明。结果在连接方式一行末尾追加短状态：均通过时为弱化的“收发均已通过”（说明改为“登录验证通过，尚未测试实际投递。”），否则为红色的“收信未通过”“发信未通过”或“收发均未通过”；有未通过项时“连接详情”自动展开，在失败的服务器行下用 `text-xs` 红字左对齐写出原因，通过的服务器显示弱化的“已通过”，服务商认证帮助留在详情下方。整个请求失败（网络、IPC、配置已改变）显示为连接分组里的红色小字，而不是 toast。添加向导的“测试登录”使用同样的行样式（标签在左、短状态、原因在标签下）。不发送邮件，不将认证通过表述为真实投递成功。QQ 与网易认证失败时显示各自的协议开通、授权码和安全验证排查指引，帮助按钮只打开所属服务商的固定官方文档。安全策略拒绝使用独立的 `providerPolicy` 原因，在同步状态、连接诊断与正文失败中提示；处理后可手动同步或重试正文，不要求用户必须修改连接。正文帮助取自保存账号的 `providerId`，未知服务商只显示通用提示。

底部操作栏左侧提供浅红色“移除账号”按钮，窄窗口下右侧操作可换行。确认框显示账号名、邮箱地址及当时的草稿/待发数量，明确所有本地草稿和发件记录将被清理、相关写信窗口与未保存内容将关闭、服务端邮件保留；始终说明已提交或结果不确定的邮件可能已送达，移除不撤回。默认焦点为取消；提交中禁止切换/新增/修改账号及重复移除，错误留在确认框重试。成功选择相邻账号，最后一个账号移除后显示现有添加入口。自动保存跨移除请求等待结果，成功后丢弃在途回调与卸载写入；失败时恢复保存。`sending` 由后端原子拒绝，不能依赖前端按钮互斥。

服务商（QQ 邮箱、网易 163 / 126 / yeah.net、通用 IMAP/SMTP 等）在 `features/accounts/providers.ts` 集中登记：默认图标、可选本地 Logo、名称、邮箱后缀、短描述和搜索别名，以账号的 `providerId` 关联（`null` 即手动配置的 IMAP/SMTP，不认识的 ID 也会显示原值）。添加向导的列表、管理弹窗账号概览和修改连接弹窗标题栏的 `ProviderBadge` 都读这份登记；新增服务商只需加一项并提供它的连接步骤。

服务商标识使用随应用打包的官方素材：QQ 使用邮箱专属 PNG，163、126、yeah.net 使用各自的完整标识，139 使用官方应用图标，Gmail 与 Microsoft Outlook 使用官方 SVG 产品图标，“Microsoft 365 / Exchange”入口使用 Microsoft 标识 SVG；保留原图的字形、配色和比例，不再裁掉标识文字或描摹成路径。选材、允许的提取或格式转换、通用图标回退与验收规则统一见[服务商图标维护规范](../../frontend/src/assets/providers/README.md)。侧边栏的账号行、管理列表与资料预览、通知设置均用 `AccountAvatar` 显示账号：具体服务商有本地 Logo 时，默认以 Logo 替换首字母，头像容器保持透明、素材自带底色原样保留，账号颜色仅作为 1 px 细圆环，图标与圆环之间保留 2 px 内边距。标识颜色提供叉号选项，悬停提示和无障碍名称为“不标识”；选择后保存空颜色，清除服务商图标的圆环及内边距，图标恢复完整大小。添加最后一步和账号资料里可单独切换“使用服务商图标”，设置按账号持久化，旧账号默认开启；关闭、手动配置或未知服务商回退首字母和彩色底，没有颜色时用中性底色。没有可用服务商 Logo 的账号不显示这个开关。图标切换只更新资料，不改变连接版本、凭证或同步。标识颜色在预设和“不标识”之后有一个彩虹色的“自定义颜色”色块，点击用系统取色器（与外观设置的自定义强调色共用 `CustomColorSwatch`）选任意 `#rrggbb`；拖动时只预览，取色器关闭时才保存，不是预设的颜色显示为选中。头像上的字母按颜色亮度选黑色或白色（预设保持白色），浅色也能看清。颜色只用于区分，不承载状态。

## 邮件列表右键菜单（已实现，三平台实机未验证，仅自动测试）

整个邮件列表只挂一个右键菜单（shadcn `context-menu`，基于 Base UI），外观与其他下拉菜单一致，不显示快捷键提示。右键时按事件目标所在的行（`[data-index]`）确定是哪封邮件，并在打开时保存这封邮件的快照；在行内的快捷按钮上右键同样以整行为目标，列表空白处右键不弹出菜单。

- **条目分组**：打开｜回复、全部回复、转发｜标为已读或未读、加星标或取消星标｜归档或移回收件箱｜删除（危险样式）。只显示传入了对应回调的条目，空分组连同分隔线一起去掉。归档的显示规则与行内快捷操作相同（收件箱邮件、且当前文件夹可在本机归档）。本机已发送副本没有服务器邮件，不显示已读、星标、归档和删除，只在最后提供“从本机移除”，仍走原有的确认对话框。
- **不改变选择**：右键既不打开邮件也不改变选中项，只有选择“打开”才会打开。菜单打开期间目标行保持悬停同款的淡底（`bg-foreground/5`），并在虚拟列表中固定挂载，滚出视口也不会卸载。列表显示上一个邮箱的旧行（加载中）时菜单禁用；多选期间也禁用，批量操作统一由标题行的操作栏完成，避免单封菜单与所选范围混淆。
- **键盘打开**：Shift+F10 或菜单键发出的 `contextmenu` 坐标可能落在行外（常见为 (0, 0)）。这类事件会被取消，并在行左侧 16px、垂直居中的位置重新派发一次，使菜单贴着该行弹出；鼠标右键必然落在行内，不受影响。关闭菜单后焦点回到打开前的位置（键盘打开时即该行）；打开前没有焦点时不把焦点移进列表。
- **原生菜单仍屏蔽**：`lib/browser-defaults.ts` 在捕获阶段对页面的 `contextmenu` 调用 `preventDefault` 的做法保持不变，Base UI 的触发逻辑不检查 `defaultPrevented`，两者可以共存，自动测试覆盖了这一点。

## 邮件翻译（已实现，实机未验证，仅自动测试）

设计与数据边界见[邮件翻译](translation.md)，接口见[应用 API](../contracts/app-api.md#邮件翻译主窗口)。代码在 `frontend/src/features/mail/translation/` 与 `features/settings/translation-pane.tsx`；下文界面文字取自 `locales/zh-CN` 与 `locales/en`（括号内为英文）。翻译只作用于阅读区里已打开的邮件正文，不改变隔离 iframe 与 IPC 权限边界。

- **何时出现。** 只有已下载、有正文文档（`body.hasHtml`）且不是本机已发送副本的邮件才有翻译控件；纯文本邮件由核心转成 HTML 文档，同样有控件，未下载或正文为空的邮件没有。
- **工具栏控件。** 在已读 / 星标那一组之后，是一个翻译按钮（“翻译”/ Translate）加旁边一个小的选项按钮（“翻译选项”/ Translation options）。点按钮：没有译文时开始翻译，有译文时在译文和原文之间切换，悬停提示为“显示原文”/“显示译文”（Show original / Show translation）；翻译中按钮显示转圈。选项菜单依次为：
  - “翻译成”（Translate to）子菜单，列出 26 种目标语言，各用其本语言名称书写（单选，选中即按该语言翻译）；
  - 检测到邮件语言时：可勾选的“总是翻译{{language}}”（Always translate …）与“不再提示{{language}}”（Don't suggest translating …），两者互斥，勾选其一会取消另一项；
  - 已有译文时：“重新翻译”（Translate again），先清除该邮件的缓存译文再重新翻译，翻译中不可用；
  - “翻译设置…”（Translation settings…），打开设置的“翻译”页。
- **没有设置服务。** 默认服务是免设置的 Microsoft 翻译，开箱即用：翻译按钮、提示行和命令面板条目无需任何设置就能工作，不会出现这个气泡。只有用户把翻译关掉（“不使用翻译”），或选了需要密钥却还没保存密钥的服务时，点翻译按钮或选择语言不会失败，而是在按钮旁弹出一个小气泡：“还没有设置翻译服务”（No translation service is set up yet）加按钮“去设置”（Open settings）。命令面板的翻译命令在这种情况下直接打开设置的“翻译”页。
- **命令面板。** 有可翻译的邮件时出现一项命令，标题随状态变化：“翻译这封邮件”（Translate this message）、已有译文时为“显示译文”（Show translation）、正在看译文时为“显示原文”（Show original）。
- **两个文档同时保留，主题一并翻译。** 原文和译文是两个独立的隔离文档，各用自己的文档令牌；切换只是显示哪一个，因此切换即时，各自保留滚动位置。主题标题显示译文，悬停显示原文。译文文档在缓存失效或被清除后不可用时，协议返回 404，不会退回提供原文，界面回到原文并在提示行显示错误。
- **本次运行内的记忆。** 应用按邮件记住用户当前是在看译文还是原文，以及是否关闭了提示；只在本次应用运行内有效，不保存到磁盘，最多记 200 封。离开仍在翻译的邮件会取消这次翻译。
- **提示行。** 正文上方一行单行提示，高度固定，状态变化时内容不跳动，不用卡片边框。只有已选服务并保存了密钥后才会出现。同一行承载全部状态，不弹出独立面板：
  - 建议：“这封邮件是{{language}}”（This message is in …）、按钮“翻译成{{target}}”（Translate to …，已有缓存译文时改为“显示译文”）、一个“更多”菜单（内容同选项菜单里的“总是翻译 / 不再提示”两项）和关闭按钮“关闭翻译提示”（Dismiss translation notice，只对本封邮件有效）；只在检测可靠且语言与目标不同、提示开关开启、语言不在“不再提示”列表时出现；
  - 翻译中：转圈、“正在翻译…”（Translating…）和“取消”；原文保持可读；
  - 显示译文：“已从{{language}}翻译”（Translated from …；不知源语言时为“已翻译”/ Translated）加服务名；只翻译了一部分时再加“邮件较长，只翻译了前面的部分”（This message is long, so only the first part was translated）；按钮“显示原文”；
  - 显示原文（看过译文之后切回原文）：“正在显示原文”（Showing the original）与按钮“显示译文”；
  - 失败：按错误代码给出的文案（见 `errors.json`）和“重试”，关闭按钮可收起错误；错误为 `translationNotConfigured` 时，按钮改为“去设置”；所选服务是免设置通道、且错误是 `translationUnavailable`、`translationRateLimited`、`translationNetwork` 或 `translationTimeout` 时，“重试”旁再加一个安静的次要按钮“换一种翻译服务”（Use another service），打开设置的“翻译”页（自带密钥的服务不显示它，因为那里换服务不是出路）；
  - 命中“总是翻译”的语言打开时自动开始翻译，直接显示为翻译中（用户本次已切回原文的邮件不再自动翻译）。
- **同意对话框。** 第一次使用某个翻译服务，或更换服务后，翻译前弹出一次对话框：标题“把邮件内容发送给{{service}}？”（Send this message to {{service}}?），正文只有一句：“邮件的主题和正文会发送给{{service}}，附件和图片不会发送。”（The subject and text of this message are sent to {{service}}. Attachments and images are not.），免设置服务与自带密钥的服务用同一文案。按钮“取消”与“翻译”（Translate）。提示保持简短：同一服务只问一次、更换服务会再问，这些由行为体现，不写进对话框。默认焦点在“取消”上。同意保存后继续翻译；取消则不翻译、不外发。同意由 core 再次强制，界面不是唯一防线。
- **设置里的“翻译”页。** 设置弹窗“邮件”组中，位于“安全性”之后，页面标题“翻译”（Translation）。按以下五组排列，使用设置页通用的分组与行样式；最后一组“高级”默认折叠：
  - **翻译服务**（Translation service）：“服务”是分组下拉（`SelectGroup` / `SelectLabel`）：**免设置**（No setup needed）下是“Microsoft 翻译”/ Microsoft Translate（默认）和“Google 翻译”/ Google Translate，**使用自己的密钥**（Use your own key）下是 DeepL、Microsoft Translator、Google Cloud Translation，最后是“不使用翻译”（Don't translate）；选免设置服务时，行说明只有一句“无需注册或密钥，直接可用。”（No sign-up or key needed.），Google 为“无需注册或密钥。在中国大陆通常需要代理。”；它并非官方开放的服务、可能失效这一点不在设置页反复提示，失败时提示行提供“换一种翻译服务”，并且**没有**密钥、区域和密钥测试行，只保留“测试”行（无需密钥即可测试）。选需要密钥的服务时：“密钥”：粘贴后“保存”，保存后显示“已保存”，可“更换”或“移除”，不再显示密钥内容；选 Microsoft 时多一行可选的“区域”；“测试”行的“测试”按钮翻译一句示例并显示“可以使用：…”或原因；
  - **翻译**（Translating）：“翻译成”（目标语言：“跟随界面语言”或 26 种语言之一）；“翻译引用的历史邮件”开关（默认关闭）；
  - **外语邮件**（Foreign-language mail）：“提示翻译”开关（默认开启）、“不提示的语言”列表、“总是翻译的语言”列表（说明为“打开这些语言的邮件时自动翻译。”），均可添加和逐项移除；
  - **已保存的译文**（Saved translations）：显示“{{count}} 封邮件，约 {{size}}”或“没有已保存的译文”，以及“清除”按钮；没有单封邮件的清除入口；
  - **高级**（Advanced）：折叠组，每次打开页面都是折叠的，不记忆展开状态。组标题与其他分组标题同字号、同顶线，是一个真正的按钮（`aria-expanded`、键盘可操作、有焦点环），右侧的小箭头在展开时转向下；折叠时标题旁用弱化文字显示当前连接：“直接连接”或“通过代理 {{host}}:{{port}}”（Through proxy {{host}}:{{port}}），已设置代理的人不用展开就能看到。展开后依次是：“连接方式”（Connection：“直接连接”或“通过代理”，说明为“只用于翻译，不影响邮箱账号。”；代理连不上时不会改为直连，这一规则不在界面里重复说明）；选“通过代理”时再有“代理类型”“代理地址”“端口”，然后是“用户名”（可选，离开输入框时与路由一起保存，清空即不再登录，说明为“代理需要登录时才填写。”）和“密码”（交互同“密钥”：保存后显示“已保存”，可“更换”或“移除”，保存后不再显示，也不留在页面里）。没有填写用户名时“密码”行不可用，并提示“先填写用户名，密码才会被使用。”。
  文案使用“密钥”“翻译服务”“代理”“用户名”“密码”等平实用语，不用“认证”“凭证”。

## 标题栏

标题栏替代系统标题栏，空白处拖动窗口，双击行为遵循系统偏好，按钮、输入框等交互元素不触发拖动。页面通过 `TitleBarActions` 把内容送进三个插槽（保持各自的 React 上下文）：

| 插槽 | 位置 | 当前内容 |
| --- | --- | --- |
| `leading` | macOS 红绿灯之后（或左边缘） | 侧边栏折叠按钮，其右侧是全部邮箱刷新按钮 |
| `center` | 两侧之间，居中 | 搜索入口（命令面板的触发器） |
| `trailing` | 窗口控制按钮之前 | 明暗模式按钮，其右侧是“收起 / 展开邮件内容”按钮；开启 MCP 后，明暗模式按钮左侧增加 MCP 状态图标（更新提示按钮若出现，位于其左侧） |

约定：

- 标题栏不显示应用名称文字。
- MCP 状态图标（已实现，未经手测）：只在开关开启时显示，为服务器图标加右上角圆点角标。运行中为绿色点，启动失败为红色点；开关已开启、服务尚未回报运行（启动中）时不显示圆点，Tooltip 写“正在启动…”，避免在短暂的启动期闪出红绿色。开关关闭时整个图标不显示。悬停 Tooltip 第一行为运行状态（“MCP 服务器: 运行中”；无连接时为“运行中，暂无客户端连接”；启动失败时显示原因），有客户端连接时第二行为“已连接：Claude Code、Cursor”，重复的合并为“Claude Code ×2”，尚未自报身份的显示“未知客户端”，名称不加“自行报告”之类的限定语，也没有“打开设置”提示行；点击图标打开“设置 → MCP”（经窗口事件通知工作台打开设置弹窗），该行为由按钮角色传达。无障碍标签只含状态文字。设置页状态行为“运行中，N 个客户端已连接”，其下逐行（弱化色）列出当前已连接的客户端，合并规则同上，无连接时隐藏该列表，同样不加限定语。状态色同时配文字说明，不只靠颜色表达。
- 与具体页面无关的全局功能（如明暗切换）放在 `App.tsx`，没有账号或启动失败时也可用；与邮件有关的（如搜索）由 `Workbench` 挂入。搜索结果中正文或附件名命中的行，用带淡色底高亮的命中片段替代预览行；结果上方一行淡色小字说明已在本地索引的多少封正文中搜索（与同步范围受限的提示合并为一行，不加分割线）。（本地全文搜索已实现，尚未手测。）
- 折叠按钮不做 toggle 外观：展开时显示"收起侧边栏"图标，收起后换成"展开侧边栏"图标，标签随之变化。
- 同一插槽里的按钮用 `TitleBarActions` 的 `order` 排序，而不是按挂载先后：明暗模式按钮和邮件内容折叠按钮分属 `App` 与 `Workbench`，加载顺序不固定，折叠按钮 `order={1}` 固定在最右。
- 明暗模式按钮循环切换"跟随系统、浅色、深色"，图标显示当前模式，通过现有外观设置保存。

## 命令面板

标题栏中间的搜索入口行为类似 shadcn `Command`（基于 `cmdk`，`components/ui/command.tsx`），点击或按 `Cmd/Ctrl+K`、`Cmd/Ctrl+F` 打开，`↑↓` 选择，`Enter` 执行，`Esc` 关闭，每次打开都从空输入开始。

- 入口占位符写明搜索范围，例如"在 全部收件箱 中搜索""在 工作邮箱 · 收件箱 中搜索"。
- 输入时面板只做预览，**不实时过滤邮件列表**。第一项固定为"在 {范围} 中搜索「xx」"，`Enter` 才把关键词应用到列表；应用后入口显示该关键词并带 × 可清除。
- 分组：搜索、邮件（当前范围内最多 8 条预览，点击打开该邮件并应用搜索）、跳转（全部收件箱与各账号文件夹）、命令。未输入时命令在前，因为文件夹列表可能很长。
- 命令只列出**已经可用**的功能：现在有“写邮件”（有账号时）和翻译命令（有可翻译的邮件时，见“邮件翻译”），不出现标记已读等尚未实现的动作。新增命令时同时更新 `command-palette.tsx` 与其测试；出现第二个命令来源后再抽成注册表。
- 过滤与排序由面板自己做（`shouldFilter={false}`），保证"搜索"项始终第一；中文输入法组字期间的 `Enter` 由 `cmdk` 忽略。
- 邮件预览目前只搜当前范围，不是跨邮箱搜索；跨邮箱搜索需要核心先提供查询。

## 键盘快捷键（已实现，实机未验证，仅自动测试）

主窗口的快捷键集中定义在 `features/mail/shortcuts.ts`：每项含 id、显示用按键、分组（浏览 / 处理 / 回复）、文案 key 和是否为单键。`?` 打开的帮助浮层（`shortcut-help.tsx`）与“设置 → 快捷键”（`settings/shortcuts-pane.tsx`）都从这份列表渲染，新增或修改快捷键只改这里；带修饰键的项（`Cmd/Ctrl+N`、`Cmd/Ctrl+K`、`Cmd/Ctrl+B`、选择时的 `Cmd/Ctrl+A`）和 Esc 只列出，仍由原组件处理。

- 单键：`j` / `↓` 下一封、`k` / `↑` 上一封（像点击相邻行一样打开，按原路径标已读，列表滚到可见；没有打开的邮件时从第一行开始；聚合行跳过），`Enter` / `o` 在没有打开的邮件时打开第一行，`/` 打开搜索，`?` 打开帮助；`e` 归档或移回收件箱，`#` / `Delete` / `Backspace` 删除（沿用撤销与永久删除确认，本机副本走“从本机移除”确认），`s` 星标，`u` 已读 / 未读；`r` / `a` / `f` 回复、全部回复、转发。处理和回复只作用于阅读区里正在显示的邮件，可用条件与阅读区工具栏一致；多选时 `e`、`#`、`s`、`u` 改为作用于选中的邮件，与顶部按钮一致。用快捷键归档或删除后打开列表里的下一封，没有下一封时打开上一封。
- 守卫（`matchShortcut`）：已被处理（`defaultPrevented`）、输入法组字（`isComposing` 或 keyCode 229）、按着 Cmd / Ctrl / Alt、焦点在输入框、文本域、下拉框、可编辑区域或 textbox / combobox / searchbox / spinbutton 角色上、页面上有打开的对话框、菜单或弹出列表时都不触发；Shift 只允许用于符号键（`#`、`?`、`/`）。`Enter` 落在按钮、链接等自身会响应的控件上、方向键落在标签页、分隔条等自身使用方向键的控件上时也让给控件。只在快捷键真正执行时 `preventDefault`。按 `event.key` 匹配，跟随键盘布局。正文在隔离 iframe 中，焦点在正文里时按键不到达应用。
- 设置 `general.singleKeyShortcuts`（默认开）可关闭全部单键，供语音输入和辅助工具用户避免误触；关闭后 `?` 也不再打开帮助，设置页的列表就是参考，单键行变淡并标注已关闭。

## 第二阶段：毛玻璃（macOS 已实现，其余平台未做，实机未验证）

第一阶段刻意不做毛玻璃，只改结构。现在的做法：

- 窗口级材质只在 macOS 配置：`desktop/src/window_chrome.rs` 的 `style_builder` 让窗口透明并套用系统 `Menu` 材质（NSVisualEffectView，随窗口激活状态变化；换成 `Sidebar` 更淡，`HudWindow` 恒为深色不适用），因此需要 `macos-private-api` 特性与 `tauri.conf.json` 的 `macOSPrivateApi`（该特性不适用于 Mac App Store 分发）。Windows（Mica / Acrylic）与 Linux 没有实现，保持不透明画布。
- `window_get_chrome` 返回 `translucent`，标题栏据此给 `<html>` 加 `data-translucent`；`index.css` 在该属性下把 `.app-canvas` 的 `--sidebar` 等变量改成半透明，所以画布色仍只在这几个变量里。浏览器预览没有窗口材质，`translucent` 恒为 false。
- 系统材质跟随窗口自己的明暗，所以应用主题变化时前端调用 `window_set_theme`（`system` / `light` / `dark`），让窗口与页面一致；固定主题下同样半透明。
- 没有使用 CSS `backdrop-filter`：它只能模糊页面内部，不能替代窗口级材质。
- 岛保持不透明，以保证文字可读；描边与阴影沿用现有 token。

## 写信窗口（已实现界面，三平台实机未验证）

写信使用独立的系统窗口，不用遮挡主窗口的模态弹窗。写信窗口同样是画布加一个岛：**复用同一个 `TitleBar`**（`features/window-chrome/`，没有第二个标题栏；macOS 为原生红绿灯，Windows / Linux 按 `window_get_chrome` 自绘按钮），标题为邮件主题、空时为“新邮件”，同时写入 `document.title`（宿主未提供设置原生窗口标题的命令，所以系统任务栏标题是否随之变化待实机确认）。岛内上方为发件账号、收件人、抄送 / 密送（默认收起，草稿里已有时展开）、主题，下面是 Tiptap 富文本编辑区及无边框格式工具栏（段落样式与粗体组常驻，窄窗口先把对齐 / 引用 / 撤销重做收进“更多格式”，再收颜色组；色板支持方向键、回车与 Esc，详见[富文本设计](sending.md#14-富文本写信已实现)），底部左侧是保存状态（打开时不显示，改动后才出现“已保存”等，详见写信窗口设计），右侧是丢弃和发送按钮（发送在最右），同样不加分割线；底栏最左是添加附件的回形针图标按钮，编辑区与底栏之间是附件栏（无附件时不显示）：每行文件名、转发标记、大小与移除图标按钮，无边框，悬停淡底色，超过上限时显示错误色提示，服务器上限只作淡色提示；系统拖入文件同样添加，拖动经过时没有高亮（Windows 上网页收不到拖动状态）；收件人行与主题行只在悬停和聚焦时有淡底色，地址是行内小标签（无效地址为错误色标签）。格式工具栏在链接按钮后有插入图片的图标按钮（带 Tooltip，只读时禁用），粘贴剪贴板里的图片同样插入；正文里的图片最宽占满编辑区，不加边框和阴影，找不到对应图片时显示淡色“图片已丢失”占位，内嵌图片不进附件栏。第一次按发送时若有丢失的图片，底栏提示“有 N 张图片已丢失，将不会发出”，不阻止发送。（内嵌图片已实现并经 macOS 用户手测，Windows / Linux 未验证。）

结构：`ComposerApp`（`features/composer/composer-app.tsx`）负责画布、标题栏、窗口标题和关闭协议；`Composer`（`composer.tsx`）与宿主无关，只要 `client`、`draftId`、账号列表和 `onSent` / `onDiscarded`，将来可原样放进主窗口的岛；草稿保存在 `use-draft-editor.ts`，收件人输入在 `recipient-field.tsx` / `address-parse.ts`（与核心 `valid_address` 同一条保守规则，核心仍是权威）。浏览器开发预览：`/?composer=<uuid>&platform=windows|linux|macos`（`platform` 与旧的 `titlebar` 参数等价），由模拟客户端为这个 id 现建一份空草稿；`?seed=outbox` 额外放入草稿和失败 / 未知 / 重试中的发送项。

发送按钮分两步：第一次点击校验（至少一个收件人、地址都有效、账号与发信凭证可用）并写出未保存内容，按钮宽度与颜色在约 200ms 内过渡为“确认发送”（主题为空时为“无主题，确认发送”），第二次点击才入队；约 400ms 内的再次点击无效以防双击越过确认，约 4 秒无操作、修改内容、`Esc` 或窗口失焦时退回；`Cmd/Ctrl+Enter` 同样按两次；减少动态效果时不播放过渡但保留 400ms 防双击；`aria-live` 播报“再次按下以确认发送”。入队请求带进入待确认时已保存的 `expectedRevision` 和新的 `clientMutationId`，冲突时退回并重新加载草稿。窗口尺寸、关闭与草稿保存见[写信与发送设计](sending.md#2-写信窗口独立窗口)。

### 主窗口的写信入口、草稿与发件箱

- 导航顶部“写邮件”与其他导航项同样式（`Cmd/Ctrl+N` 同效，提示文字里写出快捷键）；阅读区工具栏的回复 / 全部回复 / 转发；命令面板的“写邮件”。阅读区根据邮件来源提供归档与删除操作；打开本机已发送副本时，这个位置换成“从本机移除”（带确认），已读与星标按钮隐藏。已发送文件夹的列表行显示“致：收件人”（多人时加总数），头像随第一个收件人；尚未在服务器上找到副本的行在时间前有淡色电脑图标，Tooltip 说明“仅在本机”。（已实现并经 macOS 用户手测，Windows / Linux 未验证。）
- 导航里“草稿”恒在（有草稿时显示数量），“发件箱”只在有排队中、发送中、失败或需要确认的项目时出现并带数量；两者选中后岛内左侧是与邮件列表同样式的行（无边框、悬停与选中态一致），草稿行在账号名旁、写信窗口在发件账号行上方，对 MCP 创建的草稿（`origin = mcp`）显示淡色小字“由 MCP 创建”、对内置 AI 创建的草稿（`origin = ai`）显示“由 AI 创建”，不加边框或徽章底色（目前尚无入口创建此类草稿）；右侧阅读区显示草稿预览（继续编辑 / 删除）或发送项的状态、错误与可用操作。发件箱清空时若正停在发件箱，回到全部收件箱。这两个视图不参与标题栏搜索，搜索入口仍指向全部收件箱。
- 草稿阅读区与正常邮件一样显示富文本正文，保留标题、粗斜体、列表、引用、对齐、颜色、高亮和本地内嵌图片。头部显示主题、发件账号、收件人 / 抄送 / 密送与修改时间；普通附件在正文外单列名称和大小，内嵌图片不重复列为附件。正文复用隔离 iframe，跟随正文主题设置，不加载远程图片；链接交给系统打开。保存后的变更会更新当前预览，顶部继续使用“继续编辑 / 删除”图标按钮，不在预览区增加编辑工具栏。
- 发送结果用全局 toast：撤销等待期内“将在 N 秒后发送”（带“撤销”按钮），随后“正在发送…”“已发送”；失败与需要确认的 toast 带“查看”，直达发件箱对应项。toast 允许带一个动作按钮（`toast.*(title, { action })`）。

仅有图标的按钮用 `components/icon-button.tsx` 的 `IconButton`：带 `aria-label`，并用项目的 Tooltip 显示名称（有快捷键时写进提示，未实现的写“（尚未实现）”），不用原生 `title`；禁用按钮没有指针事件，所以提示挂在可聚焦的外层 `span` 上。草稿预览的“继续编辑 / 删除”是图标按钮；发件箱项的操作仍是文字按钮。

## 新增界面时的检查清单

1. 内容放在岛里，导航类内容放在画布上，不要再造第三层。
2. 不加分割线或卡片边框；需要区分时先用间距、淡底色、悬停与选中态。
3. 颜色用 token，不写死色值；在浅色和深色下各看一遍。
4. 可点击的东西不要让标题栏拖动抢走事件（使用 button、input 等语义元素或 `data-window-no-drag`）。
5. 邮件正文始终留在隔离 iframe 内，不获得 IPC 权限；拖动或调整大小时要避免 iframe 吞掉指针事件。
6. 不把未实现的功能展示成可用。
