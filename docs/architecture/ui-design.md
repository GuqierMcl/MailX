# 界面设计语言：画布与浮动岛屿

状态：**Accepted；第一阶段（无毛玻璃）已有实现，桌面三平台的实际观感尚未逐一验证** · 2026-10-21。此文是前端界面的风格约定，用于指导后续开发；与实际代码冲突时以代码和测试为准，新的明确设计优先于本文，更新时同步修订。

## 界面文本与语言

首版已支持简体中文与英文，可在“设置 → 通用 → 语言”选择跟随系统或显式语言。下文的中文名称、按钮和提示为示例；实际界面、Tooltip 和读屏标签使用当前语言，包括 Windows / Linux 自绘窗口按钮。业务组件在渲染时订阅语言变化，模块级配置保存语义 key；切换不重新挂载编辑器或清空选中项。邮件原文、主题、用户命名与附件名按原数据展示，日期 / 时间、数字、文件大小和排序沿用现状。新功能应同时提供中英文资源及无障碍文本，范围和验证规则见[中英文文本适配](internationalization.md)。

从导航或命令面板打开设置窗口时，默认选中第一项“通用”；需要定位到特定设置页的入口仍通过 `SettingsTarget.section` 指定目标。

## 总体结构

整个窗口是一块**画布**，邮件内容是浮在画布上的**岛屿**：

- **画布**：标题栏与左侧导航（`NavRail`）连成同一平面，底色由根容器 `.app-canvas` 提供，两者之间没有边框，也没有各自独立的背景。
- **岛**：邮件列表与邮件阅读区合成**一个**岛（`Island`），而不是每栏一个。两者关系紧密，拆开会过碎；导航将来扩展为综合菜单入口，留在画布上更合适。
- **间距**：岛与窗口右、下边缘及与导航之间保持 8px，让画布露出；导航收成图标栏后仍保留这 8px。

岛的表面：圆角 `rounded-2xl`、`bg-background` 实色、`shadow-sm` 和半透明描边 `ring-1 ring-foreground/10`，保证正文可读性。画布与岛的色阶通过 token 取得，不写死色值：

| 用途 | 来源 |
| --- | --- |
| 画布底色与导航色 | `--sidebar`、`--sidebar-accent`、`--sidebar-border`，在 `.app-canvas` 内按明暗覆盖，设置对话框等区域不受影响 |
| 岛 | `--background`、`--foreground` |
| 强调色 | 外观设置写入的 `--primary` 等，不在组件里改 |

主岛外层不设置滚动裁切，让上沿阴影与描边自然延伸到标题栏画布；圆角内容裁切保留在 `Island` 内，列表、阅读区和启动状态页分别管理自己的滚动。

## 不用分割线

岛内和画布上**不画分割线**，区域靠留白、色调和阴影区分：

- 不使用贯穿式 1px 线：不要在岛内用 `Separator`，不要给栏与栏之间、头部与内容之间加边框。
- 列表与阅读区之间：列表区用很淡的底色（`bg-muted/40`），阅读区保持岛的原色；拖拽条平时不可见，悬停和拖动时才显示淡色高亮，点击范围仍保持约 8px。
- 工具栏里的按钮分组用间距分开，不用竖线。
- 列表中的每条邮件**不加卡片边框**：平时透明，悬停轻微变深（`hover:bg-foreground/5`），选中时提亮为 `bg-background` 并带 `shadow-xs`。
- 邮件列表使用虚拟滚动（`@tanstack/react-virtual`），只渲染可视窗口及上下少量缓冲行；选中行和当前获得焦点的行始终保留在 DOM 中，每行带 `aria-setsize` / `aria-posinset`。每行高度固定：发件人与主题均单行截断，预览区按 `previewLines` 预留 1 / 2 / 3rem（`none` 不预留），高度随根字号缩放。预览区有三种显示：等待预览（`previewState` 为 missing 且未放弃）时第一行以弱化色显示“（加载中）”，其余留空；预览就绪（或正文已下载）时显示预览文本，文本为空则留空；预览失败，或本次尝试没有结果而暂时放弃（60 秒内不再请求）时留空。三种状态占用同一预留高度，行高不变。只有渲染出的行（可视窗口加缓冲）才请求预览，防抖约 250 ms，`none` 时不发请求。滚动到距末尾约 10 行时自动加载下一页；加载失败不自动重试，仍由“加载更多”按钮重试。
- 头像在整行**垂直居中**；未读标记放在每行最左侧的**固定窄列**（头像左边），同样垂直居中，所以无论发件人名字多长，所有行的点都在同一条竖线上。点用**固定蓝色**（浅色 `blue-500`、深色 `blue-400`），不跟随强调色：红、橙类强调色会被读成错误或紧急，黄色会和星标撞色。未读与已读的视觉差异只由这个蓝点表达，邮件文字保持同一字重。鼠标悬停或键盘聚焦邮件行时，状态点外显示直径约 14px 的中性细环，点击区域仍为透明的 28px：未读显示 8px 蓝点加环，已读显示空环；蓝点始终保持稳定，仅环淡入淡出。行右上角平时显示时间，悬停或聚焦时以星标、归档 / 恢复和删除操作替代；删除放在最右侧并使用 destructive 色。图标直接显示在行背景上，不加按钮组面板、底色、阴影或描边，动作只用约 150ms 的透明度过渡，不发生位移，并遵循减少动态效果偏好。快捷操作使用真正的 `IconButton`、Tooltip 和无障碍标签，不改变虚拟列表行高；本机副本隐藏服务器读写操作。
- 允许使用边框的只有表单控件（输入框、选择器、按钮的 outline 变体）、焦点环，以及附件等独立小元素的轮廓。判断标准：它是控件或独立对象的外形，而不是在分隔区域。

邮件行只有发件人首行为右上角的时间与快捷操作预留宽度，主题和正文预览使用全部可用宽度。悬浮按钮垂直对齐首行中心，底部不侵入主题行；显示与隐藏时不改变文字布局。

状态点点击区与头像之间保持 4px 间距，头像与文字之间保持 12px。列表和阅读区工具栏复用 `ReadStatusButton`：已读显示空环，未读显示环加蓝点；阅读区常显环，列表只在悬停或聚焦时显环，两处保留同样的 Tooltip、状态标签和点击尺寸。

## 打开的邮件独立于列表

阅读区里的邮件是**独立的状态**，不是“列表里恰好能找到的那一封”。它只记邮件 id、所属账号和打开时该账号的服务器来源，其余内容（包括已读、星标、待同步标记）都从邮件自身读取，不依赖列表里有没有它：

- 切换邮箱 / 文件夹、切换“全部 / 未读”、搜索、列表刷新、同步，以及它被标为已读而从“未读”列表里消失，都**不会**关闭它；列表只在恰好列出它时高亮。
- 只有三件事会改变它：用户点另一封邮件；用户主动关闭（工具栏最右侧的关闭按钮，或 `Esc`）；它必须消失——邮件已被删除或对用户不可见（读取返回 `notFound`），或其账号的服务器来源已被替换（这时继续显示会把旧服务器的邮件放在新账号旁边）。
- 没有打开邮件时，阅读区不显示工具栏，只显示“未选择邮件”的空状态。
- `Esc` 让位于正在使用它的控件：输入框、命令面板、菜单和对话框先于邮件处理，不会顺手关掉邮件。
- 不跨重启记住打开的邮件；以后可作为设置项提供。

## 自有外壳组件，不直接用 shadcn Sidebar

`frontend/src/features/shell/` 是应用外壳，shadcn 的 `components/ui/` 只作为底层原语（按钮、输入框、对话框等），便于同步上游。外壳级组件由我们自己维护，后续往里加内容不需要覆盖 shadcn 的定位逻辑：

| 组件 | 职责 |
| --- | --- |
| `ShellLayout` | 画布下的布局：导航展开或收成图标栏、`Cmd/Ctrl+B`、折叠按钮、导航宽度、窄窗口处理和岛；通过 `ShellContext` 暴露 `navOpen` 与 `toggleNav` 供命令使用 |
| `NavRail` | 导航容器：在完整侧栏与图标栏（`NAV_RAIL`，48px）之间切换、宽度过渡，右侧 8px 间隙兼作拖拽条 |
| `Island` | 岛的表面 |

## 邮件侧栏的结构

状态：**第一阶段已实现，未经手测** · 2026-11-05。面向所有用户，不只是技术人员：侧栏不出现“统一”“本机”“角色”之类的词，空的条目不显示。顶部按类型跨账号查看，账号树按账号查看，两种入口并存，由用户选择；账号树默认折叠，平时只占每个账号一行。

`MailSidebar` 从上到下：

- **写邮件**。
- **顶部（无分组标题）**：每一行都是跨所有账号的视图——收件箱（未读数，计数未知时显示“—”）、星标（不显示数字）、草稿（本机草稿，显示数量）、已发送、发件箱（只在有未完成的发送时出现），以及默认收起的“更多”。“更多”里是归档（本机归档，`{ kind: 'archived', accountId: null }`，显示已归档未读数）、垃圾邮件（只显示圆点，从不计数）和已删除。“更多”的展开状态记在 `localStorage` 的 `mailx.sidebar.expanded`。
- **按账号展开**：收件箱、已发送、归档、垃圾邮件、已删除在有两个及以上账号具备对应文件夹时，行尾有箭头按钮（悬停、聚焦或已展开时显示，数字随之左移而不被遮住），展开后按账号显示顺序列出每个账号的那个文件夹，带账号头像；收件箱子行显示该文件夹未读数，垃圾邮件子行只显示圆点。默认收起，状态同样记在 `mailx.sidebar.expanded`。只有一个账号时不显示箭头，该账号的文件夹在账号树里。
- **“邮箱”分组**：每个账号一行，保留头像、同步状态与手动刷新、同步失败图标。账号默认折叠，用户展开的账号记在 `mailx.sidebar.expanded`；展开后是该账号的完整文件夹树，收件箱之后是该账号的本机“已归档”，有子文件夹的文件夹默认展开，用户收起的记在 `mailx.sidebar.collapsed`。收件箱、已发送、垃圾邮件、已删除用统一名称和图标；服务器上的草稿和归档文件夹用服务器上的原名和普通文件夹图标，不加“（服务器）”等后缀，所以不会与顶部的本机“草稿”“归档”重名。账号行的未读数是该账号全部文件夹之和（垃圾邮件不计入）。尚未取得文件夹列表的账号直接显示“正在同步文件夹…”或“暂无文件夹”，不是折叠按钮。
- **选中项保持可见**：选中项来自命令面板、通知或账号移除后的回退时，侧栏只为它展开必需的部分（视图在“更多”里就展开“更多”；文件夹没在已展开的顶部行下列出时展开它的账号）。这种展开只在本次会话有效，不写入 `mailx.sidebar.expanded`；用户收起后不再自动展开，直到选中项变化。

“星标”视图查询 `{ starred: true, archive: 'include', excludeFolderRoles: ['junk', 'trash'] }`，可用“全部 / 未读”筛选和搜索。命令面板“跳转”分组按相同顺序列出这些顶部视图，再列出各账号文件夹。

下一阶段（未实现）：收藏与隐藏文件夹，入口为右键菜单（使用 shadcn `context-menu`，需保证 Shift+F10 / 菜单键可用），收藏可拖动排序，隐藏的文件夹统一收在账号区末尾以便恢复；星标计数需核心提供计数后再加。

## 列表与阅读区的分隔

列表与阅读区之间的拖拽条可以拖动，列表宽度保存在核心 `settings.json` 的 `layout.listWidth`（300–2000px，默认 420px），下次启动恢复。只保存用户亲手拖动的结果：窗口缩放引起的比例变化不写盘；阅读区折叠期间列表占满岛，也不会把那个宽度存下来。

**拖动类的布局变化都抖动写入**（侧栏宽度、列表宽度、阅读区折叠）：统一经 `useDebouncedLayoutSave`（基于 TanStack Pacer 的 `useDebouncedCallback`），停止变化 500ms 后才写一次，所以一次拖动、连按方向键或连续几次拖动都只写一次磁盘，拖动过程中不会有任何写入。等待期间的多项变化合并成一次提交，侧栏和列表各自的值不会互相丢失。窗口关闭（`pagehide`）或组件卸载时立刻写出尚未写入的内容。以后新增的这类高频布局值也应走这个入口，不要直接调用 `updateSettings`。窗口比保存的宽度所需更窄时，列表和阅读区按比例一起缩小，各自不低于最小宽度（列表 300px、阅读区 360px）；保存的宽度只在启动时用一次，所以设置读到之前先不渲染面板组，避免先按默认宽度排版再跳变。

标题栏右上角的折叠按钮把阅读区收起，列表占满整个岛；再点一次展开，图标显示点击后会发生的事。折叠时阅读区是 `inert`（Tab 和读屏都不可达），Esc 不会去关一封看不见的邮件，拖拽条隐藏。**打开任何一封邮件都会自动展开**：点列表里的邮件、命令面板里选一封、点系统通知，都走同一个 `openEmail`。折叠状态会持久化（`layout.readerCollapsed`），下次启动恢复；打开邮件使它展开，这个变化同样会保存。拖动拖拽条把阅读区压到最小宽度以下也会折叠它，状态由 `onResize` 同步回按钮。

导航宽度可拖动，范围 220–420px，默认 256px；双击拖拽条恢复默认，聚焦后可用方向键、Home、End 调整。宽度保存在核心 `settings.json` 的 `layout.navWidth`，拖动或按键结束后才保存，约定见[应用 API](../contracts/app-api.md)。拖动期间岛临时 `pointer-events-none`，避免鼠标进入正文 iframe 后丢失事件。

**导航只有两种状态：完整侧栏和图标栏，不存在完全隐藏。** 标题栏按钮、`Cmd/Ctrl+B` 和命令面板在同一位置切换，选择保存在 `layout.navCollapsed`，重启后保持。收起后的图标栏宽 48px，只显示图标，悬停和聚焦时用 Tooltip 显示名称（含未读数，如“收件箱 · 24 封未读”）：写邮件、收件箱（未读数角标，超过 99 显示 99+）、星标、草稿（数量）、已发送、发件箱（仅在有待发邮件时）、更多，然后是每个账号的头像，最后是账号和设置。

- **更多与账号改用菜单**：图标栏只有一列，所以“更多”和账号头像点击后弹出菜单（shadcn `dropdown-menu`），其中列出与完整侧栏相同的条目：归档 / 垃圾邮件 / 已删除，以及该账号的完整文件夹树（按层级缩进，含该账号的本机“已归档”，显示未读数；垃圾邮件只显示圆点）。菜单项的选中态与完整侧栏一致，打开菜单不会切换邮箱。
- **账号角的圆点**：有未读邮件时为强调色圆点，同步失败时为红色圆点；当前打开的文件夹属于某个账号时，该账号头像带强调色圆环。账号头像区独立滚动，写邮件和底部的账号 / 设置固定不动。
- **拖到很窄就收起**：把侧栏拖到宽度小于 `NAV_SNAP`（图标栏与最小宽度之间）时切换成图标栏，拖动图标栏的右边缘向右则恢复完整侧栏；图标栏状态下键盘 `→` / Home / End 展开，完整侧栏在最小宽度再按 `←` 收起。收起时保留原来的宽度，下次展开回到那个宽度。
- **窄窗口自动收成图标栏**：窗口宽度小于“侧栏最小宽度 + 列表最小宽度 + 阅读区最小宽度 + 16px”（当前 912px）时显示图标栏，即使保存的选择是完整侧栏。此时点折叠按钮可以临时展开，窗口变宽后回到保存的选择；这次临时展开不写入 `layout.navCollapsed`。

`MailSidebar` 只负责邮件相关内容，放进 `NavRail`；它里面的菜单项暂时仍用 shadcn 的 `SidebarMenu*` 原语，设置对话框也仍使用 shadcn `Sidebar`，等有定制需求再替换。新增业务板块应往导航里放内容，而不是改容器。

### 同步状态反馈

日常自动同步保持安静：侧栏账号行不显示旋转或呼吸动画，未读数持续显示，不被同步状态替换。用户主动刷新时，只在对应的刷新按钮上显示进行中反馈，其他账号行保持稳定。

新接入账号首次获取可浏览内容时，使用弱化的静态文字提示；已有缓存的账号正常启动时不重复显示首次获取提示。同步异常继续保留静态提示和处理入口，避免静默运行掩盖需要用户处理的问题。

### 账号与设置入口

导航底部有两个相邻入口：**账号**（`@` 图标）和**设置**（齿轮），各开一个独立弹窗。账号决定数据来源、网络路由和凭证，是核心资产，不放进应用偏好；同步失败时账号入口显示警示标记。

账号按修改频率拆成两部分：**资料**（名称、标识颜色、发件人名称、是否使用服务商图标，常改、无风险）和**连接**（地址、服务器、凭证、网络路由，配好后很少改，改了会重新连接）。两部分各有一个可复用组件：`ProfileFields` 和 `ConnectionForm`。添加和修改连接中的 IMAP / SMTP 登录用户名都可留空，说明文字提示默认使用邮箱地址，占位符跟随本次邮箱输入；两个字段独立在提交时解析默认值，保存实际用户名，重新编辑时显示已保存值。

- **账号管理弹窗**（`AccountsDialog`）：左侧账号列表，列表标题右侧为使用强调色的“加号 + 添加账号”文字按钮，不附加重复的 tooltip，避免弹窗默认聚焦时自动出现提示；窄窗口列表转为顶部横排时仍保留此入口。右侧为所选账号，资料直接编辑并自动保存（名称在失焦或回车时、颜色在点选时、图标偏好在切换时），所以这里没有“保存”按钮和未保存确认；连接只显示摘要，“修改连接”打开单独的弹窗。凭证需要重新确认或同步已停止时，顶部提示并直达“修改连接”。内容宽度有上限，所以用固定尺寸的弹窗而不是铺满主岛，避免大窗口下留白。
- **修改连接弹窗**（`ConnectionDialog`）：叠在管理弹窗之上，内容是 `ConnectionForm`；保存后立即重新连接，离开前确认未保存的修改。
- **添加账号弹窗**（`AddAccountDialog`）：独立的三步引导，高度固定：选择服务商 → 连接（`ConnectionForm`）→ 命名（`ProfileFields`，名称默认取邮箱地址，手动 IMAP/SMTP 默认选一个其他账号没用的颜色，其他服务商入口默认“不标识”）。每步底部有“上一步”和“下一步 / 完成”；点服务商行只是选中，点“下一步”才前进（双击行可直接前进）。步骤切换按方向左右滑入，系统要求减少动态效果时不播放。返回时保留搜索词和已选服务商，重新打开向导则重置；从第 3 步返回第 2 步会保留已填内容和密码；服务器拒绝连接参数时退回第 2 步并标出字段。服务商使用无边框的单列列表，每行从左到右显示 Logo、名称、短描述与选中标记，以淡底色区分悬停和选择。搜索框固定在上方，底部操作固定，中间列表独立滚动；搜索本地匹配名称、域名、描述与别名，忽略大小写和首尾空白，多词需全部匹配。过滤隐藏当前选项时清除选择，“下一步”恢复禁用；无结果显示提示。使用原生单选框支持 Tab、方向键与空格选择。当前列表首项为带官方本地图标的“iCloud 邮箱”，随后是“QQ 邮箱”（覆盖 QQ / Foxmail）、“网易 163 邮箱”、“网易 126 邮箱”、“网易 yeah.net 邮箱”和“139 邮箱”；末项为“IMAP/SMTP”（手动配置其他邮箱）。Gmail、Outlook 等预设与 OAuth 尚未实现，加入时各自提供连接步骤。完成后回到管理弹窗并选中新账号。

账号管理列表的每个账号左侧提供独立拖动手柄，使用 `@dnd-kit/react` 的 sortable 与指针、键盘传感器；手柄和账号选择按钮并列，点击账号仍只切换详情。宽窗口上下排序，窄窗口的顶部横排左右排序，支持滚动。聚焦手柄后按空格或回车拿起，方向键移动，再按空格或回车放下，Esc 仅取消本次拖动；说明和位置播报均随界面语言切换。拖动不会切换当前编辑账号。放下且顺序改变时保存一次，取消或原位放下不保存；保存失败回退到已提交顺序并显示错误。此离散操作直接使用布局字段更新，不走宽度变化的 500ms 抖动写入。

显示顺序保存在本机 `settings.json` 的 `layout.accountOrder`，由账号管理、邮件侧栏、命令面板、写信发件账号下拉框和相关设置中的账号列表共用，其他窗口经设置事件跟随。未记录的新账号接在末尾，不存在或已删除的 id 在显示时忽略，空偏好沿用原始账号顺序。该偏好只调整显示顺序，不改变草稿已有发件账号、显式默认发件账号或核心在缺省时选择账号的顺序。

添加时，用户未手选颜色的默认值随添加方式变化；手选颜色或“不标识”（包括再次点击当前选项）后，返回步骤、更换添加方式和保存失败重试均保留选择，重新打开向导则重置。关闭服务商图标不会自动补色；已有账号的颜色保持原值。

添加向导的连接步骤提供“测试登录”，QQ、网易和手动配置均可使用。它验证当前填写的收发连接并分别显示结果，不保存账号、不发送邮件；可以跳过测试或在部分协议失败后继续。测试时可取消，修改任意连接字段、下一步、返回、关闭及卸载都取消旧尝试并移除过期结果；测试完成保留输入，方便修正和继续保存。按钮、说明和结果位于可滚动表单内，底部“上一步 / 下一步”保持可达。

账号连接摘要中的“验证收发连接”分别检查已保存版本的 IMAP / SMTP 登录，可取消；配置变化、切换账号或关闭弹窗使旧结果失效。不发送邮件，不将认证通过表述为真实投递成功。QQ 与网易认证失败时显示各自的协议开通、授权码和安全验证排查指引，帮助按钮只打开所属服务商的固定官方文档。安全策略拒绝使用独立的 `providerPolicy` 原因，在同步状态、连接诊断与正文失败中提示；处理后可手动同步或重试正文，不要求用户必须修改连接。正文帮助取自保存账号的 `providerId`，未知服务商只显示通用提示。

“修改连接”右侧提供浅红色“移除账号”按钮，窄窗口可换行。确认框显示账号名、邮箱地址及当时的草稿/待发数量，明确所有本地草稿和发件记录将被清理、相关写信窗口与未保存内容将关闭、服务端邮件保留；始终说明已提交或结果不确定的邮件可能已送达，移除不撤回。默认焦点为取消；提交中禁止切换/新增/修改账号及重复移除，错误留在确认框重试。成功选择相邻账号，最后一个账号移除后显示现有添加入口。自动保存跨移除请求等待结果，成功后丢弃在途回调与卸载写入；失败时恢复保存。`sending` 由后端原子拒绝，不能依赖前端按钮互斥。

服务商（QQ 邮箱、网易 163 / 126 / yeah.net、通用 IMAP/SMTP 等）在 `features/accounts/providers.ts` 集中登记：默认图标、可选本地 Logo、名称、邮箱后缀、短描述和搜索别名，以账号的 `providerId` 关联（`null` 即手动配置的 IMAP/SMTP，不认识的 ID 也会显示原值）。添加向导的列表、管理弹窗“连接”分组标题旁和修改连接弹窗标题栏的 `ProviderBadge` 都读这份登记；新增服务商只需加一项并提供它的连接步骤。

服务商标识使用随应用打包的官方 PNG：QQ 使用邮箱专属图标，163、126、yeah.net 使用各自的完整标识，139 使用官方应用图标；保留原图的字形、配色和比例，不再裁掉标识文字或描摹成路径。选材、允许的提取或格式转换、通用图标回退与验收规则统一见[服务商图标维护规范](../../frontend/src/assets/providers/README.md)。侧边栏的账号行、管理列表与资料预览、通知设置均用 `AccountAvatar` 显示账号：具体服务商有本地 Logo 时，默认以 Logo 替换首字母，头像容器保持透明、素材自带底色原样保留，账号颜色仅作为 1 px 细圆环，图标与圆环之间保留 2 px 内边距。标识颜色提供叉号选项，悬停提示和无障碍名称为“不标识”；选择后保存空颜色，清除服务商图标的圆环及内边距，图标恢复完整大小。添加最后一步和账号资料里可单独切换“使用服务商图标”，设置按账号持久化，旧账号默认开启；关闭、手动配置或未知服务商回退首字母和彩色底，没有颜色时用中性底色。没有可用服务商 Logo 的账号不显示这个开关。图标切换只更新资料，不改变连接版本、凭证或同步。颜色只用于区分，不承载状态。
- **设置弹窗**：只含应用级偏好。左侧导航按职能分组，组与组之间用更大的间距和一行弱化小标题区分，不加分割线；“关于”单独放在导航底部、不属于任何分组。分组为：
  - **应用**：通用、外观、通知；
  - **邮件**：发信（默认发件账号、撤销发送时间）、安全性（远程图片、发件人头像）；
  - **集成**：MCP，以后的 AI 设置也放这里。

  窄窗口里导航收成顶部一排，此时只显示页名，不显示分组小标题。

  “MCP”页（已实现，未经手测）：一个“开启 MCP 服务器”开关，开启前弹出确认，说明外部 Agent 将能读取全部账号的本地邮件和草稿、创建 / 修改 / 删除草稿、批量设置已读 / 星标、本机归档 / 恢复、请求同步刷新、打开草稿、直接发信及使用本机文件作为附件，不能删除邮件；新增能力随总开关统一开放，不增加整理开关；页面仅保留开关、运行状态（已关闭 / 运行中及连接数 / 启动失败及原因）、已连接客户端与客户端配置；访问范围和能力边界集中在开启确认中说明，页面不再重复罗列。连接客户端分组仅用一句话提示复制并粘贴配置，并提供“复制客户端配置”（`mcpServers` 格式的 JSON，命令为应用自带的 `mailx-mcp` 绝对路径，参数恒含 `--discovery <发现文件绝对路径>`；成功后弹出短提示），按钮下方有默认折叠的“手动配置”，展开后用小号等宽字显示程序路径与发现文件路径（位于主目录内时显示为 `~/…`，Windows 为 `~\…`），各带一个复制按钮，复制的仍是完整绝对路径；折叠区不加边框或卡片。授权与生命周期规则见 [MCP 草案](../contracts/mcp.md#2-桌面连接与授权)。

## 标题栏

标题栏替代系统标题栏，空白处拖动窗口，双击行为遵循系统偏好，按钮、输入框等交互元素不触发拖动。页面通过 `TitleBarActions` 把内容送进三个插槽（保持各自的 React 上下文）：

| 插槽 | 位置 | 当前内容 |
| --- | --- | --- |
| `leading` | macOS 红绿灯之后（或左边缘） | 侧边栏折叠按钮 |
| `center` | 两侧之间，居中 | 搜索入口（命令面板的触发器） |
| `trailing` | 窗口控制按钮之前 | 明暗模式按钮，其右侧是“收起 / 展开邮件内容”按钮；开启 MCP 后，明暗模式按钮左侧增加 MCP 状态图标（更新提示按钮若出现，位于其左侧） |

约定：

- 标题栏不显示应用名称文字。
- MCP 状态图标（已实现，未经手测）：只在开关开启时显示，为服务器图标加右上角圆点角标。运行中为绿色点，启动失败为红色点；开关已开启、服务尚未回报运行（启动中）时不显示圆点，Tooltip 写“正在启动…”，避免在短暂的启动期闪出红绿色。开关关闭时整个图标不显示。悬停 Tooltip 第一行为运行状态（“MCP 服务器: 运行中”；无连接时为“运行中，暂无客户端连接”；启动失败时显示原因），有客户端连接时第二行为“已连接：Claude Code、Cursor”，重复的合并为“Claude Code ×2”，尚未自报身份的显示“未知客户端”，名称不加“自行报告”之类的限定语，也没有“打开设置”提示行；点击图标打开“设置 → MCP”（经窗口事件通知工作台打开设置弹窗），该行为由按钮角色传达。无障碍标签只含状态文字。设置页状态行为“运行中，N 个客户端已连接”，其下逐行（弱化色）列出当前已连接的客户端，合并规则同上，无连接时隐藏该列表，同样不加限定语。状态色同时配文字说明，不只靠颜色表达。
- 与具体页面无关的全局功能（如明暗切换）放在 `App.tsx`，没有账号或启动失败时也可用；与邮件有关的（如搜索）由 `Workbench` 挂入。搜索结果中正文或附件名命中的行，用带淡色底高亮的命中片段替代预览行；结果上方一行淡色小字说明已在本地索引的多少封正文中搜索（与同步范围受限的提示合并为一行，不加分割线）。（本地全文搜索已实现，尚未手测。）
- 折叠按钮不做 toggle 外观：展开时显示"收起侧边栏"图标，收起后换成"展开侧边栏"图标，标签随之变化。
- 同一插槽里的按钮用 `TitleBarActions` 的 `order` 排序，而不是按挂载先后：明暗模式按钮和邮件内容折叠按钮分属 `App` 与 `Workbench`，加载顺序不固定，折叠按钮 `order={1}` 固定在最右。
- 明暗模式按钮循环切换"跟随系统、浅色、深色"，图标显示当前模式，通过现有外观设置保存。

## 命令面板

标题栏中间的搜索入口行为类似 shadcn `Command`（基于 `cmdk`，`components/ui/command.tsx`），点击或按 `Cmd/Ctrl+K`、`Cmd/Ctrl+F` 打开，`↑↓` 选择，`Enter` 执行，`Esc` 关闭，每次打开都从空输入开始。

- 入口占位符写明搜索范围，例如"在 全部收件箱 中搜索""在 工作邮箱 · 收件箱 中搜索"。
- 输入时面板只做预览，**不实时过滤邮件列表**。第一项固定为"在 {范围} 中搜索「xx」"，`Enter` 才把关键词应用到列表；应用后入口显示该关键词并带 × 可清除。
- 分组：搜索、邮件（当前范围内最多 8 条预览，点击打开该邮件并应用搜索）、跳转（全部收件箱与各账号文件夹）、命令。未输入时命令在前，因为文件夹列表可能很长。
- 命令只列出**已经可用**的功能：现在有“写邮件”（有账号时），不出现标记已读等尚未实现的动作。新增命令时同时更新 `command-palette.tsx` 与其测试；出现第二个命令来源后再抽成注册表。
- 过滤与排序由面板自己做（`shouldFilter={false}`），保证"搜索"项始终第一；中文输入法组字期间的 `Enter` 由 `cmdk` 忽略。
- 邮件预览目前只搜当前范围，不是跨邮箱搜索；跨邮箱搜索需要核心先提供查询。

## 第二阶段：毛玻璃（macOS 已实现，其余平台未做，实机未验证）

第一阶段刻意不做毛玻璃，只改结构。现在的做法：

- 窗口级材质只在 macOS 配置：`desktop/src/window_chrome.rs` 的 `style_builder` 让窗口透明并套用系统 `Menu` 材质（NSVisualEffectView，随窗口激活状态变化；换成 `Sidebar` 更淡，`HudWindow` 恒为深色不适用），因此需要 `macos-private-api` 特性与 `tauri.conf.json` 的 `macOSPrivateApi`（该特性不适用于 Mac App Store 分发）。Windows（Mica / Acrylic）与 Linux 没有实现，保持不透明画布。
- `window_get_chrome` 返回 `translucent`，标题栏据此给 `<html>` 加 `data-translucent`；`index.css` 在该属性下把 `.app-canvas` 的 `--sidebar` 等变量改成半透明，所以画布色仍只在这几个变量里。浏览器预览没有窗口材质，`translucent` 恒为 false。
- 系统材质跟随窗口自己的明暗，所以应用主题变化时前端调用 `window_set_theme`（`system` / `light` / `dark`），让窗口与页面一致；固定主题下同样半透明。
- 没有使用 CSS `backdrop-filter`：它只能模糊页面内部，不能替代窗口级材质。
- 岛保持不透明，以保证文字可读；描边与阴影沿用现有 token。

## 写信窗口（已实现界面，三平台实机未验证）

写信使用独立的系统窗口，不用遮挡主窗口的模态弹窗。写信窗口同样是画布加一个岛：**复用同一个 `TitleBar`**（`features/window-chrome/`，没有第二个标题栏；macOS 为原生红绿灯，Windows / Linux 按 `window_get_chrome` 自绘按钮），标题为邮件主题、空时为“新邮件”，同时写入 `document.title`（宿主未提供设置原生窗口标题的命令，所以系统任务栏标题是否随之变化待实机确认）。岛内上方为发件账号、收件人、抄送 / 密送（默认收起，草稿里已有时展开）、主题，下面是 Tiptap 富文本编辑区及无边框格式工具栏（段落样式与粗体组常驻，窄窗口先把对齐 / 引用 / 撤销重做收进“更多格式”，再收颜色组；色板支持方向键、回车与 Esc，详见[富文本设计](sending.md#14-富文本写信已实现)），底部左侧是保存状态（打开时不显示，改动后才出现“已保存”等，详见写信窗口设计），右侧是丢弃和发送按钮（发送在最右），同样不加分割线；底栏最左是添加附件的回形针图标按钮，编辑区与底栏之间是附件栏（无附件时不显示）：每行文件名、转发标记、大小与移除图标按钮，无边框，悬停淡底色，超过上限时显示错误色提示，服务器上限只作淡色提示；系统拖入文件同样添加，拖动经过时没有高亮（Windows 上网页收不到拖动状态）；收件人行与主题行只在悬停和聚焦时有淡底色，地址是行内小标签（无效地址为错误色标签）。格式工具栏在链接按钮后有插入图片的图标按钮（带 Tooltip，只读时禁用），粘贴剪贴板里的图片同样插入；正文里的图片最宽占满编辑区，不加边框和阴影，找不到对应图片时显示淡色“图片已丢失”占位，内嵌图片不进附件栏。第一次按发送时若有丢失的图片，底栏提示“有 N 张图片已丢失，将不会发出”，不阻止发送。（内嵌图片已实现并经 macOS 用户手测，Windows / Linux 未验证。）

结构：`ComposerApp`（`features/composer/composer-app.tsx`）负责画布、标题栏、窗口标题和关闭协议；`Composer`（`composer.tsx`）与宿主无关，只要 `client`、`draftId`、账号列表和 `onSent` / `onDiscarded`，将来可原样放进主窗口的岛；草稿保存在 `use-draft-editor.ts`，收件人输入在 `recipient-field.tsx` / `address-parse.ts`（与核心 `valid_address` 同一条保守规则，核心仍是权威）。浏览器开发预览：`/?composer=<uuid>&platform=windows|linux|macos`（`platform` 与旧的 `titlebar` 参数等价），由模拟客户端为这个 id 现建一份空草稿；`?seed=outbox` 额外放入草稿和失败 / 未知 / 重试中的发送项。

发送按钮分两步：第一次点击校验（至少一个收件人、地址都有效、账号与发信凭证可用）并写出未保存内容，按钮宽度与颜色在约 200ms 内过渡为“确认发送”（主题为空时为“无主题，确认发送”），第二次点击才入队；约 400ms 内的再次点击无效以防双击越过确认，约 4 秒无操作、修改内容、`Esc` 或窗口失焦时退回；`Cmd/Ctrl+Enter` 同样按两次；减少动态效果时不播放过渡但保留 400ms 防双击；`aria-live` 播报“再次按下以确认发送”。入队请求带进入待确认时已保存的 `expectedRevision` 和新的 `clientMutationId`，冲突时退回并重新加载草稿。窗口尺寸、关闭与草稿保存见[写信与发送设计](sending.md#2-写信窗口独立窗口)。

### 主窗口的写信入口、草稿与发件箱

- 导航顶部“写邮件”与其他导航项同样式（`Cmd/Ctrl+N` 同效，提示文字里写出快捷键）；阅读区工具栏的回复 / 全部回复 / 转发；命令面板的“写邮件”。归档、删除仍是未实现的占位按钮；打开本机已发送副本时，这个位置换成“从本机移除”（带确认），已读与星标按钮隐藏。已发送文件夹的列表行显示“致：收件人”（多人时加总数），头像随第一个收件人；尚未在服务器上找到副本的行在时间前有淡色电脑图标，Tooltip 说明“仅在本机”。（已实现并经 macOS 用户手测，Windows / Linux 未验证。）
- 导航里“草稿”恒在（有草稿时显示数量），“发件箱”只在有排队中、发送中、失败或需要确认的项目时出现并带数量；两者选中后岛内左侧是与邮件列表同样式的行（无边框、悬停与选中态一致），草稿行在账号名旁、写信窗口在发件账号行上方，对 MCP 创建的草稿（`origin = mcp`）显示淡色小字“由 MCP 创建”、对内置 AI 创建的草稿（`origin = ai`）显示“由 AI 创建”，不加边框或徽章底色（目前尚无入口创建此类草稿）；右侧阅读区显示草稿预览（继续编辑 / 删除）或发送项的状态、错误与可用操作。发件箱清空时若正停在发件箱，回到全部收件箱。这两个视图不参与标题栏搜索，搜索入口仍指向全部收件箱。
- 发送结果用全局 toast：撤销等待期内“将在 N 秒后发送”（带“撤销”按钮），随后“正在发送…”“已发送”；失败与需要确认的 toast 带“查看”，直达发件箱对应项。toast 允许带一个动作按钮（`toast.*(title, { action })`）。

仅有图标的按钮用 `components/icon-button.tsx` 的 `IconButton`：带 `aria-label`，并用项目的 Tooltip 显示名称（有快捷键时写进提示，未实现的写“（尚未实现）”），不用原生 `title`；禁用按钮没有指针事件，所以提示挂在可聚焦的外层 `span` 上。草稿预览的“继续编辑 / 删除”是图标按钮；发件箱项的操作仍是文字按钮。

## 新增界面时的检查清单

1. 内容放在岛里，导航类内容放在画布上，不要再造第三层。
2. 不加分割线或卡片边框；需要区分时先用间距、淡底色、悬停与选中态。
3. 颜色用 token，不写死色值；在浅色和深色下各看一遍。
4. 可点击的东西不要让标题栏拖动抢走事件（使用 button、input 等语义元素或 `data-window-no-drag`）。
5. 邮件正文始终留在隔离 iframe 内，不获得 IPC 权限；拖动或调整大小时要避免 iframe 吞掉指针事件。
6. 不把未实现的功能展示成可用。
