# 「此刻」页面

状态：**第一期（无 AI）已实现，仅自动测试与浏览器预览，桌面三平台未手测**；AI 概述与对话为 Proposed · 2026-11-14。代码在 `frontend/src/features/now/`，统计查询见[应用 API](../contracts/app-api.md)。本文记录讨论确定的方向，细节可随实现调整；与[界面设计语言](ui-design.md)冲突时，以本文明确列出的例外为准，其余仍遵循该文档。

## 1. 定位

「此刻」（英文 Now）是主窗口里的一个独立页面：向用户问候，汇总邮箱现在的状况，在配置 AI 后给出更自然的总结并允许直接对话。它不是必经的门厅，用户可以设为启动页，也可以完全不用。

基调：**统计与规则是底，AI 是加分项。**

- 页面上的事实（数量、状态、验证码等）一律来自本地计算，规则可以解释，离线和没有配置 AI 时完整可用。
- AI 只负责把这些事实说得更自然、补充重点和回答提问，不产生页面上的统计数字。
- AI 关闭、失败或超时时，页面退回预设内容，不出现错误横幅；第一次生成失败时预设句旁有一个很淡的重试图标（见 5.1）。

不使用“首页 / Home”“仪表盘 / Dashboard”“助手 / Assistant”等名称：前两者偏冷或像门厅，后者把页面和 AI 绑定，与上述基调矛盾。

## 2. 入口

- **导航位置**：侧栏“写邮件”之下、“收件箱”之上；图标栏中位置相同，Tooltip 为“此刻”。
- **图标**：Hugeicons 的 `SunriseIcon`（日出），固定不随时段变化，方便按图标找到入口。不用时钟（易与历史记录或定时发送混淆），不用太阳（标题栏明暗模式按钮已用 `Sun03Icon`），不用星芒（留作 AI 内容标记）。
- **命令面板**：“跳转”分组列出“此刻”，排在顶部视图之前。
- **启动页**：“设置 → 通用 → 启动时打开”（`general.startupView`：此刻 / 收件箱），默认此刻；升级前没有这一项的设置文件同样按此刻打开，想回到原来习惯的用户可改选收件箱。只在主窗口启动、设置首次读到时生效一次，不覆盖用户已经切换的视图。

## 3. 页面结构

页面占满整个主岛，不拆成列表和阅读区。

```text
┌───────────────────────────── 岛 ─────────────────────────────┐
│                  （背景氛围层：按时段的渐变）                     │
│          ┌──────────── 内容列（居中，限宽）────────────┐          │
│          │ 问候                                        │          │
│          │ 概述句（预设或 AI）                          │          │
│          │                                            │          │
│          │ 需要处理的事 · 验证码（有才显示）              │          │
│          │ 收件箱：新邮件 / 未读 / 星标未读 + 未读列表     │          │
│          │ 近况：14 天收件图、收发对比、往来最多、今天      │          │
│          │ 最近的附件（有才显示）                         │          │
│          │ 同步状态页脚                                  │          │
│          │ ╭ AI 输入框（仅在 AI 可用时出现）╮            │          │
│          └────────────────────────────────────────────┘          │
└──────────────────────────────────────────────────────────────┘
```

- **内容列**限宽（最大约 760px）并水平居中，装饰与背景铺满整个岛。内容比岛矮时整体垂直居中，略高于正中（上下留白约 2:3）；内容超过一屏时顶端对齐、正常滚动。由布局实现，不按“内容多少”切换。统计和未读列表都返回（成功或失败）后才显示内容列，之前只显示背景，避免问候语随后续内容到达而跳动。AI 输入框以后固定在内容列底部。
- **分组不用卡片边框或分割线**，靠留白、字号层级和淡底色块（如 `bg-muted/40`）区分，与岛内其他页面一致。
- **标题栏**：页面没有阅读区，“收起 / 展开邮件内容”按钮在此页隐藏；搜索入口范围与草稿、发件箱视图相同，仍指向全部收件箱。
- **快捷键**：列表与阅读区的单键（`j` / `k`、`e`、`s` 等）在此页无效；`/`、`?`、`Cmd/Ctrl+K`、`Cmd/Ctrl+N` 照常可用。
- **打开邮件**：点击页面上任一邮件，跳到它所在的视图（如收件箱）并经现有 `openEmail` 在阅读区打开，不在此页内嵌阅读器。打开的邮件本就独立于列表，见[界面设计语言](ui-design.md#打开的邮件独立于列表)。
- 浅色、深色、中英文和窄窗口都要可用；窄窗口下装饰减弱，内容优先。

## 4. 内容：统计层（无需 AI）

### 4.1 问候

- 按本机时段给出问候（清晨、上午、下午、傍晚、深夜分别措辞），配日期。
- **时段图标**：问候语前有一个 Hugeicons 图标，随时段变化（`greeting.ts` 的 `SEGMENT_ICONS`）：清晨 `SunriseIcon`、上午 `Sun03Icon`、中午 `Sun01Icon`、下午 `SunCloud01Icon`、傍晚 `SunsetIcon`、深夜 `MoonStarIcon`。颜色是低饱和的暖橙、琥珀、暖黄、橙玫、靛蓝，取自 `index.css` 的 `--now-icon-*`（浅深色各一套，在岛的背景上不低于 3:1）。大小跟标题大写字母等高，落在问候语基线上；对读屏隐藏（问候语本身已说明时段）。每次进入页面时随该块淡入并从 −12° 转正；页面开着跨过时段时，新旧图标交叉淡入；减少动态效果时静止。称呼取默认发件账号的发件人名称，没有时不称呼。
- 预设文案按**情境**挑选：时段、星期（如周一、周五）、节日，中文界面可加二十四节气；邮箱状态也参与，例如收件箱已清空、有发送失败、有账号需要处理。
- **同一天保持稳定**：以本机日期和情境为种子挑选句子，切换页面再回来不换句子；情境变化（如时段跨越、出现新的待处理事项）时才更换。
- 文案写在中英文资源文件中，按情境分组，每组若干句；涉及数量的句子按语言处理单复数。语气平实亲切，不过度热情，不使用表情符号作为主要内容。

### 4.2 统计项

各项只在有内容时出现，空的条目不显示（与侧栏一致）。

| 项目 | 内容 | 数据来源 |
| --- | --- | --- |
| 需要处理的事 | 同步停止或需要重新登录的账号、发件箱中失败或需要确认的发送、未完成的草稿 | 现有同步状态、发件箱、草稿 |
| 收件箱 | 一行小数字按钮：新邮件（上次查看后到达，进入全部收件箱）、未读（进入全部收件箱并切到“未读”）、星标未读（进入星标）；值为 0 的隐藏，未读除外。下面列最新的未读邮件，最多 6 行，不嵌套滚动，上次查看后到达的标“新”；未读超过 6 封时显示“查看全部 N 封未读”。有新邮件、未读或星标未读时显示 | 新邮件与星标未读来自统计查询；未读数取文件夹计数；列表用与收件箱“未读”筛选相同的列表查询（限 6 条），随同步刷新 |
| 最近的验证码 | 最近 15 分钟内识别出的验证码（最多 3 个），显示来源发件人与时间；页面停留期间超时自动隐藏 | [验证码识别](verification-codes.md)；统计查询从缓存正文或预览中找出已有的验证码，另给出 `codeCandidates`：窗口内主题像验证码、但预览和正文都还没有的邮件（最多 5 封）。统计查询自己不为此下载正文；页面把验证码和候选一起交给共用识别（`allowFetch: true`，core 可为像验证码的主题下载正文），候选在识别返回 `ready` 时才作为验证码显示，同样不超过 3 个、按时间从新到旧、满 15 分钟移除。（只检查窗口内最新的 50 封。）复制与邮件列表、阅读区共用同一流程：由应用的验证码识别给出可复制的结果（可能为像验证码的邮件下载正文），宿主写剪贴板并遵循“复制后移到已删除”设置；只显示识别已确认、可以复制的验证码；尚未识别、无法识别、无验证码或有歧义的条目都不显示 |
| 最近的附件 | 近 7 天收件箱中带附件的邮件（最多 5 封）：正文已下载时显示文件名，否则显示“附件”；点击打开所在邮件 | 附件元数据 |
| 近况 | 近 14 天每天收件的柱状小图（今天用强调色，其余灰色，无坐标轴；每根柱子悬停或键盘聚焦显示日期和封数，图表一个 Tab 停留点、方向键切换日期）；“近 7 天收到 N 封”并与前 7 天比较（差距不超过 2 封或一成时写“差不多”）；发出封数（两周都为 0 时不显示）；往来最多的 3 人（点击查看与对方的往来邮件）；今天收到多少、还剩几封未读。近 14 天有收发时显示 | 统计查询的 `activity`：前端传入本机时间的 14 个零点；收件含本机归档，发信与“已发送”视图同口径；往来最多只算你写过信的地址、不含自己的地址；只有每个收件箱与已发送文件夹都已完整同步、未超同步上限且同步窗口覆盖两周时才比较 |
| 同步状态 | 内容列底部一行弱化小字“所有邮箱已同步 · N 分钟前”，后跟低饱和的圈勾图标；时间取最久未同步的账号；有账号正在同步时为“正在同步…”，有同步异常时为“部分邮箱同步异常”，两者都不带图标 | 现有同步状态 |
| 等你回复（未实现） | 别人发来、需要回复的邮件 | core 不保存“已回复”（`\Answered`）标记，需从会话推算并过滤通知类邮件，误报较多，计划与 AI 一起做 |

- “上次查看时间”存于 `localStorage` 的 `mailx.now.lastVisitedAt`（只有主窗口显示此页）：进入页面时读取并在本次停留期间固定，离开此页或窗口隐藏时更新为当前时间。首次使用时从当天零点（本机时间）算起。
- 新邮件、星标未读、验证码与附件由 core 的只读查询 `mail_overview`（桌面命令 `emails_overview`）计算，与邮件列表共用当前来源与代际过滤，排除本机归档；以后 MCP 与 Web 宿主可以复用。需要处理的事、收件箱未读复用前端已有的同步状态、发件箱、草稿与文件夹计数，不重复查询。结果不含正文。
- 数字随现有同步与邮件状态事件刷新，不轮询。相对时间（“6 分钟前”）由页面共用的分钟时钟每分钟刷新，窗口隐藏时暂停，回到前台立即刷新。

## 5. 内容：AI 层（可选）

仅在用户配置了可用的 AI 模型（见 [AI 服务商与模型配置](ai-providers.md)）后出现；依赖的流式输出、内容披露与取消机制见 [AI Runtime](../ai-runtime/README.md)，目前尚未实现。

### 5.1 概述句

- 用一两句话替换预设的概述句。它不复述统计区已有的数字，而是挑**一件值得一提的事**来说，带一点观察与俏皮（例如“三天没来，收件箱悄悄攒了 12 封新邮件”）；有趣来自“注意到了什么”而不是措辞，所以“值得一提的事”由 core 确定性地算出，模型只负责挑一件、说好。页面上的统计区不由 AI 生成。
- **发给模型的内容**（`core/src/assistant/summary.rs`，没有邮件正文和附件内容）：
  - `<facts>`：事实本身，是唯一的依据。包括新邮件数与最新几封的发件人、主题（不可信文本）、带附件的邮件数、星标未读、今日与近 7 天收发数、前 7 天的对比（历史不完整时不带）；以及**此刻**：用户本地的星期与时段（如“Wednesday night, around 21:00”）、“用户上次查看是约 40 分钟前”的粗略说法、今天的**节日或节气**。
  - **本地时间由 core 推出**：core 不知道时区，但 `dayStarts` 是用户本地的午夜，由最后一个午夜的 UTC 时刻反推出 UTC 偏移（本地午夜 = `00:00 − 偏移`），再用 `generatedAt` 得到本地小时与星期；没有 `dayStarts` 时不给这一行。时段与问候语一致（5 点起清晨、8 点上午、11 点中午、13 点下午、17 点傍晚、21 点起夜里）。只取整点，因为缓存键含事实，每分钟变化的时间会让缓存永远不命中。偏移取 −11 至 +13 小时中的一个（+13 与 −11 等写法相同时取 +13）；当天发生夏令时切换时，切换之后的几个小时会差一小时。
  - **节日与节气**来自前端：请求可带 `occasion`，是封闭列表（`calendar.ts` 里的节日 id 与节气 id），规则同预设句的 `lineContext`：节日按界面语言（英文只有元旦），节气只在中文界面发送。core 把它变成一行事实（如“Today is the solar term 立冬 (Start of Winter)”），未知值在反序列化时就被拒绝，自由文本进不了提示词。
  - `<notable>`：core 算出的观察，每条是带数字的一句英文，只在条件真的成立时出现，最有意思的在前，最多 5 条。账号被助手排除时，凡不能按账号拆分的（星标未读、两周活动及由它们得出的观察）一律不给，与 `<facts>` 一致。
  - `<recent_lines>`：最近 5 条已完成的概述句（按语言分别在内存里记，进程退出即丢），要求模型换个角度、换个说法。它**不在缓存键里**：缓存键仍是事实、模型、语言和提示词版本，同样的事实在 30 分钟内命中同一句；只有新的模型运行才会避开旧句。
- **观察清单与阈值**（常量在 `summary/observe.rs`；按此顺序，取前 5 条）：
  1. 久别归来：离上次查看 ≥ 24 小时，并说这期间到了多少新邮件；
  2. 今天比往常忙：今日收件 ≥ 5 且 ≥ 前 13 天日均的 2 倍（前一周数据完整时）；
  3. 安静：自上次查看没有新邮件、今天也没收到（久别时由第 1 条代说）；
  4. 收件周环比：近 7 天对前 7 天涨 ≥ 50% 或跌至 ≤ 67%（即 −33%），两周都 ≥ 5 封且前一周数据完整；
  5. 发信周环比：同样的涨跌幅，两周都 ≥ 3 封；前 7 天发了 ≥ 3 封而近 7 天一封没发则说“一封没发”；
  6. 往来最多的人：`topContacts[0]` 近 7 天 ≥ 3 封（名字是不可信文本，截断同发件人）；
  7. 前 6 个整天里最忙的一天：≥ 5 封、不低于第二名的 3/2、也不输给今天；
  8. 星标邮件仍未读（≥ 1）；
  9. 今天收到的邮件全部已读（收件 > 0 且未读为 0）；
  10. 深夜（本地 23 点起至 5 点前）或周末仍有新邮件到来。
- AI 生成的文字旁有一个小的星芒标记，悬停说明“由 AI 生成”和生成时间。
- **提示词的风格**（`prompt.rs`，`PROMPT_VERSION` 为 4）：从 `<notable>` 里挑最有意思的一件领头（没有就用时段、星期或节日），一两句，中文约 40 字内、英文约 25 词内；温暖、爱观察、略带俏皮，允许轻微的拟人，但不得超出事实，不连用感叹号、不用表情符号、不打招呼（页面上方已有问候）、不用“你有 N 封未读”开头；可以顺势给一句有事实依据的小提醒，不给泛泛的建议；最多两个数字，不复述整个事实块。提示词里按语言附 4–5 条风格示例（事实是编的，只学口吻）和一条“不要这样写”的反例（只会念数字）。原有的安全规则不变：只用给出的事实、不改数字、不编造，发件人、主题和联系人名字是不可信文本，只输出句子本身。
- **按需生成并缓存**：新邮件数量或待处理事项变化、或跨越时段后才重新生成；进入页面不必每次请求。页面显示“生成于 HH:mm”，提供刷新按钮。缓存键遵循 AI Runtime 第 4 节（内容摘要、模型、提示模板版本、语言），换模型或换账号范围不复用。
- 生成期间先显示预设文案，完成后淡入替换；失败、超时或取消时保留预设文案，不弹错误提示（设置页的 AI 测试负责诊断）。
- **输出上限与思考**：概述句输出上限为 4096 token（core `SUMMARY_OUTPUT_CAP`，与模型目录的输出长度取较小者）。句子本身只有一两句，上限是留给先思考再回答的模型的：思考用的 token 也计入上限，上限太小会让模型还没写出第一个字就用完。请求不带任何服务商专属的“少思考”参数（不认识的参数可能让对方拒绝请求，助手只按协议适配，见 [AI Runtime](../ai-runtime/README.md) 第 3 节），模型按自己的默认方式思考；思考内容不显示、不进缓存。单次请求总时长与对话相同，为 10 分钟。
- **被截断的句子不展示**：模型因输出上限停下（`finish_reason=length`）时，运行按 `aiInvalidResponse` 失败，不缓存，界面按失败处理，不会出现写到一半的句子。
- **重试**：第一次生成失败（没有已保留的句子，也不在等待同意）时，预设句旁出现一个很淡的刷新图标，提示为“AI 这次没写出来，再试一次”，点击后发起 `fresh: true` 的新运行，运行期间图标消失。助手被关闭或没有可用模型（`assistantDisabled`、`aiNotConfigured`）时重试没有意义，不显示。
- **刷新**：概述句旁的刷新图标始终可见（静止时是很淡的灰色，悬停或聚焦时加深），提示与无障碍名称为“重新生成”。点击后请求 `fresh: true` 的新运行，core 跳过 30 分钟缓存、重新请求模型，并用新答案替换缓存项。运行期间图标禁用并缓慢旋转（减少动态效果时不旋转），原来的 AI 句子保持显示，下方是 AI 工作线；**新句子只在完成时替换**，约 200ms 交叉淡入，不随流式文字逐段替换，因为旧句子被改写成半句会让行高和文字跳动，也让用户读到一半的内容。刷新失败、超时或取消时静默保留原来的句子，也不显示重试图标。

### 5.2 待办建议（后续）

在概述之后列出建议处理的邮件，每条带来源邮件，点击打开；只是建议列表，不自动创建任务，规则同 AI Runtime 第 1 节。

### 5.3 数据披露

- 首次使用某个模型服务时，像邮件翻译一样先征得同意，说明哪些内容会发给哪个服务（例如新邮件的发件人、主题和预览）；更换服务后重新询问。同意由 core 强制。
- 未同意前不发送任何内容，页面保持预设文案，概述位置可以放一个“用 AI 总结”的按钮触发同意。
- 默认只发送头部与预览，不发送完整正文和附件；需要更多内容时按 AI Runtime 第 3 节扩大范围并重新确认。概述句另外会带上用户本地的星期与时段、上次查看的粗略时间、今天的节日或节气，以及此前几句概述（见 5.1），这些都不含邮件内容。

## 6. AI 对话输入框

对话的共用构件、动效与性能规则见 [AI 交互界面](ai-chat-ui.md)，本节只写此页特有的部分。

- **仅在 AI 可用时显示**。没有配置 AI 时不显示输入框，也不退化成搜索：标题栏已有搜索入口，再放一个会造成重复和混淆。不在页面上放“去配置 AI”的引导，相关说明放在设置的 AI 页。
- **形态**：内容列底部的单行胶囊输入框，聚焦后增高，旁边只有发送与停止按钮，占位文字如“问问你的邮件”。出现和收起使用淡入加轻微位移，不推动上方内容。
- **对话视图**：发出第一句后，同一内容列切换为对话视图，问候与统计收成顶部一行摘要；`Esc` 或“返回”回到概览。当前对话在内存里保留，同时按设置保存在本机，可从页眉的“历史对话”重新打开（见 [AI 交互界面](ai-chat-ui.md)）。
- **配置变化**：配置好 AI 后输入框立即出现，无需重启。AI 被关闭或配置失效时，输入框收起，进行中的对话转为只读。
- **能力边界**：与本地 MCP 相同的工具（读取、整理、草稿、附件、发信、发件箱，不能删除邮件），哪些直接执行、哪些先问见[内置 AI 工具权限](ai-permissions.md)；运行机制见 [AI Runtime](../ai-runtime/README.md)。
  - 回答列出引用的邮件，点击打开；直接执行的整理在对话中列出结果并可撤销；发信默认出现确认卡。
  - 邮件内容与模型输出均不可信：回答按纯文本或受限 Markdown 渲染，不渲染 HTML、不自动加载链接或图片。
- **命令面板**：AI 可用时可加一条“问 AI”命令，聚焦此输入框；没有 AI 时不出现。

## 7. 动效与装饰

这是界面设计语言里“岛内保持朴素”的一个例外：此页允许背景氛围和入场动效，但内容区仍不用卡片边框和分割线。

- **背景氛围**：按时段变化的缓慢渐变（清晨偏暖、白天明亮、夜间偏深），色相由 `--primary` 等 token 推导，随强调色和明暗主题变化；不写死色值。文字区域的对比度必须满足可读要求。
- **入场**：每天首次打开播放完整版：内容错落淡入（上移 4px、200ms、间隔 40ms）、数字由小到大滚动、近况图的柱子长出。之后每次进入播放较轻的一版：各块淡入并上移 2px，每块 150ms、间隔 25ms，减速曲线；数字直接显示，柱子约 250ms 内从底部长出（间隔更短）。动效代码在 `motion.ts`（`entrance(mode, index)`，`mode` 为 `first | return | none`），时长与曲线用 `index.css` 的共用动效变量。
- **AI 概述句的光泽**：进入页面时概述位置已有完成的 AI 句子（包括缓存的）时，播放一次约 800ms 的 AI 渐变光泽，从右向左扫过文字，只动背景位置，不改变布局，之后移除。流式生成出来的句子、刷新后换上的句子不播放。
- **AI 文字**：流式输出时逐段出现，即本页最主要的动态效果。
- **性能**：只用 `transform` 与 `opacity` 动画，避免持续运行的 canvas / WebGL。窗口隐藏、最小化或页面不可见（`visibilitychange`）时暂停全部动画；应用常驻后台，不能因为此页持续占用 CPU 或电量。
- **减少动态效果**：遵循系统偏好，开启后只保留静态渐变，不播放入场、光泽、数字滚动，时段图标和刷新图标静止。
- 装饰元素对读屏隐藏（`aria-hidden`）；AI 流式文字用礼貌级 `aria-live` 播报完成后的结果，不逐字播报。

## 8. 隐私与安全

- 统计层只在本机计算，不外发任何内容。
- AI 层与对话遵循第 5.3 节的同意与披露范围，以及 AI Runtime 的数据披露规则。
- 页面上的发件人、主题、附件名和 AI 输出按纯文本展示，不渲染 HTML。
- 验证码只在用户点击时复制，不自动复制。

## 9. 分期

1. **第一期（无 AI，已实现）**：入口与图标、页面结构、问候与预设文案、统计项（不含“等你回复”）、近况统计与图表、启动页设置、动效与减少动态效果；core 汇总查询及测试。
2. **第二期（AI 概述）**：在内置 AI 的流式输出、内容披露与取消落地后，加入 AI 概述句、同意流程与缓存。
3. **第三期（对话）**：AI 输入框、对话视图、只读工具与引用、建议按钮、逐封确认的发信。
4. **后续**：待办建议、“等你回复”、模块显示与排序的个性化、对话持久化。

每期完成时按惯例更新 ui-design.md、应用接口文档、用户指南（中英文）、CHANGELOG 与验证记录。

## 10. 第一期实现说明

- **预设文案**：`locales/*/now.json`，按情境分组。优先级为：需要处理（停止的账号、发送失败或结果不确定；草稿不计入）＞节日＞节气（仅中文）＞新邮件＞周一 / 周五 / 周末＞收件箱清空＞平常。以本机日期和情境名的哈希挑句，同一天、同一情境不换句。
- **节日与节气**：本地计算，不联网。元旦；春节、元宵、端午、七夕、中秋用 `Intl.DateTimeFormat` 的农历（运行环境不支持时不显示节日）；二十四节气用 21 世纪通用公式加已知修正，适用 2000–2099 年。农历节日与节气只用于中文文案。
- **布局**：内容列最大 760px，内容少时居中；背景为按时段的静态径向渐变，时段变化时交叉淡入约 1 秒；入场动画每天首次进入时播放完整版，之后每次进入播放较轻的一版（见第 7 节），近况图的柱子同时从底部长出。
- **近况比较的完整性**：同步游标记录 `history_complete`（迁移 31），当前代际完成过一轮未超上限的同步后为真，后续每轮进行期间保持不变，避免比较句在每轮同步时闪烁。
