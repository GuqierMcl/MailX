# 「此刻」页面

状态：**第一期（无 AI）已实现，仅自动测试与浏览器预览，桌面三平台未手测**；AI 概述与对话为 Proposed · 2026-11-14。代码在 `frontend/src/features/now/`，统计查询见[应用 API](../contracts/app-api.md)。本文记录讨论确定的方向，细节可随实现调整；与[界面设计语言](ui-design.md)冲突时，以本文明确列出的例外为准，其余仍遵循该文档。

## 1. 定位

「此刻」（英文 Now）是主窗口里的一个独立页面：向用户问候，汇总邮箱现在的状况，在配置 AI 后给出更自然的总结并允许直接对话。它不是必经的门厅，用户可以设为启动页，也可以完全不用。

基调：**统计与规则是底，AI 是加分项。**

- 页面上的事实（数量、状态、验证码等）一律来自本地计算，规则可以解释，离线和没有配置 AI 时完整可用。
- AI 只负责把这些事实说得更自然、补充重点和回答提问，不产生页面上的统计数字。
- AI 关闭、失败或超时时，页面静默退回预设内容，不出现错误横幅。

不使用“首页 / Home”“仪表盘 / Dashboard”“助手 / Assistant”等名称：前两者偏冷或像门厅，后者把页面和 AI 绑定，与上述基调矛盾。

## 2. 入口

- **导航位置**：侧栏“写邮件”之下、“收件箱”之上；图标栏中位置相同，Tooltip 为“此刻”。
- **图标**：Hugeicons 的 `SunriseIcon`（日出），固定不随时段变化，方便按图标找到入口。不用时钟（易与历史记录或定时发送混淆），不用太阳（标题栏明暗模式按钮已用 `Sun03Icon`），不用星芒（留作 AI 内容标记）。
- **命令面板**：“跳转”分组列出“此刻”，排在顶部视图之前。
- **启动页**：“设置 → 通用 → 启动时打开”（`general.startupView`：收件箱 / 此刻），默认收件箱，不改变已有用户的习惯。只在主窗口启动、设置首次读到时生效一次，不覆盖用户已经切换的视图。

## 3. 页面结构

页面占满整个主岛，不拆成列表和阅读区。

```text
┌───────────────────────────── 岛 ─────────────────────────────┐
│                  （背景氛围层：按时段的渐变）                     │
│          ┌──────────── 内容列（居中，限宽）────────────┐          │
│          │ 问候                                        │          │
│          │ 概述句（预设或 AI）                          │          │
│          │                                            │          │
│          │ 需要处理的事                                 │          │
│          │ 自上次查看后的新邮件                         │          │
│          │ 最近的验证码 · 最近的附件                     │          │
│          │                                            │          │
│          │ ╭ AI 输入框（仅在 AI 可用时出现）╮            │          │
│          └────────────────────────────────────────────┘          │
└──────────────────────────────────────────────────────────────┘
```

- **内容列**限宽并居中，暂定最大约 720–880px，避免大窗口下文字行过长；装饰与背景铺满整个岛。内容列自己滚动，输入框固定在内容列底部。
- **分组不用卡片边框或分割线**，靠留白、字号层级和淡底色块（如 `bg-muted/40`）区分，与岛内其他页面一致。
- **标题栏**：页面没有阅读区，“收起 / 展开邮件内容”按钮在此页隐藏；搜索入口范围与草稿、发件箱视图相同，仍指向全部收件箱。
- **快捷键**：列表与阅读区的单键（`j` / `k`、`e`、`s` 等）在此页无效；`/`、`?`、`Cmd/Ctrl+K`、`Cmd/Ctrl+N` 照常可用。
- **打开邮件**：点击页面上任一邮件，跳到它所在的视图（如收件箱）并经现有 `openEmail` 在阅读区打开，不在此页内嵌阅读器。打开的邮件本就独立于列表，见[界面设计语言](ui-design.md#打开的邮件独立于列表)。
- 浅色、深色、中英文和窄窗口都要可用；窄窗口下装饰减弱，内容优先。

## 4. 内容：统计层（无需 AI）

### 4.1 问候

- 按本机时段给出问候（清晨、上午、下午、傍晚、深夜分别措辞），配日期。称呼取默认发件账号的发件人名称，没有时不称呼。
- 预设文案按**情境**挑选：时段、星期（如周一、周五）、节日，中文界面可加二十四节气；邮箱状态也参与，例如收件箱已清空、有发送失败、有账号需要处理。
- **同一天保持稳定**：以本机日期和情境为种子挑选句子，切换页面再回来不换句子；情境变化（如时段跨越、出现新的待处理事项）时才更换。
- 文案写在中英文资源文件中，按情境分组，每组若干句；涉及数量的句子按语言处理单复数。语气平实亲切，不过度热情，不使用表情符号作为主要内容。

### 4.2 统计项

各项只在有内容时出现，空的条目不显示（与侧栏一致）。

| 项目 | 内容 | 数据来源 |
| --- | --- | --- |
| 需要处理的事 | 同步停止或需要重新登录的账号、发件箱中失败或需要确认的发送、未完成的草稿 | 现有同步状态、发件箱、草稿 |
| 新邮件 | 自上次查看此页后到达的收件箱邮件数，按账号分开（账号颜色与头像），附几封最新邮件的发件人和主题 | 收件箱头部；需在本机记录“上次查看时间” |
| 未读与星标 | 收件箱未读数、星标中的未读 | 现有计数 |
| 最近的验证码 | 最近 15 分钟内识别出的验证码（最多 3 个），显示来源发件人与时间；页面停留期间超时自动隐藏 | [验证码识别](verification-codes.md)；统计查询从缓存正文或预览中找出候选（只检查窗口内最新的 50 封，不为此下载正文）。复制与邮件列表、阅读区共用同一流程：由应用的验证码识别给出可复制的结果（可能为像验证码的邮件下载正文），宿主写剪贴板并遵循“复制后移到已删除”设置；只显示识别已确认、可以复制的验证码；尚未识别、无法识别、无验证码或有歧义的条目都不显示 |
| 最近的附件 | 近几天收到的附件名称、发件人，点击打开所在邮件 | 附件元数据 |
| 常联系的人（未实现） | 近期往来最多的几位联系人 | 本地头部统计；后续 |
| 等你回复（未实现） | 别人发来、需要回复的邮件 | 依赖“已回复”标记或回复关系；core 目前是否保存需先确认 |

- “上次查看时间”存于 `localStorage` 的 `mailx.now.lastVisitedAt`（只有主窗口显示此页）：进入页面时读取并在本次停留期间固定，离开此页或窗口隐藏时更新为当前时间。首次使用时从当天零点（本机时间）算起。
- 新邮件、星标未读、验证码与附件由 core 的只读查询 `mail_overview`（桌面命令 `emails_overview`）计算，与邮件列表共用当前来源与代际过滤，排除本机归档；以后 MCP 与 Web 宿主可以复用。需要处理的事、收件箱未读复用前端已有的同步状态、发件箱、草稿与文件夹计数，不重复查询。结果不含正文。
- 数字随现有同步与邮件状态事件刷新，不轮询。

## 5. 内容：AI 层（可选）

仅在用户配置了可用的 AI 模型（见 [AI 服务商与模型配置](ai-providers.md)）后出现；依赖的流式输出、内容披露与取消机制见 [AI Runtime](../ai-runtime/README.md)，目前尚未实现。

### 5.1 概述句

- 用一两句话替换预设的概述句，例如概括新邮件主要来自哪里、哪封可能需要关注。数字仍由第 4 节的统计提供，作为输入给模型，要求模型不得改动；页面上的统计区不由 AI 生成。
- AI 生成的文字旁有一个小的星芒标记，悬停说明“由 AI 生成”和生成时间。
- **按需生成并缓存**：新邮件数量或待处理事项变化、或跨越时段后才重新生成；进入页面不必每次请求。页面显示“生成于 HH:mm”，提供刷新按钮。缓存键遵循 AI Runtime 第 4 节（内容摘要、模型、提示模板版本、语言），换模型或换账号范围不复用。
- 生成期间先显示预设文案，完成后淡入替换；失败、超时或取消时保留预设文案，不提示错误（设置页的 AI 测试负责诊断）。

### 5.2 待办建议（后续）

在概述之后列出建议处理的邮件，每条带来源邮件，点击打开；只是建议列表，不自动创建任务，规则同 AI Runtime 第 1 节。

### 5.3 数据披露

- 首次使用某个模型服务时，像邮件翻译一样先征得同意，说明哪些内容会发给哪个服务（例如新邮件的发件人、主题和预览）；更换服务后重新询问。同意由 core 强制。
- 未同意前不发送任何内容，页面保持预设文案，概述位置可以放一个“用 AI 总结”的按钮触发同意。
- 默认只发送头部与预览，不发送完整正文和附件；需要更多内容时按 AI Runtime 第 3 节扩大范围并重新确认。

## 6. AI 对话输入框

对话的共用构件、动效与性能规则见 [AI 交互界面](ai-chat-ui.md)，本节只写此页特有的部分。

- **仅在 AI 可用时显示**。没有配置 AI 时不显示输入框，也不退化成搜索：标题栏已有搜索入口，再放一个会造成重复和混淆。不在页面上放“去配置 AI”的引导，相关说明放在设置的 AI 页。
- **形态**：内容列底部的单行胶囊输入框，聚焦后增高，旁边只有发送与停止按钮，占位文字如“问问你的邮件”。出现和收起使用淡入加轻微位移，不推动上方内容。
- **对话视图**：发出第一句后，同一内容列切换为对话视图，问候与统计收成顶部一行摘要；`Esc` 或“返回”回到概览。对话只在本次运行内保留，重启后清空；持久化以后再议。
- **配置变化**：配置好 AI 后输入框立即出现，无需重启。AI 被关闭或配置失效时，输入框收起，进行中的对话转为只读。
- **能力边界**：
  - 模型通过[工具层](agent-tools.md)以内置 Agent 身份读取邮件，首期只授予只读动作，账号范围与披露授权一致。
  - 回答需列出引用的邮件，点击打开。
  - 涉及写操作（拟草稿、归档、标记等）时，模型只能给出建议按钮，由用户点击后经现有接口执行。
  - 首期提供发信工具，但每次发送都要用户同意：模型调用发送时，对话中出现一张确认卡，列出发件账号、收件人（含抄送 / 密送）、主题、正文预览和附件，用户点“发送”后才入队，之后照常有撤销发送窗口；用户点“取消”或离开对话视图即视为拒绝，模型收到拒绝结果。确认卡由宿主根据草稿当前版本生成，模型不能自行批准，草稿在确认期间被修改则确认失效。授权模型与确认凭据见[内置 AI 工具权限](ai-permissions.md)。
  - 邮件内容与模型输出均不可信：回答按纯文本渲染（可支持受限的 Markdown 子集，不渲染 HTML、不自动加载链接或图片），不能触发任何未经用户点击的动作。
- **命令面板**：AI 可用时可加一条“问 AI”命令，聚焦此输入框；没有 AI 时不出现。

## 7. 动效与装饰

这是界面设计语言里“岛内保持朴素”的一个例外：此页允许背景氛围和入场动效，但内容区仍不用卡片边框和分割线。

- **背景氛围**：按时段变化的缓慢渐变（清晨偏暖、白天明亮、夜间偏深），色相由 `--primary` 等 token 推导，随强调色和明暗主题变化；不写死色值。文字区域的对比度必须满足可读要求。
- **入场**：每天首次打开时内容错落淡入、数字由小到大滚动；之后再进入直接显示，不重复播放。
- **AI 文字**：流式输出时逐段出现，即本页最主要的动态效果。
- **性能**：只用 `transform` 与 `opacity` 动画，避免持续运行的 canvas / WebGL。窗口隐藏、最小化或页面不可见（`visibilitychange`）时暂停全部动画；应用常驻后台，不能因为此页持续占用 CPU 或电量。
- **减少动态效果**：遵循系统偏好，开启后只保留静态渐变，不播放入场和数字滚动。
- 装饰元素对读屏隐藏（`aria-hidden`）；AI 流式文字用礼貌级 `aria-live` 播报完成后的结果，不逐字播报。

## 8. 隐私与安全

- 统计层只在本机计算，不外发任何内容。
- AI 层与对话遵循第 5.3 节的同意与披露范围，以及 AI Runtime 的数据披露规则。
- 页面上的发件人、主题、附件名和 AI 输出按纯文本展示，不渲染 HTML。
- 验证码只在用户点击时复制，不自动复制。

## 9. 分期

1. **第一期（无 AI，已实现）**：入口与图标、页面结构、问候与预设文案、统计项（不含“常联系的人”和“等你回复”）、启动页设置、动效与减少动态效果；core 汇总查询及测试。
2. **第二期（AI 概述）**：在内置 AI 的流式输出、内容披露与取消落地后，加入 AI 概述句、同意流程与缓存。
3. **第三期（对话）**：AI 输入框、对话视图、只读工具与引用、建议按钮、逐封确认的发信。
4. **后续**：待办建议、“等你回复”、常联系的人、模块显示与排序的个性化、对话持久化。

每期完成时按惯例更新 ui-design.md、应用接口文档、用户指南（中英文）、CHANGELOG 与验证记录。

## 10. 第一期实现说明

- **预设文案**：`locales/*/now.json`，按情境分组。优先级为：需要处理（停止的账号、发送失败或结果不确定；草稿不计入）＞节日＞节气（仅中文）＞新邮件＞周一 / 周五 / 周末＞收件箱清空＞平常。以本机日期和情境名的哈希挑句，同一天、同一情境不换句。
- **节日与节气**：本地计算，不联网。元旦；春节、元宵、端午、七夕、中秋用 `Intl.DateTimeFormat` 的农历（运行环境不支持时不显示节日）；二十四节气用 21 世纪通用公式加已知修正，适用 2000–2099 年。农历节日与节气只用于中文文案。
- **布局**：内容列最大 760px；背景为按时段的静态径向渐变，时段变化时交叉淡入约 1 秒；入场动画每天首次进入时播放。

## 11. 待定问题

- core 是否记录 `\Answered` 或回复关系，决定“等你回复”能否实现。
- 页面停留期间相对时间（“6 分钟前”）不随时间刷新，是否需要按分钟更新。
- 三平台桌面实机观感（背景渐变、入场动画、窄窗口）。
