# 桌面与自托管 Web

状态：**桌面收信、阅读、写信与首版中英文文本已有实现 / Web 为 Initial draft**。第一阶段桌面 MVP，第二阶段服务器 MVP；真实平台体验与服务商兼容性分别验证，后续仍可调整设计。

## 1. 桌面宿主

当前 `desktop/` 加载 Vite 构建产物，直接依赖 `core/`，装配账号服务、系统凭据库与受限账号 IPC。前端是由 shadcn 组件构成的账号导航、列表和配置详情，保存配置不连接邮箱。实际命令见[应用 API](../contracts/app-api.md)，启动方式见[开发指南](../development/README.md)。

桌面直接以 Tauri `app_data_dir()` 作为 user-data-dir，向核心注入该目录和 SecretStore。宿主启动时在阻塞线程打开核心，取得 `mailx.lock`，打开并校验 `mailx.sqlite3`，恢复凭证更新后才发布 `Ready` 和配置读写。同步 AccountService 由宿主在阻塞线程调用，以互斥访问保证串行执行，避免数据库或系统凭据操作阻塞 UI 线程。打开失败不会缓存半初始化服务；用户解锁凭据库后可以重试。

启动状态以 `Initializing / Ready / Failed` 同时控制界面和业务 IPC。Ready 前账号命令返回 `coreNotReady`，前端不会挂载账号页面。

一个数据目录只允许一个核心实例；第二个写入者返回 `alreadyOpen`，当前不承诺聚焦已有窗口。关闭主窗口后宿主退出并释放服务与目录锁；有写信窗口时，先请求它们写出草稿再退出（写信窗口为独立窗口，见[写信与发送设计](sending.md#2-写信窗口独立窗口)）。退出后不继续同步或发通知，没有托盘常驻；未来启用常驻时必须显式配置。未来退出流程停止新任务、取消可取消读取，并按[账号操作契约](account-configuration.md#6-操作与后台任务契约)及[发送恢复语义](mail-sync.md)保留在途操作的事实。
未来邮件工作台拆为应用壳、账号 / 文件夹导航、分页虚拟邮件列表、阅读器、撰写器、AI 面板和设置。v0.1 先完成键盘可达、焦点管理、深浅主题及窗口缩放，不把装饰性动效放在收发链路之前。

### 多窗口生命周期

窗口分 `main` 与每份草稿一个的 `composer-<uuid>`，加载同一前端包，写信窗口用 `?composer=<draftId>` 区分角色。窗口白名单见[应用 API](../contracts/app-api.md#写信窗口与发送命令发信步骤-4a)。写信窗口的系统关闭请求被拦截，交给页面写出草稿后调用 `composer_close`，3 秒无回应则宿主直接销毁；主窗口关闭（或 Cmd+Q）时先对每个写信窗口发 `mailx://app-closing`，等它们关闭（最多 3 秒）再退出，没有写信窗口时立即退出。窗口状态插件只记住 main。草稿与发送队列事件只送 main 与对应写信窗口；设置变更事件送所有通过来源与角色校验的 main 和 composer 窗口。

## 2. UI 数据流

当前业务组件仅依赖 `MailxClient`，桌面实现使用 Tauri IPC，类型由 Rust DTO 生成。所有业务界面使用 shadcn 组件组合；无桌面宿主的浏览器显示能力不可用，不用 localStorage 模拟成功。未来 Web 实现使用同源 HTTP。领域 DTO 与错误保持一致，传输特有能力由 adapter 处理。

- 当前账号界面区分加载、保存中、成功、冲突和错误，提交后清空秘密输入。工作台的服务端数据由 TanStack Query 管理（`frontend/src/lib/query-client.ts`）：查询不按时间过期、不在窗口聚焦时刷新、不重试，何时刷新只由同步事件决定。账号与文件夹树、邮件分页（`useInfiniteQuery`）和邮件详情各有查询键，邮件列表的键包含账号服务器身份与过滤条件。任一目录数据变化时，所有已缓存的列表被标记为过期但不立即重拉；正在显示的列表仅在其覆盖目录的版本变化时重拉全部已加载页，其余列表在下次显示时更新。选中、过滤和搜索等界面状态仍是组件本地状态。
- 交互状态层只保存布局、选中项、未提交交互状态；正文、凭证、发送结果不以 UI Store 为唯一事实来源。
- 草稿定时保存到核心，以 revision 检测冲突；关闭编辑器前提示未保存失败，不能只依赖浏览器内存。
- 事件表示“资源已变更”，UI 重新查询快照；断流后重新订阅并主动刷新，不假设接收了每个事件。
- AI 流式增量用于展示，Run 快照用于恢复；取消页面订阅不自动取消后台邮件同步。

缓存缺失、搜索范围不全、待同步 flags、发送 `unknown` 和 AI 被取消均需可见状态，不用统一“操作失败”遮蔽语义。

### 应用偏好

语言、外观、安全性、窗口布局（如侧边栏宽度）等应用级偏好由核心 `SettingsStore` 保存在数据目录的 `settings.json`，不使用 Tauri store 插件，前端也不直接读写文件。文件是带 `version` 的格式化 JSON，便于查看和手工编辑；写入时先写临时文件、`fsync` 后原子改名。缺字段使用默认值，语言按下文兼容规则处理；未知字段忽略，手工改坏的单个字符串字段回到默认值。无法解析、版本不受支持或超过 64 KiB 的文件改名为 `settings.json.bak` 后以默认值继续，界面会提示。应用运行时手工修改的文件只在下次启动读取，期间界面保存会覆盖它。

偏好与账号数据分开：主题、字体这类与邮件数据无关的设置放 `settings.json`；需要引用账号或随账号删除的设置以后放 SQLite。

前端在 React 渲染前用 localStorage 的 `mailx.appearance` 副本应用上次外观以避免闪烁，随后以核心返回值为准并刷新副本；该副本不是事实来源。首次读取到 `stored=false` 时导入旧版 `mailx.theme` 主题偏好并删除该键。外观通过 `<html>` 上的 CSSOM 自定义属性生效，符合 `style-src 'self'` 的 CSP。

`general.language` 支持 `system | zh-CN | en`。没有设置文件时默认为 `system`；已有合法文件缺少语言字段时补 `zh-CN`，保留升级前语言；可解析文件中的非法语言回到 `system`，不丢弃其他有效设置。宿主启动时读取并缓存系统语言，中文标签含简繁体与地区变体均映射为 `zh-CN`，其他语言或读取失败使用 `en`；显式选择覆盖系统值，系统语言变化在重启后重新解析。核心只接收受支持语言，不依赖平台 API。此变更扩展现有设置文件，不迁移邮件数据库。

主窗口与写信窗口在 React 首次渲染前使用 `mailx.language` 中缓存的有效语言；缓存缺失或无效时，以浏览器语言映射作临时选择。两种资源已同步打包，无需网络请求。位于业务启动闸门外的 `SettingsSync` 随后读取宿主快照，用派生的 `effectiveLocale` 更新界面、缓存和 `<html lang>`；核心初始化失败时仍可读取设置。语言保存成功后才切换，保存失败保留原语言。

设置快照增加 `effectiveLocale` 和当前进程内单调递增的 `revision`，两者不写入文件。主窗口和合法写信窗口先等待 `mailx://settings-changed` 监听注册，再读取快照；只有 main 可修改设置。保存成功后宿主广播 `{ revision }` 失效通知，各窗口重读完整快照；重新聚焦时补读，并重试失败的监听注册。统一设置缓存拒绝旧 revision 的读取 / 保存响应，已提交值与待保存更改分开维护，同一节保存串行，失败只撤销对应更改。邮件正文 iframe 不获得设置 IPC 或事件访问权限。

切换语言只更新文案和受控错误，不重新挂载编辑器、清空查询缓存、下载正文或改写已有草稿；回复 / 转发引用头按创建时语言固化。日期 / 时间、数字、文件大小、列表连接和文件夹排序沿用现状，区域格式化仍为 Planned。原生窗口与系统菜单等平台体验，以及打包后的三平台多窗口同步和通知仍需分别手验，详见[中英文文本适配](internationalization.md)和[验证记录](../development/validation.md#2026-10-25-中英文文本适配)。

## 3. Web 宿主（建议 v0.2）

Axum 托管同一工作台的构建产物，提供 `/api/v1` 与 `/api/v1/events`。前端和 API 同源；附件下载从受鉴权接口输出，不把 `/data` 作为静态目录。服务端负责邮箱和模型连接，浏览器不保存协议凭证。

部署形态为单用户私有实例，单镜像包含 Rust 二进制和静态资源，不内置邮箱服务器、Redis 或外部数据库。镜像内服务监听容器网络以供映射，示例 Compose 应默认将宿主端口绑定至 loopback；公网使用反向代理 TLS，受信代理名单显式配置，不盲信 `X-Forwarded-For`。

`/data` 挂载本地磁盘；主密钥以独立只读 secret 文件挂载。容器以非 root 运行，根文件系统尽量只读，临时空间有界。首次发布时再确定基础镜像、目标架构与真实镜像名，不先提供不可用的拉取命令。

## 4. Web 认证初案

| 阶段 | 初始方案 |
| --- | --- |
| 首次引导 | 服务器本地生成一次性 setup token；无 token 无法抢占管理员；引导成功后永久关闭 setup 入口 |
| 登录 | 单管理员密码，成熟 Argon2id 实现；参数在 M5 的目标硬件基准后确定 |
| 二次认证 | TOTP + 一次性恢复码；远程使用前完成配置，恢复码只显示一次且哈希保存 |
| Session | 服务端保存可撤销 Session；Cookie 使用 HttpOnly、Secure、SameSite；登录后轮换，退出立即撤销 |
| 写操作 | CSRF token 与 Origin 校验；禁止跨域宽泛授权 |
| 防爆破 | 按账号与来源组合退避、短时速率限制和审计；重启不能清空关键失败计数 |
| 恢复 | 本机维护命令触发恢复并撤销现有 Session；不提供匿名远程重置入口 |

避免“错 5 次锁 IP 1 小时”成为共享出口用户的拒绝服务入口。限速阈值、闲置 / 绝对会话时限、TOTP 失败预算和恢复流程在 M5 再具体设计并验证；认证未完成前不对公网发布。

Web 登录 Session 与 MCP 授权是两类凭据，不能拿浏览器 Cookie 或邮箱 token 当作通用 MCP token。远程 MCP 不属于 Web 首次上线的必要条件，按[独立契约](../contracts/mcp.md)推进。

## 5. 分发与可观测性

桌面候选产物为 Windows 安装包、macOS 应用包、Linux 包；具体格式由对应平台构建验证确定。M4 配置三平台 CI、签名 / 公证可用性、依赖许可检查和发布校验和。自动更新在签名与回滚机制明确前不启用。

健康探针不输出账号信息：存活只检查进程响应，就绪检查数据库与核心启动完成，不把外部邮箱暂时离线当成容器必须重启。指标默认仅本地，包括同步延迟、队列长度、错误类别、缓存大小与任务耗时。

桌面和 Web 各自拥有账号凭证、缓存及本地草稿，首版不设计两者之间的设备同步，也不允许多个实例共享同一个 SQLite 文件。
