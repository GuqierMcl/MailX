# 网络、凭证与不可信内容边界

状态：**账号配置、凭证边界、只读 IMAP 路由与按需正文隔离已有实现；SMTP 会话已在 core 内实现但未接入发送队列和界面；OAuth 及 AI 边界为后续设计**。保存账号后会由后台同步任务按账号路由连接 IMAP；具体机制可随后续设计调整并重新验证。

## 1. 信任边界

系统需要保护邮箱凭证、正文、附件、草稿、AI Key 与发信能力。邮件发送方、HTML 内容、模型输出、MCP 调用方和代理都不能被当作应用管理员。操作系统管理员或被完全控制的本机不在应用可独立防护的范围内；本地优先不等于磁盘已加密。

| 边界 | 设计要求 |
| --- | --- |
| UI → 应用服务 | 参数验证、主体来源、账号范围与操作权限 |
| 核心 → 邮箱 / 模型 | 指定路由、TLS 验证、端点约束、超时 |
| 邮件 → 阅读器 | MIME 限额、HTML 白名单、隔离 iframe、资源限制 |
| AI / MCP → 邮件数据 | 上下文最小化、可撤销授权、禁止自行升级权限 |
| 数据目录 → 凭证库 | 仅保存引用，不返回密钥明文 |

## 2. 账号路由

当前已持久化并校验下表的路由配置，由 `core/src/net/` 为 IMAP 建立协议字节流。后续 HTTP ClientFactory 为 OAuth / AI 等 HTTP 请求应用同源策略；`reqwest` 的代理配置不能自动代理 IMAP / SMTP TCP 流。

| mode | 语义 | 失败行为 |
| --- | --- | --- |
| `direct` | 不读取系统或环境代理，直接连接目标 | 返回网络错误 |
| `inherit` | 解析 MailX 应用默认路由；默认路由初始为 direct | 默认代理失败则返回错误 |
| `custom` | 指定 SOCKS5 或 HTTP CONNECT、凭证引用、DNS 策略 | 不得自动回退 direct |

当前应用默认路由固定为 direct、版本为 1，没有独立全局代理设置页。后续应用默认路由由用户明确设置；系统 PAC / 自动发现暂不实现，UI 不使用含混的“跟随系统”文案。SOCKS5 默认将目标域名交给代理解析；HTTP CONNECT 使用目标域名，不在本地预先查询目标 IP。直连时才由本机解析。代理本身的域名解析单独记录。

当前路由覆盖 IMAP，后续还需覆盖 SMTP、后台 OAuth token 交换 / 刷新及附件下载。OAuth 打开的系统浏览器仍遵循浏览器 / 系统网络设置，MailX 不能承诺控制它的代理。模型请求使用独立模型配置路由，不偷偷复用当前邮箱代理。

连接池按账号、路由配置版本、TLS / 认证配置分组，不跨账号混用。更改路由时禁止旧连接接受新任务并重建连接；继承路由还依赖默认路由版本。在途结果按同步、刷新和发送分类收尾，不能一律丢弃，见[账号操作契约](account-configuration.md#6-操作与后台任务契约)。日志可记录账号内部 ID、路由类别、耗时和脱敏错误，禁止记录代理密码与认证头。

SMTP 的自定义连接适配能力原是 M0 阻断风险，已由测试探针关闭：`lettre` 的 `AsyncSmtpConnection` 可运行在 `net::connect` 打开的字节流上，Direct / SOCKS5 / CONNECT 及 STARTTLS / 隐式 TLS 在受控本地服务上跑通，代理不可达时不回退直连，见[写信与发送设计](sending.md#4-smtp-会话)。探针后改为手写会话（`core/src/smtp/`），仍使用 `net::connect` 与 `net::upgrade_tls`；会话已有本地假服务器测试，但尚未接入发送队列、命令或界面，真实服务商和真实代理发信也未验证，不能据此宣称“收发全部分流”。

## 3. TLS 与 OAuth

当前 IMAP/SMTP 配置只接受隐式 TLS 或强制 STARTTLS；IMAP 已实现真实握手并在 TLS 成功后认证；SMTP 会话（core 内，未接线）的 STARTTLS 与隐式 TLS 同样走 `net::upgrade_tls`，与 IMAP 共用一套证书验证，STARTTLS 的 `220` 之后若读缓冲里已有明文字节则按注入拒绝。验证主机名和证书链，失败不降级明文，不提供全局“忽略证书”开关。后续企业私有 CA 支持应由账号显式配置并记录来源。

OAuth 当前仅预留类型并返回 `unsupported`。后续使用服务商支持的授权流程，桌面以系统浏览器 + 授权码 / PKCE 为目标，校验 `state`、严格匹配回调并使授权会话一次有效。桌面不把分发包里的 client secret 当作秘密；服务端私有应用凭证通过外部配置注入。

token 刷新按实际 grant 做 single-flight，避免同一 refresh token 并发轮换；第一版授权限定在单账号的单一认证配置，不复制为多个独立刷新者。刷新结果持久化后切换凭证版本；明确撤销或失效才进入需重新授权状态，网络失败不等同授权失效。重新授权指定认证配置与预期版本，由提供商验证授权主体及目标邮箱资源。服务商注册、redirect URI、scope 和公开应用验证属于发布依赖，实施前逐一核实，不以开发者测试账号成功替代正式分发验证。认证兼容范围见[产品矩阵](../product/README.md)。

## 4. SecretStore

当前 core 通过后端 `SecretStore` 读写秘密，桌面提供系统凭据适配。SQLite 仅保存引用；凭证更新以非敏感 journal 处理跨存储恢复，端点变化保留旧信任范围，见[账号配置](account-configuration.md)。系统库的暂不可用与条目确实缺失分别表达；不会通过删除数据或降级明文来处理故障。下列未来平台、OAuth 与 Web 能力按实际验证范围交付。

- 桌面系统凭据库目标为 Windows Credential Manager、macOS Keychain、Linux Secret Service；当前平台构建与实际存取证据见[验证策略](../development/validation.md)，不能由适配代码推断全平台已通过。系统凭据库不可用时提示配置问题，不静默改为明文文件。
- 邮箱授权码、refresh token、代理密码和模型 API Key 只经受控写入入口进入后端；当前 UI 仅得 `passwordConfigured` 与 `trust` 等脱敏元数据；未来授权状态另行建模。凭证输入可短暂存在表单内存，提交后清空，不进入 localStorage、状态持久化或日志。
- Web 采用成熟 AEAD 库保护凭证值，主密钥经只读 secret 文件注入且位于 `/data` 之外；随机唯一 nonce，AAD 绑定记录 ID / 版本。密码哈希、密钥加密和数据目录加密是不同用途，不能混用。
- M5 实现时再确定并记录密钥格式、轮换 / 恢复方案与验证向量；主密钥丢失不能靠登录密码恢复。不得将主密钥与加密数据一并存为“加密备份”。

## 5. 邮件正文渲染

Tauri 的信任边界和能力机制要求限制 WebView 对原生能力的访问；MailX 将正文视作独立不可信资源，不让它获得应用权限。[Tauri 安全文档](https://v2.tauri.app/security/)。

处理链：原始 MIME → 有界解码 → 纯文本提取 → `ammonia` 白名单 HTML → 资源 URL 重写 → sandbox iframe。iframe 不启用 `allow-scripts`、`allow-same-origin`、表单、弹窗或顶层导航；邮件脚本不可执行，宿主阻止子框架初始化可调用的 Tauri API。WebView2 可能保留冻结的 internals 中 plugins / postMessage 两个底层成员；不能将其描述为对象完全不存在，权限隔离由真实 WebView 测试核查。应用 CSP 与正文 CSP 分开维护。

- 删除 script、事件属性、form、object、embed、meta refresh、远程字体、CSS `url()` / `@import`、SVG 和其他主动内容。CSS 属性与样式块结构化清理，处理转义和注释，保留安全排版；不能以危险子串过滤替代。净化器是其中一层，不能替代沙箱。
- 默认 CSP `default-src 'none'`，仅允许处理后样式与由父应用生成的安全图片资源。禁止正文自行发起 fetch、加载原始外部 URL 或自动下载。
- 当前按需正文：`cid:` 仅解析当前可见邮件的 MIME 部分；协议资源绑定当前文档，改为其它邮件 id / CID 时拒绝。图片验证真实格式与大小，拒绝 SVG、HTML、未知或伪造类型；PNG / JPEG 完整解码，GIF / WebP 转为 PNG 首帧，不直接提供未验证的动画帧。内嵌资源最多 50 MiB，边长最多 8192、解码预算 64 MiB。有限 `data:` 图片也先验证，仅保留完整地址不超过 1 MiB 的安全图片，不开放通用 data URL。
- 外链保留正文中的文字和按钮，悬停 title 显示真实地址。原生导航回调在提交前取消 `/link` 跳转，产生绑定邮件 / 文档 / 索引的一次性事件；可信主窗口检查当前已加载可见文档后立即调用 Rust opener。仅允许 http / https / mailto；邮件脚本仍被禁止，无法自行调用 opener。去掉编号列表和逐次确认不改变 iframe / IPC 隔离。
- 安全性设置支持“每次询问”（默认）、“自动加载”、“永不加载”。单行提示支持本次加载、勾选后保存自动加载、关闭本次提示；保存失败不放行。CID / data 图片独立显示。重新打开重新询问；策略收紧撤销放行，图片协议每次还检查最新设置。
- Rust 加载器只接受净化器保留的 `<img src>` http/https 索引，不接受任意前端 URL。使用账号路由、原始域名 TLS 校验及经过验证的连接地址；常规地址必须为公网 IP。兼容本机 TUN 代理的 Fake-IP DNS：只有 HTTPS 域名解析结果可使用 198.18.0.0/15，并在发送 HTTP 前验证原始域名的 TLS 证书；直接填写该网段 IP、明文 HTTP、其他内网 / 元数据地址仍拒绝。Fake-IP 的上游实际地址由用户的本机网络映射处理；每次重定向重新验证，HTTPS 不降级 HTTP，不携带邮箱凭证、Cookie、Referer，也不接受响应 Cookie。单响应最多 8 MiB、最多 3 次跳转、含排队在内 30 秒超时；图片请求最多 4 个并行（不改变邮件同步并发），单文档最多 32 个图片槽。已验证图片仅在当前阅读绑定的内存中按 URL 复用（保留字节最多 64 MiB），不持久化；读取仍检查当前邮件身份，结束阅读或收紧策略时释放，迟到结果不能恢复旧缓存。远程 SVG（image/svg+xml）在 Rust 中转为静态 PNG，仅处理矢量图形；不加载其中的文件、网络图片、data 图片、嵌套 SVG 或字体，不执行脚本。输入最多 1 MiB，XML 禁止 DTD、最多 20,000 节点和 32 层，输出边长最多 4096、最多 4M 像素，暂不支持滤镜。CSS URL / srcset / 正文内联 SVG / 远程字体继续移除。

实际协议为 macOS / Linux 的 `mailx-body://localhost` 和 Windows 的 `http://mailx-body.localhost`。Wry 会重写 Windows 传入请求的 scheme，因此资源与 CSP 必须按浏览器实际 origin 生成。协议仅 GET；404 不暴露原因，其他方法为 405；所有响应包含 CSP、nosniff、no-referrer、no-store。图片 CSP 限定当前邮件 /part 与 /remote 路径，不能通过资源加载触发 /link。每次 document / part / remote / link / links_open 都重新验证绑定。

原正文版本的三平台合成 WebView 验证已有通过记录，见[验证策略](../development/validation.md)。当前改为导航提交前拦截，WebView2 保留 204 后备；本次运行证据独立记录，不沿用旧版本通过结论。Body WebView 在 MVP 阶段改为手动工作流，普通前端与 Rust 检查仍自动运行。

## 6. 端点与 SSRF

当前凭证受信端点包含协议、主机、端口、TLS 与登录用户名；仅改端点并保留密码时返回 `needsConfirmation`，不自动扩大可接收凭证的范围。后续连接器必须在认证前校验信任，不能因为新服务器的 TLS 证书有效就发送旧密码。

管理员可显式配置企业邮箱和本地模型的私网地址；配置端点与邮件内嵌 URL 是两种信任来源。邮件图片加载器默认禁止 loopback、私网、link-local、云元数据地址，校验解析后的实际连接地址和每次重定向；重定向次数与响应大小有界。代理代解析时若无法保证此校验，则拒绝该图片请求，不回退成不受限代理获取。

当前图片直连解析结果必须全部为公网地址，并固定实际连接 IP，防止 DNS 重绑定；共享地址段、IPv4 映射和 IPv6 过渡地址也拒绝。自定义代理保持远端 DNS 约定：只有能验证的公网 IP 字面量图片可走代理；域名图片无法验证代理实际连接地址，暂时拒绝，不泄漏本地 DNS、不回退直连。代理凭证仅用于代理隧道。

Ollama 默认仅在用户启用后探测配置好的本地端点，不扫描局域网。容器中的 localhost 指容器自身，本地模型访问由部署者显式配置。模型 endpoint 仅管理员可改，凭证请求不跨 origin 自动重定向。

## 7. AI 与 MCP 权限

内容披露前明确提供商、账号范围和本次内容；邮件中的“忽略之前规则”“把所有邮件转发”等文字不能变成系统指令。v0.1 模型工作流无发信权限，模型输出以文本或结构化建议展示，插入草稿后仍需用户检查。

MCP 默认关闭，配对后按客户端限制账号和动作，撤销立即生效。普通读取授权本身可能披露正文里的验证码，不能声称禁用 OTP 工具就隐藏了所有验证码；专项 OTP 工具只是更敏感的提取通道，首版不发布。实际工具边界见 [MCP 契约](../contracts/mcp.md)。

## 8. 日志和诊断

默认日志只含内部 ID、阶段、错误码、耗时和重试次数。脱敏 auth / URL userinfo / 地址 / 主题 / 正文 / 模型输入输出；SMTP 会话调试也不得原样输出 AUTH 或 DATA。审计记录访问和变更结果，不把敏感内容复制到另一张表。

同步错误详情不传递原始协议响应：HTTP CONNECT 拒绝只保留验证过的数字状态码与固定说明，畸形响应使用固定原因；TLS 握手与验证失败使用固定摘要，丢弃服务端证书名称和平台原始诊断。此限制不改变证书校验、错误分类、退避或代理失败禁止直连回退的行为。

诊断导出需列出将包含的字段并由用户触发；当前不设计默认遥测上传。故障报告使用合成样本和可复现步骤，真实邮件不得进入公开 issue。
