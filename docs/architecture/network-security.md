# 网络、凭证与不可信内容边界

本文记录账号配置、凭证、IMAP / SMTP 账号路由、正文隔离、发送队列与本地 MCP 的安全边界；通用 OAuth 基础已实现但生产服务商未开放，内置 AI 及 Web 凭证保护仍为后续设计。保存账号后由后台任务按账号路由同步，用户界面与获授权的 MCP 工具经同一发送队列发信。真实服务商与平台验证范围见[验证记录](../development/validation.md)。

## 1. 信任边界

系统需要保护邮箱凭证、正文、附件、草稿、AI Key 与发信能力。邮件发送方、HTML 内容、模型输出、MCP 调用方和代理都不能被当作应用管理员。操作系统管理员或被完全控制的本机不在应用可独立防护的范围内；本地优先不等于磁盘已加密。

| 边界 | 设计要求 |
| --- | --- |
| UI → 应用服务 | 参数验证、主体来源、账号范围与操作权限 |
| 核心 → 邮箱 / 模型 | 指定路由、TLS 验证、端点约束、超时 |
| 邮件 → 阅读器 | MIME 限额、HTML 白名单、隔离 iframe、资源限制 |
| AI / MCP → 邮件数据 | 上下文最小化、可撤销授权、禁止自行升级权限 |
| 数据目录 → 凭证库 | 仅保存引用，不返回密钥明文 |

## 2. 账号路由

当前已持久化并校验下表的路由配置，由 `core/src/net/` 为 IMAP 与 SMTP 建立协议字节流。OAuth token 与身份请求复用账号路由，后续 AI HTTP 客户端使用独立策略；`reqwest` 的代理配置不能自动代理 IMAP / SMTP TCP 流。

| mode | 语义 | 失败行为 |
| --- | --- | --- |
| `direct` | 不读取系统或环境代理，直接连接目标 | 返回网络错误 |
| `inherit` | 解析 MailX 应用默认路由；默认路由初始为 direct | 默认代理失败则返回错误 |
| `custom` | 指定 SOCKS5 或 HTTP CONNECT、凭证引用、DNS 策略 | 不得自动回退 direct |

当前应用默认路由固定为 direct、版本为 1，没有独立全局代理设置页。后续应用默认路由由用户明确设置；系统 PAC / 自动发现暂不实现，UI 不使用含混的“跟随系统”文案。SOCKS5 默认将目标域名交给代理解析；HTTP CONNECT 使用目标域名，不在本地预先查询目标 IP。直连时才由本机解析。代理本身的域名解析单独记录。

当前账号路由覆盖 IMAP 同步 / 标记写回 / 删除、正文与附件获取、IMAP IDLE、SMTP 连接测试与队列发送，以及允许加载的远程邮件图片。OAuth token 交换 / 刷新与身份查询沿用账号路由且代理失败不回退直连；OAuth 打开的系统浏览器仍遵循浏览器 / 系统网络设置，MailX 不能承诺控制它的代理。模型请求将使用独立模型配置路由，不复用当前邮箱代理。应用内更新使用宿主自己的 HTTP 客户端，不读取账号代理，见[更新器网络路径](updater.md#5-网络路径)。

协议连接按账号、路由配置版本、TLS / 认证配置隔离，不跨账号混用；SMTP 每次发送使用独立连接，不借用 IMAP 连接。更改路由时禁止旧连接接受新任务并重建连接；继承路由还依赖默认路由版本。在途结果按同步、刷新和发送分类收尾，不能一律丢弃，见[账号操作契约](account-configuration.md#6-操作与后台任务契约)。日志可记录账号内部 ID、路由类别、耗时和脱敏错误，禁止记录代理密码与认证头。

SMTP 当前使用手写会话（`core/src/smtp/`），`lettre` 仅用于 MIME 构造；会话通过 `net::connect` 与 `net::upgrade_tls` 接入发送队列、桌面写信和 MCP 发信。Direct / SOCKS5 / HTTP CONNECT、STARTTLS / 隐式 TLS 和代理失败不回退直连已有受控测试，见[写信与发送设计](sending.md#4-smtp-会话)。每次尝试重新解析当前账号的路由与凭证；正文开始前的临时失败可退避重试，正文发出后结果不确定则进入 `unknown`，不自动重发。真实服务商和真实代理组合仍需按验证记录逐项确认。

## 3. TLS 与 OAuth

当前 IMAP / SMTP 配置只接受隐式 TLS 或强制 STARTTLS；两者均在 TLS 成功后认证，使用 `net::upgrade_tls` 和同一套证书验证。SMTP STARTTLS 的 `220` 之后若读缓冲里已有明文字节则按注入拒绝。验证主机名和证书链，失败不降级明文，不提供全局“忽略证书”开关。后续企业私有 CA 支持应由账号显式配置并记录来源。

OAuth 通用基础采用授权码 + PKCE，检查一次性 `state`、回调来源 / 路径、重复参数与时限，临时监听器只绑定 IPv4 loopback。授权地址来自受信注册，不能由邮件、前端或 MCP 提供。生产服务商及身份适配器注册表为空，未知提供商在任何监听或浏览器副作用之前拒绝；公开应用注册与服务商身份验证仍是开放依赖。桌面不把公开客户端的 client secret 当作秘密。

刷新按 grant 协调并发和持久化，新 token 不在保存成功前交付连接；账号移除使协调器失效。token 交换和身份查询使用有界 HTTP 解析，禁止重定向到其他端点；协议凭证显式区分密码与 OAuth。IMAP XOAUTH2 拒绝只返回固定认证错误，断线与畸形挑战仍保留可重试协议失败类别；SMTP 从 OAuth AUTH 开始抑制所有服务器回复文字，避免 raw / Base64 bearer 凭证被回显到成功结果、发件箱错误或日志。临时网络故障不等同明确撤销。邮件服务器拒绝本地仍有效的 bearer 时，该值从缓存移除并刷新重试一次，不会被反复重放。刷新 token 时的代理、TLS 与网络故障在 IMAP 和 SMTP 中都保留各自的失败类别。详见[账号 OAuth 边界](account-configuration.md#5-通用-oauth-基础与开放边界)。

## 4. SecretStore

当前 core 通过后端 `SecretStore` 读写秘密，桌面提供系统凭据适配。SQLite 仅保存引用；凭证更新以非敏感 journal 处理跨存储恢复，端点变化保留旧信任范围，见[账号配置](account-configuration.md)。系统库的暂不可用与条目确实缺失分别表达；不会通过删除数据或降级明文来处理故障。下列平台与 Web 能力按实际验证范围交付。

- 桌面系统凭据库目标为 Windows Credential Manager、macOS Keychain、Linux Secret Service；当前平台构建与实际存取证据见[验证策略](../development/validation.md)，不能由适配代码推断全平台已通过。系统凭据库不可用时提示配置问题，不静默改为明文文件。
- 邮箱授权码、refresh token、代理密码和模型 API Key 只经受控写入入口进入后端；当前 UI 仅得认证类型、授权状态、凭证是否已配置与 `trust` 等脱敏元数据。凭证输入可短暂存在表单内存，提交后清空，不进入 localStorage、状态持久化或日志。
- 未来 Web 版采用成熟 AEAD 库保护凭证值，主密钥经只读 secret 文件注入且位于 `/data` 之外；随机唯一 nonce，AAD 绑定记录 ID / 版本。密码哈希、密钥加密和数据目录加密是不同用途，不能混用。
- M5 实现时再确定并记录密钥格式、轮换 / 恢复方案与验证向量；主密钥丢失不能靠登录密码恢复。不得将主密钥与加密数据一并存为“加密备份”。

## 5. 邮件正文渲染

Tauri 的信任边界和能力机制要求限制 WebView 对原生能力的访问；MailX 将正文视作独立不可信资源，不让它获得应用权限。[Tauri 安全文档](https://v2.tauri.app/security/)。

处理链：原始 MIME → 有界解码 → 纯文本提取 → `ammonia` 白名单 HTML → 资源 URL 重写 → sandbox iframe。iframe 不启用 `allow-scripts`、`allow-same-origin`、表单、弹窗或顶层导航；邮件脚本不可执行，宿主阻止子框架初始化可调用的 Tauri API。WebView2 可能保留冻结的 internals 中 plugins / postMessage 两个底层成员；不能将其描述为对象完全不存在，权限隔离需在真实 WebView 中专项核查。应用 CSP 与正文 CSP 分开维护。

- 删除 script、事件属性、form、object、embed、meta refresh、远程字体、CSS `url()` / `@import`、SVG 和其他主动内容。CSS 属性与样式块结构化清理，处理转义和注释，保留安全排版；不能以危险子串过滤替代。净化器是其中一层，不能替代沙箱。
- 默认 CSP `default-src 'none'`，仅允许处理后样式与由父应用生成的安全图片资源。禁止正文自行发起 fetch、加载原始外部 URL 或自动下载。
- 当前按需正文：`cid:` 仅解析当前可见邮件的 MIME 部分；协议资源绑定当前文档，改为其它邮件 id / CID 时拒绝。图片验证真实格式与大小，拒绝 SVG、HTML、未知或伪造类型；PNG / JPEG 完整解码，GIF / WebP 转为 PNG 首帧，不直接提供未验证的动画帧。内嵌资源最多 50 MiB，边长最多 8192、解码预算 64 MiB。有限 `data:` 图片也先验证，仅保留完整地址不超过 1 MiB 的安全图片，不开放通用 data URL。
- 外链保留正文中的文字和按钮，悬停 title 显示真实地址。原生导航回调在提交前取消 `/link` 跳转，产生绑定邮件 / 文档 / 索引的一次性事件；可信主窗口检查当前已加载可见文档后立即调用 Rust opener。仅允许 http / https / mailto；邮件脚本仍被禁止，无法自行调用 opener。去掉编号列表和逐次确认不改变 iframe / IPC 隔离。
- 安全性设置支持“每次询问”（默认）、“自动加载”、“永不加载”。单行提示支持本次加载、勾选后保存自动加载、关闭本次提示；保存失败不放行。CID / data 图片独立显示。重新打开重新询问；策略收紧撤销放行，图片协议每次还检查最新设置。
- Rust 加载器只接受净化器保留的 `<img src>` http/https 索引，不接受任意前端 URL。按账号路由下载，无邮箱凭证、Cookie、Referer；每次重定向复检，HTTPS 不降级。响应输入最多 8 MiB、最多 3 次跳转、含排队的请求总等待最多 30 秒；下载和阻塞解码各最多 4 个并发，取消异步等待不提前释放仍在运行的解码槽。每封最多 32 个图片槽，当前阅读成功图片的保留总量最多 64 MiB，超出则报告限额错误。成功图片同时进入账号 / 来源 / 连接版本隔离的磁盘缓存，TTL 30 天，命中仍检查当前身份与授权。关闭或收紧策略撤销绑定并取消排队/网络等待，已启动的有界阻塞解码可以收尾但不能恢复可读结果。
- 远程图片按实际内容识别，不依赖响应 Content-Type 或 URL 扩展名；兼容缺失、通用或误标类型。支持 PNG/APNG、JPEG、GIF、WebP、ICO、BMP、TIFF、PNM、QOI、DDS 的 DXT 变体、Radiance HDR、Farbfeld、带 v2 尾签名的 TGA。完整校验的 JPEG 保留压缩字节，其余转静态 PNG；APNG 使用默认图像，动画帧不直接交给 WebView。栅格边长最多 8192，解码分配及输出像素各有 64 MiB 预算，编码输出最多 16 MiB。HTML 错误页、损坏或超预算输入拒绝，CID / data 继续采用独立的声明类型规则。
- 远程 SVG 也可从实际 XML 识别，但必须具有 SVG 根元素和标准命名空间，经 Rust 转静态 PNG；不输出原 SVG，不加载文件、网络/data 图片、嵌套图片或字体，不执行脚本。输入最多 1 MiB，禁止 DTD、最多 20,000 节点和 32 层，输出边长最多 4096、最多 4M 像素及 16 MiB，暂不支持滤镜。CSS URL / srcset / 正文内联 SVG / 远程字体继续移除。
- 可信主窗口可读取绑定文档的固定图片状态（加载中 / 成功 / 固定错误分类），不向 iframe 暴露 URL 或底层诊断。手动重试复用成功图片的内存，只重新准入失败资源，换发文档令牌并撤销旧令牌，有短冷却；不自动重试 TLS 或策略错误。

实际协议为 macOS / Linux 的 `mailx-body://localhost` 和 Windows 的 `http://mailx-body.localhost`。Wry 会重写 Windows 传入请求的 scheme，因此资源与 CSP 必须按浏览器实际 origin 生成。协议仅 GET；404 不暴露原因，其他方法为 405；所有响应包含 CSP、nosniff、no-referrer、no-store。图片 CSP 限定当前邮件 /part 与 /remote 路径，不能通过资源加载触发 /link。每次 document / part / remote / link / links_open 都重新验证绑定。

导航在提交前拦截，WebView2 保留 204 后备。普通前端与 Rust 检查自动运行；修改正文 CSP、sandbox、自定义协议、链接拦截或升级 Tauri / Wry 时，按受影响行为和平台安排专项原生验证。专用 Body WebView 工作流及测试脚手架已移除，普通测试不等同于真实引擎隔离验证，也不能沿用旧实现的通过结论。验证方式与执行证据统一见[验证记录](../development/validation.md#body-native-validation)。

## 6. 端点与 SSRF

当前凭证受信端点包含协议、主机、端口、TLS 与登录用户名；仅改端点并保留密码时返回 `needsConfirmation`，不自动扩大可接收凭证的范围。IMAP / SMTP 登录计划在认证前校验信任，后续连接器沿用此边界，不能因为新服务器的 TLS 证书有效就发送旧密码。

管理员可显式配置企业邮箱和本地模型的私网地址；配置端点与邮件内嵌 URL 是两种信任来源。图片直连默认禁止 loopback、私网、link-local、元数据地址、共享地址、IPv4 映射和 IPv6 过渡地址；解析一次后筛出合格候选，去重并固定实际连接 IP，每跳重做检查。最多检查 64 个解析结果、采用 16 个合格候选，以约 300ms 的地址族回退连接，连接器不能再次查询系统 DNS。已知 TUN Fake-IP 例外仅适用于 HTTPS 域名的 198.18.0.0/15 与 2001:2::/48，仍校验原始域名 TLS；字面量与明文 HTTP 不适用，任意自定义网段未自动放开。

自定义代理的 `imageProxyDns` 默认 false；用户在账号设置明确开启后，HTTPS 域名图片可经 SOCKS5 / HTTP CONNECT 传递原域名，由代理解析，应用不进行目标本地 DNS，也绝不在代理失败后直连。代理本身的配置端点可为本机地址；邮件目标中的私网 IP 字面量和明确本地主机名仍拒绝。TLS 验证原域名，但无法证明代理最终地址为公网：最终域名解析的地址控制由用户选择的代理承担。代理类型、主机、端口或认证用户名变化后，旧许可撤销，需要针对新配置明确开启；保存结果不包含临时确认字段。普通直连 HTTP 图片沿用先试 HTTPS 的行为；代理域名路径仅 HTTPS，升级失败保留 HTTPS 失败原因，不发送明文域名请求。代理凭证仅用于隧道。

后续 Ollama 集成仅在用户启用后探测配置好的本地端点，不扫描局域网。容器中的 localhost 指容器自身，本地模型访问由部署者显式配置。模型 endpoint 仅管理员可改，凭证请求不跨 origin 自动重定向。

## 7. AI 与 MCP 权限

内置模型工作流尚未接入；后续设计要求在内容披露前明确提供商、账号范围和本次内容。邮件中的“忽略之前规则”“把所有邮件转发”等文字不能变成系统指令。所有工具调用均由宿主授予动作与账号范围，模型输出和邮件内容不能扩大授权。

MCP 默认关闭，开启前确认授权范围。首版开启后不做逐客户端配对：同一系统用户下能读取发现文件的进程都可连接，统一授权为“读取邮件与草稿、创建 / 修改 / 删除草稿、标记已读 / 星标、本机归档 / 取消归档、正常同步刷新、直接发信、发件箱查询 / 重试 / 取消与本机文件附件，不能删除邮件”、范围为全部账号。直接发信随总开关授权，无需逐封确认，也不另设发送开关；关闭开关立即断开连接、作废 token 并拒绝新的调用，但不撤销已入队的发送任务。逐客户端账号与动作范围留作后续。

核心检查宿主提供的主体、动作与账号范围；发送还检查草稿当前版本、幂等键与是否正在写信窗口中编辑，冻结内容后进入既有发送队列。附件工具只接受 MailX 所在电脑上的有界普通文件，不返回路径或文件字节；`unknown` 的人工处理仍只开放给用户 UI。具体规则见[发送与附件工具](mail-send-tools.md)。

普通读取授权本身可能披露正文里的验证码，不能声称禁用 OTP 工具就隐藏了所有验证码；专项 OTP 工具只是更敏感的提取通道，首版不发布。实际工具边界见 [MCP 契约](../contracts/mcp.md)。

## 8. 日志和诊断

默认日志只含内部 ID、阶段、错误码、耗时和重试次数。脱敏 auth / URL userinfo / 地址 / 主题 / 正文 / 模型输入输出；SMTP 会话调试也不得原样输出 AUTH 或 DATA。审计记录访问和变更结果，不把敏感内容复制到另一张表。

同步错误详情不传递原始协议响应：HTTP CONNECT 拒绝只保留验证过的数字状态码与固定说明，畸形响应使用固定原因；TLS 握手与验证失败使用固定摘要，丢弃服务端证书名称和平台原始诊断。此限制不改变证书校验、错误分类、退避或代理失败禁止直连回退的行为。

诊断导出需列出将包含的字段并由用户触发；当前不设计默认遥测上传。故障报告使用合成样本和可复现步骤，真实邮件不得进入公开 issue。
