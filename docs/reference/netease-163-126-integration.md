# 网易 163 / 126 / yeah.net 邮箱调研与接入方案

状态：**Implemented / 三个预设、添加前测试登录、授权码引导与安全策略拒绝诊断已有实现，用户已反馈真实邮箱手测并确认可以合并** · 2026-10-28。

调研基线为 `29bc484`。本轮 agent 的实施验证使用合成数据和受控协议服务，公开 TLS / 能力探测不带账号或凭证，没有登录真实邮箱、读取邮件或发信。后续用户手测反馈单独记录在第 5 节；逐域名、平台和收发场景的兼容矩阵仍需补齐证据。

## 1. 推荐方案与范围

使用 **IMAP + SMTP + 客户端授权码**，复用 MailX 现有账号、SecretStore、账号路由、同步和发送队列。服务商选择器提供“网易 163 邮箱”、“网易 126 邮箱”和“网易 yeah.net 邮箱”三项，分别保存服务商 ID（`netease163` / `netease126` / `neteaseYeah`）。三项共用授权码表单，使用各自的官方 PNG 标识，名称与描述明确区分地址后缀。

| 入口 | 预设接受的地址域名 | IMAP 默认 | SMTP 默认 |
| --- | --- | --- | --- |
| 网易 163 邮箱 | `163.com` | `imap.163.com:993`，隐式 TLS | `smtp.163.com:465`，隐式 TLS |
| 网易 126 邮箱 | `126.com` | `imap.126.com:993`，隐式 TLS | `smtp.126.com:465`，隐式 TLS |
| 网易 yeah.net 邮箱 | `yeah.net` | `imap.yeah.net:993`，隐式 TLS | `smtp.yeah.net:465`，隐式 TLS |

参数来自网易官方免费邮箱服务器表 [S1]；默认登录用户名为用户输入的完整邮箱地址，IMAP/SMTP 共用用户生成的授权码 [S2][S4][S8]。官方表还列出 SMTP SSL 端口 994；首版选择 465，不自动轮换端口或降级为明文，也不加入缺少本轮证据的 587 默认方案。

现有模型足够承载这三个预设，没有架构层面的阻塞，也不需要新的认证类型或为预设新增数据库迁移。服务商入口、官方图标、授权码引导及错误提示已实现，已有用户真实邮箱手测反馈；各域名与场景的独立兼容证据仍需补齐。

范围边界：

- `yeah.net` 已按同一官方免费邮箱表加入独立入口，对应 `imap.yeah.net` / `smtp.yeah.net`，不指向 163 主机。
- `vip.163.com`、`vip.126.com`、`188.com`、`163.net` 及企业自有域名不加入这三个免费邮箱的自动匹配列表。不能只因名字包含 163/126，或 MX 属于网易，就套用免费邮箱端点；这些地址暂用手动配置，单独核实其产品规则。
- 域名忽略大小写并精确匹配，邮箱本地部分和完整登录名保持原值；不自动合并别名或推导主账号。原来通过手动配置添加的网易账号保留已保存的连接，不自动换端点、迁移 `providerId` 或重建缓存。

## 2. 官方接入条件与用户流程

### 服务开通与授权码

网易当前官方说明 [S2][S3] 给出的流程是：网页版邮箱 → 设置 → POP3/SMTP/IMAP → 开启 IMAP/SMTP 服务 → 按页面完成验证 → 获取客户端授权码。是否需要短信由系统根据账号状态决定；MailX 仅提供固定官方帮助入口，不复制短信号码或固定验证步骤。

官方将生成的通用客户端授权码描述为 **16 位字母数字组合**，仅展示一次；忘记后需要新增，不能找回。官方推荐为额外客户端新增授权码；本方案在 MailX 内让 IMAP/SMTP 共用同一码，不引导用户在多个软件间重复使用。[S2][S3][S4]

添加向导继续采用：选择服务商 → 填写连接 → 设置账号资料。

1. 连接页默认显示完整邮箱地址、客户端授权码、“如何获取”和默认服务器摘要；“测试登录”可在保存前验证当前配置，不创建临时账号，可跳过或取消。
2. 高级设置保留收发独立用户名、独立凭证、服务器和账号路由；用户名未覆盖时跟随输入的完整邮箱地址。
3. 最后一步沿用“使用服务商图标”，按账号保存、默认开启；关闭后使用首字母和彩色头像。
4. 保存后表示配置已保存并开始同步；收发连接诊断分别显示认证结果，不把保存或诊断成功称为完整收发通过。

官方帮助还确认存在 Outlook 等客户端使用的 OAuth 2.0 登录 [S7]，公共服务器本轮也公告了 XOAUTH2。因此不能写成“网易不支持 OAuth”。但本轮未取得面向 MailX 的应用注册和授权接入资料，首版不将 OAuth、扫码或网易邮箱大师专有协议作为依赖。

### 收信范围与流量

官方“只能收取部分邮件”帮助配图包含“最近 30 天 / 全部邮件”选项 [S6]。它与 MailX 每个目录/UIDVALIDITY 首次固定的 30 天本地同步窗口不同；两者共同决定能看到的邮件，不能承诺添加后立即下载全部历史。

现有成功 SEARCH 对账会隐藏本地窗口内、服务器结果不再包含的旧 UID。应实测网易缩小/恢复收取范围及跨日行为，记录已缓存头部和正文的可见性；不预先承诺永久离线归档，也不把服务器不可见一律解释为用户删除。相关现有机制见 [QQ 方案的范围分析](qq-foxmail-integration.md#服务端收取范围与本地缓存)。

网易明确第三方客户端有流量限制，并说明开通会员不能提高第三方客户端上限 [S9]。沿用现有同步节奏、分页、按需正文与退避，实测持续使用和多客户端并行；不编造固定连接数/每日额度，也不推荐用户买会员来解决该限制。

## 4. 重点兼容问题

### IMAP ID：已有能力，验证实际接受情况

网易官方明确指出：未表明客户端身份可能得到 `Unsafe Login. Please contact kefu@188.com for help`，并要求发送 IMAP ID [S5]。其 Java 示例先 `store.connect(完整地址, 授权码)`，再 `store.id(...)`，与 MailX 登录后发送的顺序一致，不支持“网易必定要求登录前 ID”的判断。

官方列出的 name/version/vendor/support-email 是示例字段，没有明确声明四者全部必需。MailX 已发送真实 name/version，首版先验证其可用性；不冒充 Outlook、Foxmail 或邮箱大师，不填虚构的 vendor 或支持邮箱。如果实测证明还需要字段，再补真实且适用于所有会话的身份元数据与回归。

仍需记录登录后的 CAPABILITY、ID 完成状态，以及实际 LIST / EXAMINE。当前继续忽略普通的完整 ID NO/BAD；明确的 Unsafe Login 策略拒绝会终止会话，超时或断线也会结束会话。这在一般 IMAP 服务上合理，但网易若拒绝 ID 后仍允许 NOOP，当前连接诊断可能通过而目录不可访问。不能用认证/NOOP 成功证明 IMAP ID 已被接受或收信可用。

### 安全策略拒绝：已有固定分类与显式恢复

调研基线将 LOGIN NO/BAD 统一映射为“凭证被拒绝”，其他命令丢弃原因，可能把 Unsafe Login 误报为授权码问题或可重试协议错误。本轮已补齐这一诊断缺口；这仍不是已观测到的个人网易登录故障。

后端仅扫描负面状态响应前 4096 字节中的官方完整 `Unsafe Login. Please contact kefu@188.com for help` 信号（ASCII 忽略大小写），映射固定的 `providerPolicy`，不转发原始服务器文本，不从邮件字面量或任意解析失败中提取信号。认证、能力查询、ID、诊断 NOOP、目录和正文、标记写回共用分类；其他未知拒绝保留原有通用提示，不能凭一个 NO/BAD 断言授权码错误或账号被封。

同步、连接诊断、正文三类公开错误码均增加 `providerPolicy`，契约和生成 DTO 已同步。头部同步与标记写回暂停，保留缓存及待写队列；手动同步或修改连接可重建任务，前后台切换和新标记不会解除暂停，旧世代结果不能重新阻断新任务。正文失败持久化该原因，由用户明确重试。网络、TLS 和代理保留现有分类；服务未开或授权码错误/撤销在缺少明确信号时仍归为通用认证拒绝，由官方引导排查，不能声称已自动区分。当前诊断继续保持只认证、不读目录；如以后增加“检查收件箱访问”，需显式扩展契约与结果含义。

### 已发送副本与持续使用

实际发信验收需核对 SMTP accepted、收件方到达、From/MAIL FROM、Message-ID 与服务器已发送文件夹的副本数量。MailX 当前不做 IMAP APPEND，accepted MIME 与邮件列表的本地副本合并也尚未实现。先观察网易是否自动留存，不为预设直接增加 APPEND，更不能因副本没有显示而重发 SMTP。

SMTP 已支持本轮服务器公告的 LOGIN/PLAIN；本轮 agent 未执行真实 SMTP 认证，用户手测反馈也未逐项记录所用认证方式。现有 PLAIN 初始响应处理和失败后不切换机制的行为不能据能力公告判为网易缺陷；发生可复现差异后再补通用协议兼容，避免在真实账号上试遍认证方式。
